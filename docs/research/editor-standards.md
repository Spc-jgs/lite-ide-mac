# 用「编辑器为什么被骂、为什么成名」审 lite-ide（2026-10-12）

标准不是我们自己定的：各家编辑器被骂最多的地方、和它们打出名堂的那一条，社区里讨论了十几年，大体收得成下面七条。
lite-ide 的定位是「取代 Sublime、键位跟 IDEA」（DIRECTION.md D1），所以**前四条是核心，后三条是取舍**。

每一条按「我们的承诺 → 证据（实测或代码）→ 缺口」写。证据只写量过、读过代码核实过的；没量过的标「未量」。

## 七条标准

| | 成名的那一条 | 代表 | 反过来被骂的 |
|---|---|---|---|
| 1 | **从不让人等** | Sublime 秒开、大文件不卡；Zed | IDEA 启动和「Indexing…」挡着干活；VS Code 插件多了变慢；打字卡顿 |
| 2 | **从不丢你的东西** | Sublime 的 hot exit（不问就存、重启还在） | 崩溃丢了没保存的改动；关窗时一串「要保存吗」 |
| 3 | **从不打断你** | Sublime 的安静 | VS Code 的通知、IDEA 的弹窗、窗口抢焦点、自动更新的提示 |
| 4 | **键盘找得到一切** | Sublime 的 Goto Anything、VS Code 的命令面板 | 功能藏在菜单深处；快捷键记不住又查不到；换编辑器肌肉记忆全废 |
| 5 | 开箱就对 | VS Code 不配置也能用 | Vim / Emacs 的配置负担；设置文件太复杂 |
| 6 | 懂你的代码 | IDEA | 轻量编辑器「只是个记事本」 |
| 7 | 占用少 | Sublime、Zed | Electron 应用几百 MB |

## 逐条对照

### 1. 从不让人等 —— 守住了

| 场景 | 实测 | 出处 |
|---|---|---|
| 启动（热） | **398–479ms**，预算 < 0.5s；恢复 3 个窗口只多约 50ms | 2026-10-12 测试 `.app` 连起 5 次 / 3 窗口各 3 次 |
| 启动（打包后第一次） | ~1s，`window` 段是磁盘和签名校验 | ARCHITECTURE「启动分段」、app.log |
| 打开 1GB 日志 | 0.38ms 出首屏 | ARCHITECTURE 性能表 |
| 打开 50MB 单行 JSON | 0.4s，界面不卡 | 2026-10-12 |
| 打字 | 修过网格布局那次之后 JS 侧约 2ms / 键 | frontend.md「外壳网格的 1fr」 |
| 碰盘 / 子进程 / 网络的命令 | 一律不在主线程（有测试卡着白名单） | `tests/main_thread.rs` |
| 后台进程攥着管道 | 2 秒宽限期，不会一直转 | 2026-10-12 修 |

**没有「Indexing…」挡着干活**：日志索引在后台、进度在状态栏、边建边能看；项目文件列表 rg 现列。这是 IDEA 最常被骂、我们结构上就没有的一条。

缺口：日志视图里比窗口宽的长行看不到后半截（#64）—— 不是「等」，是「看不到」，归这条下面最近的地方。

### 2. 从不丢你的东西 —— 守住了，今天补了两处

- **hot exit**：⌘Q 不问，没保存的改动进会话快照，重开还在；草稿（scratch）停手半秒、切走、关标签就自动写盘；
  项目文件不自动写盘（半截代码写进盘会惊动构建工具和 Git），关它的脏标签会问（USAGE「草稿」「退出」那几段）。
- **崩溃**：有脏标签时定时把快照落盘，带草稿和 stamp，重开时和盘上的对一遍（frontend.md「会话快照存草稿」）。
- **删除只进废纸篓**：今天（2026-10-12）抓到 `discard` 直接删未跟踪的文件，改了；现在 clippy 卡着。
- **装命令行工具不盖别人的 `lite`**：今天改的。
- **外部改了、你也改了**：冲突裁决「用磁盘上的 / 保留我的」，不静默覆盖。

缺口：无（已知的都修了）。

### 3. 从不打断你 —— 守住了

- 不可逆的才弹确认，可逆的直接做、做完说一句（ui.md 第十三条四档）。消息走状态栏，不弹窗；「做完的消息」顶掉面包屑，几秒后自己回去。
- 没有自动更新器、没有遥测（立项时排除，PLAN.md）—— 也就没有「有新版本」「帮我们改进」这类打断。
- 抢焦点：应用自己的 `set_focus` 只在你操作它时用；测试构建连系统转交的那条也堵了（#54）。

缺口：右键菜单用完之后焦点回到哪（#50，要真输入验）。

### 4. 键盘找得到一切 —— 守住了，今天补了一处

- ⇧⇧ 随处搜索：文件、内容、操作、符号、跳行一个框；**操作那一档覆盖全部动作**并且旁边印着快捷键（ui.md「浏览器里没有菜单栏」）—— 这就是命令面板。
- 键位跟 IDEA（用户的肌肉记忆在那边）；键位表是唯一出处，菜单、速查、空态卡片都从它生成，测试卡着漂移。
- 今天：没打开文件时那张卡片原来列着 ⌘S / ⌘W / ⇧⌘O / F3 这些**此刻按了没反应**的键、⌘P 和上面的按钮印了两遍、最新的主流程「运行任务」不在 —— 改成按「有没有项目、是不是 git 仓库」只列按得出效果的。

缺口：终端里不能 ⌘F（#34）；「快捷键速查」本身没有快捷键（⌘/ 让给了编辑器的注释，要靠 ⇧⇧ 找到它 —— 取舍，不改）。

### 5. 开箱就对 —— 取舍过

- 不配置能用：从 Finder 起也找得到 mvn / pnpm（任务经登录 shell 跑）；`package.json` 的 scripts 自动列出来；编码自动认；大文件自动走日志模式。
- **Maven / Gradle 的任务要自己写一行 `tasks.json`**：`package.json` 的 scripts 是作者写下的「能跑什么」，照着列不算猜；`pom.xml` 能跑什么只能猜（`spring-boot:run`？`test`？）。猜错了比让人写一行糟 —— 取舍，TASKS.md 有理由。
- 设置只有文件（#67）。

### 6. 懂你的代码 —— 明确不追

不上 LSP（ARCHITECTURE 决策 7：jdtls 启动 5–10s、常驻 1GB+，和第 1、7 条直接冲突）。Java 的跳转靠 Lezer 树 + import 解析，够「看一眼、改两行」；深的交给 IDEA 和 agent（#46）。**这是定位上的选择，不是缺口**。

### 7. 占用少 —— 守住了

起来四个进程合计 152–158MB（预算 < 200MB）；安装包 4.1MB 的 .dmg。每多一个窗口 30–120MB，跟开着什么走（MULTIWINDOW 第 5 节）。GPU 进程那约 100MB 跟着什么走还没查清（#49）。

## 结论

**核心的四条都守住了**，而且有数字、有测试卡着，不是印象。今天打磨补了第 2 条两处、第 4 条一处。剩下的缺口都已经在 issue 里：

| 缺口 | 归哪条 | issue | 建议顺序 |
|---|---|---|---|
| 终端里不能 ⌘F | 4 键盘找得到 | #34 | 先 —— 天天用 |
| 日志长行看不到后半截 | 1 / 看得到 | #64 | 次之 |
| 右键菜单之后焦点 | 3 不打断 | #50 | 要真输入，排后 |
| ⌘S 在键位表和编辑器里各接一次 | 4 键位唯一出处 | #53 | 要真输入，排后 |

**我们和这些编辑器最不一样的一点**：它们的承诺大多靠「团队记得」，我们把承诺写成了会失败的测试和 lint（主线程白名单、DTO / 菜单同步、不许插 HTML、输入法、disallowed-methods）。七条里能写成测试的，以后也照这个办。
