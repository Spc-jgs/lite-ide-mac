# 多窗口（一个窗口一个项目）+ 关窗不退出（issue #41）—— 设计

> 状态：**设计已定，第 7 节四个问题 2026-10-08 按建议拍板**；下一步是第 0 步实测。
> 出发点见 [DIRECTION.md](DIRECTION.md) 第 6 节「多窗口」和 D1 里那条「一个窗口一个文件夹、同时开很多个」。
> 读之前先看 [ARCHITECTURE.md](ARCHITECTURE.md) 的进程模型和内存那两节。

## 0. 一句话

**每个项目一个原生窗口，每个窗口一个独立的 WebView。**前端状态天然按窗口隔开，所以要改的几乎都在 Rust 侧，只有三件事：

1. **进程级的资源，要记住它属于哪个窗口**：终端、日志句柄、文件监听、远程操作；
2. **事件改成按目标发送**，不再广播给所有窗口；
3. **跨窗口共享的状态收归 Rust 一处管**：开着哪些窗口、最近打开、菜单可用状态。

前端改动集中在「会话快照怎么存」和「打开文件夹走哪条路」。

整条设计的支点是一个原则：**只属于一个窗口的东西，留在那个窗口里；多个窗口都要读写的东西，只能有一个主人，这个主人就是 Rust 进程。**
后面每一处取舍，都是在回答「这个东西属于谁」。

## 1. 现状：哪里默认了「只有一个窗口」

整份代码都是在「只有一个窗口」的前提下写的。用两个窗口去对照，下面这些地方会出问题：

| 地方 | 现在 | 两个窗口时会怎样 | 严重程度 |
|---|---|---|---|
| `lib.rs` `on_window_event` | 任何窗口 `Destroyed` → `kill_all_ptys()` | **关掉 A 窗口，B 窗口的终端全被杀掉**（B 里正在跑的 gradle 一起没了） | 丢工作 |
| `state.rs` `remotes` | 表的键是前端给的 `opId`，每个窗口从 0 开始数 | A 和 B 同时 fetch，两边都用 1 号，**后来的那个被当成撞号拒绝** | 功能坏 |
| `state.rs` `watch` | 一个槽位：换项目根就换掉 | B 打开项目时**把 A 的监听顶掉**，A 从此收不到文件变动 | 静默失效 |
| `state.rs` `files`（日志句柄） | 前端关标签时才释放 | 直接关窗口的话，这个窗口的 mmap 一直留到应用退出 | 泄漏 |
| `lib.rs` 菜单事件 | `app.emit("menu", id)` 广播 | **在 A 里按 ⌘S，B 也会保存** | 功能错 |
| `fs.rs` `fs-changed` | 广播 | A 的项目文件变了，B 也会刷新文件树（虽然白刷，但会把性能拖下来） | 浪费 |
| `open.rs` `Inbox` | 一个全局的「前端就绪」标记 | 分不清该送给哪个窗口；新窗口还没起来时发的事件会丢 | 功能坏 |
| `persist.svelte.ts` | 不带后缀的 `lite-ide.session` 保存「上次退出时的现场」 | 多个窗口同时写同一个键，**后写的覆盖先写的**，下次启动只能恢复一个窗口 | 丢现场 |
| `persist.svelte.ts` `#prune` | 按**自己内存里**的最近列表，清掉别的项目快照 | A 启动后 B 才开了新项目，A 的列表里没有 B → **A 顺手把 B 的快照删了**，里面的未保存草稿也一起没了 | 丢数据 |
| `sync_menu_state` | 前端变了就推给 Rust，Rust 改全局菜单 | 菜单变灰状态反映的是**最后一次推送的窗口**，不一定是你正在用的那个 | 显示错 |
| `capabilities/default.json` | `"windows": ["main"]` | 新窗口不在名单里，就没有 `core:default` 权限，**监听不了任何事件** | 起不来 |

`#prune` 那条最危险。它不会报错，只会在某次启动之后发现某个项目的现场没了。所以它必须在第一步就改掉，不能等到上线再撞见。

**已经天然按窗口隔开、不用动的**：

- **所有 `Channel`**：终端输出 `on_data`、fetch/push 进度 `on_progress`。`Channel` 是跟着那一次调用走的，调用来自哪个 WebView，数据就只回到哪个 WebView。三个大数据流全在这条路上，这是现在架构白送的。
- **前端全部状态**：tabs、docs、git、project…… 每个 WebView 是独立的 JS 堆。
- **偏好**（`localStorage` 里的 minimap、字号、合并包名等）：同一个 origin 下的 WebView 共享同一份 `localStorage`。偏好本来就该全局，这正好。第 0 步会实测这一点。
- **原生菜单的「窗口」子菜单**：`menu.rs` 已经调用了 `set_as_windows_menu_for_nsapp`，macOS 会自动把窗口列表塞进去；「关闭窗口 ⇧⌘W」也已经在了。⌘\` 切换窗口是系统自带的。

## 2. 目标形态（照 IDEA，只取你用得到的）

- **一个项目一个窗口。**用 ⌘O、「最近打开」、`lite 目录`、Finder 拖文件夹打开项目时：
  - 这个项目**已经开着** → 把那个窗口拉到前面，不开第二个；
  - **没开着**，而且当前窗口已经有项目 → 开一个新窗口；
  - **没开着**，当前窗口是空的（没有项目） → 就用当前窗口。
  
  IDEA 每次会弹窗问「This Window / New Window」。这里不问，理由见第 7 节 Q2。
- **分支浮层里的「打开工作树」→ 新窗口。**这正是你现在在 IDEA 里对 Codex 工作树的用法。
- **打开单个文件**（Finder 双击、`lite 文件`、拖到 Dock）：
  - 落到**项目包含这个文件的那个窗口**（有好几个就取路径最长的，也就是最具体的那个）；
  - 都不包含 → 落到**最后一个处于活动状态的窗口**（Sublime 的做法）；
  - 一个窗口都没有 → 新开一个。
- **关掉窗口不退出应用**（#41）。点 Dock 图标，或者用 ⌘O 这类不需要窗口的操作，都能把窗口叫回来。
- **⌘Q 退出后，下次启动恢复上次开着的所有窗口**，每个窗口的项目、标签、位置和大小都回来。
- **不做的**，见第 9 节：一个窗口里放多个根目录、标签拖到别的窗口、同一文件跨窗口同步编辑。

## 3. Rust 侧：资源按窗口归属

### 3.1 命令怎么知道自己是哪个窗口调的

Tauri 的命令可以声明一个 `window: tauri::WebviewWindow` 参数，框架会自动注入**发起这次调用的窗口**，前端什么都不用传。

所以 `pty_spawn`、`open_log`、`watch_root`、`git_fetch` / `git_push` / `git_cancel` 这些命令只要多一个参数，拿 `window.label()` 去登记就行。

- **IPC 的 DTO 不变**，`dto_sync` 不受影响；
- **前端调用不变**，浏览器桩（mock）也不变。

还有一条路是让前端自己传窗口 id。没选它，因为前端传的东西可能错，Rust 注入的一定对。这和 `open_external` 那条「约束写在 Rust 侧才算数」是同一个道理。

### 3.2 `AppState` 的四张表

| 表 | 改成 | 窗口 `Destroyed(label)` 时 |
|---|---|---|
| `ptys: HashMap<u32, Pty>` | `Pty` 多一个 `owner: String` 字段 | 只杀 `owner == label` 的终端（新增 `kill_ptys_of(label)`；`kill_all_ptys` 只留给退出路径用） |
| `files: HashMap<u32, Arc<LogFile>>` | 值变成 `(owner, Arc<LogFile>)` | 关掉这个窗口的所有句柄，过滤任务一起取消 |
| `watch: Mutex<Option<Watch>>` | `Mutex<HashMap<label, Watch>>` | 移除这个窗口的监听（先摘出来，在锁外析构，同现在的规矩） |
| `remotes: HashMap<u32, Cancel>` | 键变成 `(label, u32)` | 取消这个窗口还在跑的 fetch/push |

`MAX_PTYS = 16` 仍然是**整个进程**的上限，不按窗口算。它是一道「防跑飞」的闸，不是配额，闸就该装在总阀门上。

**每一个 `*_of(label)` 都照搬 `kill_pty` 的规矩：先从表里摘出来，放掉锁，再在锁外析构。**这条路径就在关窗口的流程上，析构卡住的表现是「点了关闭，窗口没反应」。

### 3.3 事件：谁发给谁

| 事件 | 发给 | 怎么做 |
|---|---|---|
| `menu` | **当前聚焦的窗口** | Rust 记下最近一次 `WindowEvent::Focused(true)` 的 label，用 `emit_to(label, …)`。一个窗口都没有时见 3.5 |
| `fs-changed` | 注册这个监听的窗口 | 监听回调里捕获 `label`，用 `emit_to` |
| `open-paths` | 按第 2 节的规则路由 | 路由是一个**纯函数**：输入「路径 + 开着哪些窗口、各自的项目根」，输出「送给哪个窗口 / 开新窗口 / 聚焦哪个」。单测覆盖 |

**`emit_to` 而不是 `emit_filter`，也不是让前端自己按窗口过滤。**让前端过滤，意味着每个窗口都要被唤醒一次，再各自判断「这不是给我的」。这条路今天行得通，可一旦哪个窗口漏判，就会重演「A 按 ⌘S、B 也保存」。在发送端做一次决定，不会有漏判。

### 3.4 `Inbox` 变成每个窗口一个

新窗口出现的过程是：Rust 创建窗口 → WebView 加载 → 前端挂上监听 → 调 `initial_paths`。这中间有几百毫秒。现在的 `Inbox` 就是为了盖住这段时间差，多窗口时照搬：

```rust
// 以前：一个全局的 (就绪?, 攒着的路径)
// 以后：每个窗口一份
inboxes: Mutex<HashMap<String /*label*/, (bool, Vec<String>)>>
```

- 路由决定「开新窗口，路径是 X」→ 先把 X 放进**新窗口的 inbox**，再创建窗口。新窗口的前端启动时调 `initial_paths`，Rust 看这次调用来自哪个 label，就把那个 label 的 inbox 交出去。
  **新窗口怎么知道自己该开哪个项目，靠的就是这一步**：不用拼 URL 参数，也不用新增命令。这条路是现成的。
- 窗口销毁时删掉它的 inbox（#41 那条「前端没了要回到攒着的状态」自然就解决了：窗口没了，它的 inbox 也没了，下一个路径会走「开新窗口」）。

### 3.5 窗口注册表（跨窗口的状态只有一个主人）

新增 `src-tauri/src/windows.rs`，Rust 进程里只有一份：

```rust
struct WinInfo {
    root: Option<String>,   // 前端在项目根变化时告诉 Rust（新命令 set_window_root）
    frame: Frame,           // 位置和大小，Moved / Resized 时更新（防抖）
    menu: MenuState,        // 这个窗口最后一次推送的菜单状态
}
struct Registry {
    wins: HashMap<String, WinInfo>,
    order: Vec<String>,     // 最近一次聚焦的顺序（最近的在前）
    closed: Vec<Closed>,    // 最近关掉的窗口（项目 + 位置）。点 Dock 重开时用
    recent: Vec<String>,    // 最近打开的项目，从 localStorage 搬过来
    recent_files: Vec<String>,
    quitting: bool,
}
```

它服务四件事：

1. **路由**（3.3）：要知道「哪个窗口开着哪个项目」。
2. **菜单状态**：`sync_menu_state` 只把状态存进**调用它的那个窗口**的 `WinInfo`。只有当调用者正是聚焦窗口时，才真正改原生菜单。窗口获得焦点时，Rust 用缓存把菜单重新刷一遍，不用等前端推。
   这样菜单显示的一定是**你正在看的那个窗口**的状态。
3. **最近打开**：原来每个窗口在自己内存里各存一份，互相覆盖，而且会误删别人的快照。收到这里之后：
   - 读：前端启动时取一次；
   - 写：打开项目时让 Rust 记一笔；
   - 「最近打开」原生菜单本来就由 Rust 建，这下不用再从前端推了（`set_recent` 这个命令可以删掉）。
4. **下次启动恢复哪些窗口**：落盘到 `~/Library/Application Support/com.liteide.app/windows.json`。

**为什么落文件，不落 `localStorage`：**
- `localStorage` 只有 WebView 能读，而创建窗口的决定必须在**前端起来之前**做出：先知道要开几个窗口，才能去开。
- 以后的配置文件（DIRECTION 第 6 节）也会放在这个目录。
- 代价：`scripts/uninstall.sh` 要多删一个目录。这一点写进第 6 步。

**读失败一律当作没有这个文件，绝不 panic**，这是启动路径的老规矩。

### 3.6 退出时，窗口列表不能被自己清空

这是这份设计里**最容易写错的一处**，单独说。

⌘Q 的时候，Tauri 会依次销毁每个窗口，每销毁一个都会触发一次 `Destroyed`。如果 `Destroyed` 的处理是「把这个窗口从注册表删掉，然后落盘」，那么最后一个窗口销毁时，落盘的是一张**空表**，下次启动一个窗口都恢复不出来。

更糟的是，这个 bug 在「只开一个窗口」时**看起来是好的**。单窗口时，这一张表里只有它自己，删掉后落一张空表，下次启动走默认流程，和现在的行为一样，所以察觉不到。只有开两个窗口再退出才会暴露。

规则：

- `RunEvent::ExitRequested` 里，**先把 `quitting = true`，再把当前窗口列表落盘**；
- `Destroyed` 里看到 `quitting` 为真，就只释放资源，**不改列表、不落盘**；
- 用户**单独关掉**一个窗口（不在退出流程里）：把它从 `wins` 挪进 `closed`，然后落盘。

同一个事件里，还要分清这次退出是「因为最后一个窗口关了」（要拦下来，#41），还是「⌘Q」（照常退出）：

- `ExitRequested { code: None }` 是「没有窗口了」触发的；
- ⌘Q 走的是 `app.exit()`，带着 code。

这一点在第 0 步实测确认。测试要覆盖「开两个窗口 → 退出 → 列表里还是两个」，并且按 AGENTS 的规矩，把 `quitting` 那行删掉，确认测试会变红。

### 3.7 建窗口

```rust
let cfg = app.config().app.windows[0].clone();   // 和 main 用同一份配置
WebviewWindowBuilder::from_config(app, &WindowConfig { label: next_label(), ..cfg })?
    .position(frame.x, frame.y)   // 恢复时用存下来的；新开时从聚焦窗口往右下错开 28pt（macOS 的习惯）
    .build()?;
apply_window_material(&w);        // 材质层每个窗口都要挂一次，不挂就是一扇透明的空窗
```

- **label**：第一个仍叫 `main`，后面的叫 `w-1`、`w-2`……，只增不复用。复用 label 会让还没清理完的旧资源撞上新窗口。
- **能力清单**：`capabilities/default.json` 的 `windows` 改成 `["main", "w-*"]`（Tauri 2 支持通配）。
  这是安全配置。它只是把现有的权限套到新窗口上，没有新增任何权限，但按 AGENTS 的规矩先在这里说明。
- **窗口标题**：`set_title(项目名)`。标题栏本身是隐藏的（`hiddenTitle`），但「窗口」菜单、Mission Control、⌘\` 用的都是它。现在所有窗口都叫 `lite-ide`，开三个就分不清谁是谁。

### 3.8 没有窗口时（#41）

- `ExitRequested` 没有 code → `api.prevent_exit()`，应用留在 Dock 上。
- `RunEvent::Reopen { has_visible_windows: false }`（点 Dock 图标）→ 从 `closed` 里取**最后关掉的那个**重开。如果 `closed` 是空的，就开一个空窗口。
- 菜单事件到来时一个窗口都没有：
  - 「打开文件夹…」「最近打开」「新建草稿」这类**不需要现有窗口的**，由 Rust 直接处理：前两个走「开新窗口」，新建草稿开一个空窗口再把事件转过去；
  - 其余的菜单项此时应该都是灰的。最后一个窗口销毁时，Rust 用「全部为假」的状态刷一遍菜单，理由同 #41 里写的：前端没了，就没人再同步菜单状态。
- `open-paths` 在没有窗口时，按路由规则走「开新窗口」。

## 4. 前端

### 4.1 会话快照怎么存

| 键 | 以前 | 以后 |
|---|---|---|
| `lite-ide.session` | 上次退出时的现场（带草稿） | **不再写**。第一次升级时读一次，迁移成第一个窗口的快照，然后删掉 |
| `lite-ide.session:<root>` | 每个项目一份，不带草稿标签（`withoutTabs` 滤掉） | **不变，但它成了唯一的一份**：窗口恢复时就读它。草稿标签也存进来（见下） |
| `lite-ide.session:`（空 root） | —— | 空窗口（没有项目）的那一份。同一时刻最多一个空窗口，所以一个键够了 |
| 最近打开、最近文件 | 在快照里 | 搬到 Rust 注册表（3.5） |

**草稿标签跟着窗口走。**以前草稿「贴在桌角，换项目它还在」，这是单窗口时代的规则：切项目时要把它从旧项目带到新项目。多窗口之后不再有「切项目」，每个窗口的草稿就待在这个窗口里，自然也就存进这个窗口的快照。
草稿文件本身在磁盘上的草稿目录里，并且会自动保存。所以任何一个窗口的草稿列表都能看到全部草稿，不会因为「在另一个窗口开着」就找不到。

**`#prune` 的新规则**：不再由窗口按自己内存里的列表去删别人的快照，改由 Rust 注册表决定。「最近打开」里挤出去的项目，Rust 告诉前端去删，而且**正开着的窗口的项目、以及快照里带着未保存草稿的，一律不删**。
后半句是在修一个今天就存在的洞：今天挤出最近列表时，里面的草稿会被静默删掉。只是单窗口时很难撞上。

### 4.2 打开文件夹

`tabflow.openPath` 对目录的处理，今天是「就地换项目根」（VS Code 的方式）。改成：

```ts
if (info.kind === "dir") {
  if (project.root === null) { /* 空窗口：照旧，就地变成这个项目 */ }
  else if (project.root !== info.path) { await openWindow(info.path); return; }  // 交给 Rust 路由
}
```

`openWindow` 是新命令，走和 `open-paths` 同一个路由：已经开着就聚焦，没开着就开新窗口。
⌘O、最近打开、工作树「打开」、文件树里右键「作为项目打开」，全都汇到这一个口。

`beforeRootChange` / `afterRootChange` 这对钩子**只在空窗口第一次得到项目根时**会跑。那时没有旧项目要存，也没有干净标签要关，逻辑可以简化。它的「切项目时关掉干净标签」那半边成了死代码，要删。按 AGENTS 的规矩，删之前先把它改坏，确认没有测试依赖它。

### 4.3 关窗口时有未保存的改动

**建议不弹窗，照现在的「热退出」处理**：未保存的内容进这个项目的快照，下次打开这个项目时原样回来。理由见第 7 节 Q3。

`pagehide` 已经会触发一次强制落盘（`App.svelte:493`）。关掉单个窗口时它能不能可靠地触发，第 0 步实测。如果不可靠，就改成拦截 `onCloseRequested`：先落盘，再放行关闭。

### 4.4 Git 控制台

控制台的记录是 Rust 里的一个全局环形缓冲，所有窗口跑的 git 都在里面。每条记录本来就带着 `cwd`，**展示时按当前窗口的仓库根过滤**就行，不用拆成多份存储。IDEA 的 Git 控制台也是每个项目各看各的。

## 5. 内存：这是真正的代价

每个窗口一个 WebView，**每个 WebView 一个 `WebKit.WebContent` 进程**。GPU 和 Networking 进程是共享的。按 2026-09-06 的实测：

| | 实测 / 估算 |
|---|---|
| 一个窗口起来（四个进程合计） | 152–158 MB（实测） |
| 其中 WebContent | 106–173 MB，随着开的标签数量变化（实测） |
| **每多开一个窗口** | **大约 +100–170 MB（估算，第 0 步要实测）** |
| 你的日常：4 个工作树 + 1 个前端仓库 = 5 个窗口 | **大约 600–800 MB（估算）** |

作为对比：IDEA 开 4 个窗口，它们共享一个 JVM，常见 2–3 GB；VS Code 每个窗口也是一个渲染进程，每个 200–400 MB。**所以 5 个窗口 600–800 MB，在同类工具里仍然是最轻的，只是离「<200 MB」那条预算很远了。**

「<200MB」那条是按「一个窗口」定的。多窗口之后，预算要改成**按窗口算**：

- 第一个窗口 < 200 MB（不变）
- 每多一个窗口 < 150 MB（第 0 步实测后定）

另一条路是「一个窗口，项目做成顶部的一排切换标签」。它确实省内存，但放不下「两个项目在两块屏幕上并排」这种用法，而这正是你现在在 IDEA 里做的事，所以不选。

**有一处可以留作以后优化，这次不做**：长时间没被聚焦的窗口，可以把它的编辑器 / 日志视图卸载掉，只留状态和终端，WebContent 就能缩回几十 MB。等实测到多窗口确实让机器吃紧再做。

## 7. 拍板记录（2026-10-08，四条都按建议）

**Q1 内存：每多一个窗口大约 +100–170 MB，接受吗？**
**定：接受。**理由是第 5 节那张对比表，而且这正是你要的用法。第 0 步实测后，把预算改成按窗口算。

**Q2 打开项目时，要不要像 IDEA 那样每次问「当前窗口 / 新窗口」？**
**定：不问**，规则固定：已经开着就聚焦，当前窗口是空的就用它，否则开新窗口。
IDEA 那个对话框大多数人第一次就勾了「别再问」。我们不做设置页，勾上的选项也没有地方存。真想「在当前窗口换项目」，先「关闭项目」再打开就行，多一步，但不会有歧义。

**Q3 关掉一个有未保存改动的窗口，要不要弹窗问保存？**
**定：不弹**，和现在关应用时一样，改动进快照，下次打开这个项目时回来。
你熟悉的两套都不弹：Sublime 是热退出，IDEA 是自动保存。唯一的风险是「这个项目很久不再打开，快照被挤出最近列表时一起删掉」，4.1 已经把这个口子堵上了。

**Q4 从 Finder 打开单个文件：落到「项目包含它的窗口」，没有的话落到「最后活动的窗口」，行吗？**
**定：行。**日志文件多半不在任何项目里，就会落到你正在用的那个窗口，和 Sublime 一样。

## 8. 验收（真 `.app` 上）

1. 开项目 A，用 ⌘O 开项目 B → 出现第二个窗口；用 ⌘O 再开 A → 回到 A 窗口，不开第三个
2. A、B 各开一个终端，在 B 里跑 `sleep 100`；关掉 A 窗口 → B 的 `sleep` 还在跑
3. A、B 同时 fetch → 两边都成功，各自的进度条只在自己窗口里动
4. 在 A 里按 ⌘S → 只有 A 保存；聚焦 B 时菜单的变灰状态是 B 的
5. 在 A 的项目里改文件 → A 的文件树刷新，B 不动（`LITE_IDE_DEBUG=1` 看 `app.log` 里 `fs-changed` 只发了一次）
6. 分支浮层里打开一个工作树 → 新窗口，标题是工作树的名字
7. 关掉所有窗口 → 进程还在，Dock 图标还在；点 Dock → 最后关掉的那个项目回来
8. 开三个窗口，⌘Q，再启动 → 三个窗口都回来，位置、标签、光标都对
9. 在 A 里改了没保存，关掉 A，再打开 A → 改动还在
10. 窗口都关着时 `open -a lite-ide x.log` → 开出一个窗口，里面是这个文件
11. ⌘Q 之后 `pgrep zsh` 里没有孤儿进程

## 9. 这一轮明确不做

- **一个窗口里放多个根目录**（VS Code 的多根工作区）：你的用法是一个窗口一个项目，D1 那段写过了。
- **把标签拖到另一个窗口**：要跨 WebView 转移编辑器状态（包括撤销历史），成本高，用得少。
- **同一个文件在两个窗口里同步编辑**：两个窗口开着同一个文件时，照现有的「外部改动」检测处理，和「另一个程序改了这个文件」一样对待。等真撞到了，再考虑全局的「一个文件只在一个窗口里」登记。
- **macOS 原生的窗口标签页**（把多个窗口合并成一个窗口里的标签）：系统可能白送，但它和我们自己的标签条叠在一起会很乱。第 0 步顺手看一下，默认关掉。
- **把不活动的窗口卸载以省内存**：见第 5 节最后一段。
