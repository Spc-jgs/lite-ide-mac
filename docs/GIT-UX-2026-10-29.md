# Git 与差异视图修复 · 2026-10-29

本轮解决截图中两项问题：双栏 / 统一差异的阅读与滚动，以及提交历史缺少刷新、提交后不更新。图标沿用已有资源，没有新依赖，没有改真实仓库的提交或分支。工作树中此前的工作台 UI、资源治理及任务日志改动保留。

## 为什么历史不更新

代码已有窗口焦点、文件监听和 Git 写操作后的 `git.refresh()`，但它只刷新状态与 stash，以及活的工作区差异。`GitLog.svelte` 原来只依赖仓库和筛选条件，因此 `HEAD` 已变化，提交列表仍可停在旧结果。更改侧栏的刷新按钮也没有使历史失效；底部历史没有独立刷新入口。

现在 Git 状态维护历史更新序号。HEAD、分支或上下游计数变化时使历史失效；`.git` 事件与显式刷新也会更新历史，覆盖 HEAD 不变但远程引用变化的情况。普通工作区保存、状态未变化时不重复读取历史。显式刷新与普通刷新并发时，更新请求保留到最新有效响应，旧响应不能覆盖新状态。

底部 Git 标题栏和侧栏使用同一刷新动作。刷新保留关键词、当前提交与列表位置；返回时以当时的选择为准，刷新过程中点另一条也不会被抢回。新增“跳到最新提交”入口，清除关键词、选首行并滚到顶端。失败保留旧列表、显示原因，提供重试。历史仍只加载最近 300 条，达到上限时明确标记，不把局部列表冒充完整历史。

## 差异的阅读规范

沿用项目字号、配色和图标，使用 IDE 的信息密度与 macOS 的克制控件层级。版本名称独立成一行，代码区不与工具条争空间：

- 未暂存：暂存区 → 工作区；已暂存：HEAD → 暂存区；历史：提交前 → 该提交；与本地比较：该提交 → 工作区。本地历史单独标明“所选历史版本 / 当前内容（含未保存更改）”。
- 双栏平分可用空间，中央分隔独立；同一网格负责两侧纵向对齐，长行不会撑宽某一栏。
- 统一视图固定旧 / 新行号与增删标记，只滚动代码；上下文与改动共用相同列宽，不再被最长行撑开。
- 横向滚动条放在视口底部，短差异和滚动到中段均可操作；双栏共享偏移，支持拖动、方向键、Home / End。换行后收起横向滚动条，两侧继续对齐。
- 字号和行高跟随编辑器。换行、前后变化、展开未变化行及按行 / 按块暂存继续可用；历史差异保持只读。
- 窄于 720px 的差异区域自动统一显示；恢复宽度后恢复用户的双栏选择。新建 / 删除文件沿用单侧视图。
- 差异区右键和 Shift+F10 提供复制选区、前后更改、换行及显示方式；新建菜单不增加图标。

另修正底部工具窗按需加载的依赖：加载 effect 只跟随工具窗开合 / 类型，不订阅加载器内部的 busy / comp 状态；错误通知也不订阅通知自身。旧写法遇到模块请求失败，会在 busy 恢复后再次加载，连续拉取并挤满通知记录。故障注入中从 1003 次模块请求、300 条有界记录，降到一次请求、一次通知。

## 右键入口的范围

文件树、编辑器、更改列表共用按文件定位的 Git 动作：查看工作区更改、查看已暂存更改、提交历史、暂存、取消暂存、放弃更改。冲突文件的工作区入口打开合并视图，“暂存”显示“标记为已解决”。不可执行项灰显；不可逆放弃继续进入既有确认，不直接改盘。

编辑器的文件历史与所选行历史使用右键文件和它自己的选区，不再借用全局活动标签。分屏中右键未激活编辑器时也不能误指向另一个文件。更改列表支持 Shift+F10；历史文件菜单补上打开工作区文件和复制相对路径，删除文件的打开入口灰显。

## Git 功能盘点与下一步

参照 JetBrains 的 [Log tab](https://www.jetbrains.com/help/idea/log-tab.html)、[Differences viewer](https://www.jetbrains.com/help/idea/differences-viewer.html) 与 [Git integration](https://www.jetbrains.com/help/idea/using-git-integration.html)，再逐项核对当前组件、命令包装和 Git 服务。以下“已有”表示代码入口存在，不等于本轮逐项重新做了真实远程验收。

| 交互式 rebase 与继续 / 跳过 / 放弃 | RebaseDialog、GitPane 操作横条 | 已有，不在本轮扩写 |

| Stash | 更改菜单储藏、恢复最近一次 | 有基础入口；缺完整 stash 浏览、挑选和删除 UI |
| Worktree | BranchPicker 新建 / 打开 / 移除 | 已有，不纳入文件右键 |
| Git 控制台 | 独立标签，命令 / 错误 / 复制 / 清空 / 刷新 | 已有，保留 |

| 任意两条提交 / 两个分支的完整比较 | 现有单提交、单文件与本地比较不能替代 | 仍缺，需要比较对象选择和多文件结果视图 |
| 从历史提交新建分支 / 创建与管理标签 / revert / reset | 目前分支挂件可新建、检出标签或提交，历史行未提供这些操作 | 部分缺；需逐项明确影响与确认，不能给所有动作套同一种确认框 |
| 历史中独立分支树、多选提交、可配置列 | 目前通过挂件和“全部分支”进入，单选提交 | 仍缺，不影响此次更新修复 |
| 文件树目录级批量 Git、忽略 / 停止跟踪、重命名 / 删除的 Git 语义 | 本轮只统一单文件动作；目录原有文件操作不冒充 Git 命令 | 仍缺，应明确作用范围再补 |
| Changelists / Shelve、托管平台 PR 集成 | 当前无专门模型与界面 | 未实现，不为对齐 IDEA 自动引入新系统 |
| 历史查询错误的后端语义 | `gitsvc::history::log_entries` 当前将 `Error::Git` 统一视为空历史，并非只识别空仓库 | 仍需区分未出生分支与真实查询失败；本轮重试覆盖 IPC 实际返回错误的情况 |
| 空白忽略与高级 diff 选项、差异编辑 | 当前差异只读，提供换行和单双栏 | 仍缺；不能把“统一”误称可编辑模式 |

下一步建议优先历史错误语义、分页 / 定位与比较对象选择；涉及改历史的 reset / revert、标签、目录批量操作单独设计。此次没有将盘点中的全部缺口扩大成一次 Git 重写。

## 资源测量：保留 REVIEW，不作为性能通过

本轮改变历史的更新触发与工具窗 effect，选择 `scripts/resources.sh --build --profile quick`，出现增长观察项后再跑 `--profile full`。两轮源码 SHA-256 都是 `d36850ee09d63f6f55d6b0f231af8edb1b63e752e1fb8090c15318c0bd19b699`，测试二进制为 `c0b0dab893f8f73bd3adfc2540f5ee103c335867d9bb0ae1dd7ecbc465c92066`；测量前后源码未变化。HEAD 为 `b094ada`、dirty，不能只用 HEAD 代替整个工作树身份。

- [quick 报告](../design/workbench-2026-10-29/Git-resource-quick.md)：四轮关闭后 footprint 从 188.58 到 302.33 MiB；恢复空闲 245.20 MiB，单核 CPU 0.15%。
- [full 报告](../design/workbench-2026-10-29/Git-resource-full.md)：两轮预热、八轮测量、关闭后等待 15 秒、空闲采样 60 秒；关闭后 footprint 从 248.07 到 285.32 MiB，增长约 37.25 MiB，拟合约 4.65 MiB/轮、R² 0.851。恢复空闲 287.79 MiB，单核 CPU 0.22%，该 60 秒 logical writes 84 KiB；主进程 FD 始终 11，退出后未发现登记的残留进程。
- full 快速打开 12 文件的采样峰值约 637.35 MiB，超过 300 MiB 调查参考线。两轮都是 `REVIEW`，没有删告警、放宽阈值或强制 GC。

full 初段与正式打包有时间重叠，系统内存压力等级测前测后均为 2，swap 占用也有变化；这些条件与原始计数保留在 JSON。结果只能作为本机当前工作树的调查线索，不能用来宣称性能改善。延长等待后仍有增长观察项，后续需在无构建干扰的同场景下结合 Allocations 定位存活对象；目前不能单凭这些数字判定泄漏或归因给本轮 Git 改动。这里没有扩成未经证据支持的缓存重写。

quick / full 是后台无 JVM、12 小文件与日志的有限场景，不覆盖真实大仓库长期工作、前台帧率或 Java 语言服务器；本轮真实 Git 验收单独记录，未把资源脚本当成 Git 功能验证。
