# 使用手册

从源码到 macOS 应用，以及日常怎么用。

---

## 一、日常开发

```bash
pnpm install          # 只需第一次
pnpm app              # 起 dev server 并打开窗口，改前端热更新
```

只改前端时不必重编译壳 —— 浏览器里打开 <http://localhost:1420> 就能调 UI，
会自动挂上一个 IPC 桩喂假数据（`src/lib/dev/mock-ipc.ts`），秒级热更新。
生产构建里一个字节都不会带进去 —— 靠的是 `main.ts` 里那个 `import.meta.env.DEV` 分支：
生产构建时它是常量假，整段连同 `import()` 在编译期就被删掉，不是靠 tree-shaking
（tree-shaking 曾经漏过一次，见 `.claude/rules/frontend.md`）。

---

## 二、打包成 App

```bash
pnpm app:bundle       # 生成 .app 与 .dmg
```

产物在：

```
src-tauri/target/release/bundle/
├── macos/lite-ide.app                    4.6 MB
└── dmg/lite-ide_0.1.0_aarch64.dmg        2.4 MB
```

只想要可执行文件、不打包（迭代时更快）：

```bash
pnpm app:build        # 只编译，产物 src-tauri/target/release/lite-ide
```

## 三、怎么用它

**不用装。** `pnpm app:bundle` 打完包，直接双击

```
src-tauri/target/release/bundle/macos/lite-ide.app
```

Spotlight 也搜得到它，`open -a lite-ide` 一样能开。

**把它设成文本文件的默认打开方式**（可选，但这是「看一眼文件」不再去开别的
编辑器的关键一步）：在 Finder 里选一个 `.log` / `.txt` / `.md`，`⌘I`，
「打开方式」里选 lite-ide，点「全部更改…」。右键「打开方式」的列表里也有它，
拖到 Dock 图标上也能开 —— 三条路都进**已经开着的那个应用**，不会再起一个进程；
文件落到项目包含它的那个窗口，哪个项目都不包含（多半是日志）就落到你正在用的那个窗口。

> 曾经往 `~/Applications` 复制过一份，结果是 Spotlight 里出现**两个**同名
> `lite-ide.app`。两份只要有一次「打包了没重装」就分叉，而你不会知道自己
> 点开的是哪一个 —— 这正好是踩过的那个坑（照着旧构建的现象查了半天代码）。
> 盘上只留一份，就没有点错的可能。
>
> 代价是 `cargo clean` 或删掉 `target/` 会把它一起带走。产物本来就是可再生的，
> 重新 `pnpm app:bundle` 即可。

### 关于 Gatekeeper

这个 app 用的是 **adhoc 临时签名**，没有开发者证书、没有公证
（自用工具，PLAN 里就定了不做签名分发）。

**自己本地构建的不受影响**：quarantine 标记是文件"从网络下载"时才会被打上的，
本地编译出来的没有，双击直接能开。实测确认过。

**如果把 .dmg 传到另一台机器**（AirDrop、网盘、U 盘、GitHub Release 都算），
那份文件会带上 quarantine，首次打开会弹"无法验证开发者"。两种处理：

```bash
# 办法一：去掉 quarantine 标记（推荐，一次就好）
xattr -dr com.apple.quarantine /Applications/lite-ide.app
```

办法二：在 Finder 里 **右键点图标 → 打开**，弹窗里再点一次"打开"。
之后双击就正常了。

## 四、命令行启动

```bash
open -a lite-ide                          # 上次的现场
open -a lite-ide ~/some-project           # 打开一个项目目录
open -a lite-ide /var/log/system.log      # 打开单个文件
```

更顺手的是 `lite` 命令：菜单「文件 → 安装命令行工具…」。装完：

```bash
lite ~/some-project
lite huge.log "带 空格/的.txt"
```

传目录 → 作为项目根打开：这个项目已经有窗口开着就回到那个窗口，没有就开一个新窗口；
传文件 → 只开这个文件，**不会**把它的父目录当成项目（看一眼 `~/Downloads/x.log` 不该让
Downloads 变成项目、进最近列表），落到项目包含它的窗口，都不包含就落到你正在用的窗口。
应用没开就冷启动。

`/usr/local/bin` 在多数机器上要 sudo 才写得进去，那时脚本已经写好在
`~/Library/Application Support/com.liteide.app/bin/lite`，界面会把补软链的那句
`sudo ln -sf …` 摆出来，抄进终端跑一次就行。`.app` 挪过位置就再点一次菜单重装。

> 这一节到 2026-09-15 之前写的是「给二进制做个软链」—— **那是错的**。macOS 上
> 双击、拖 Dock、`open -a` 送文件走的是 Apple Event，不走命令行参数；软链到
> 二进制只在应用没开着时有效，开着时会再起一个进程。生成的 `lite` 脚本是一句
> `exec open -a …`，冷热都对。当时 `open -a lite-ide 文件` 本身也不通
> （应用起来了，文件没开），是接了 `RunEvent::Opened` 之后才通的。

### 日志模式里的搜索

过滤框里可以写多个条件，语法照 grep 的习惯：

| 写法 | 意思 |
|---|---|
| `order timeout` | 两个都得有（空格 = 且） |
| `timeout -healthcheck` | 有 timeout 且**没有** healthcheck |
| `"connection pool"` | 带空格的整串 |
| `/order.?id=\d+/` | 正则；`-/re/` 是排除正则 |

大小写跟右边的 `Aa`，正则也一样。正则写坏了框里的字会变红，那一条不生效、别的照常。
单独一个 `-` 或 `/` 是字面量。非 UTF-8 的文件（GBK 日志）里，正则只对 ASCII 可靠 ——
中文关键字请用字面量，它会按文件编码转过再搜。

在过滤框敲关键字之后，右边有一组「只看命中 / 全文」：

| | 什么时候用 |
|---|---|
| **只看命中** | 「这个订单号出现过几次」—— 视图里只剩命中行 |
| **全文** | 「这条报错前后发生了什么」—— 显示全文，在命中之间跳 |

跳转：`↵` 下一处、`⇧↵` 上一处（焦点在过滤框里时），或者 `F3` / `⇧F3`（任何时候），
也可以点计数旁边那两个箭头。计数显示 `2/4,167`，当前停的那一行左侧有一条蓝线。

跳到底会绕回第一条 —— 一直按「下一处」不会卡住。

### 最左边那条竖条

所有工具的入口都在那儿。上半截是侧边栏的：开关、文件树、Git 改动、搜索、
**草稿**（便签图标，没开项目也在）；底下那两个是底部工具窗的：**终端**和
**提交历史**（钟表）。

状态栏里**没有**这些的第二份 —— 打开哪个工具窗只有导轨这一处。
**收起侧边栏时它留着**，按钮位置不变 —— 不用每次去找开关跑哪儿去了。
Git 图标右上角的角标是未提交的改动条数（超过 99 显示 `99+`）。

点亮着的那个图标就把对应的面板收起来 —— 一个按钮既是「去那儿」也是「不看了」。

### 标题栏与状态栏

窗口顶上只有两个挂件：**项目**（点开是最近项目 / 打开文件夹 / 清除记录）和
**分支**（点开是分支与工作树）。右边那一大片是空的 —— 那是拖窗口的地方。
从这两处打开别的项目或工作树，都是**开一个新窗口**（见「十一、多窗口与会话恢复」）。

底下状态栏分左右两半：

- **左**：当前文件的路径。点其中的目录段会在文件树里定位到它。
  有提示消息时（「已保存」「已切到 xxx」）消息顶掉路径，过几秒自己回来。
- **右**：当前文件的状态，而且**点了都能改** —— 编辑/日志模式、语言、编码、
  有没有未保存的改动、有没有未提交的改动。窗口窄到 740px 以下时，
  「知道了也不改变下一步」的那几格会先退场。

### 文件树

**点文件和点目录列出来** —— `.gitignore`、`.github/`、`.env`、`.claude/`
这些天天要改的东西就在树里。

**不列的是版本库目录和系统杂物**：`.git`、`.svn`、`.hg`、`CVS`，`.DS_Store`、`Thumbs.db`。
它们不是项目的内容，是工具和系统替你放的；VS Code 和 IDEA 默认也都藏它们。`.git/` 藏起来
主要是为了安全 —— 列在树上就能对它右键删除、改名、往里拖文件，手一滑仓库就坏了。
要看 `.git/config` 这类东西走终端。搜索也不进这几个。

**合并单层目录**（树头第四个按钮，默认开）：一个目录里只有一个子目录、别的什么都没有，
就和子目录并成一行，照 IDEA 的 Compact Middle Packages：

```
src/main                ← 普通目录用 / 连（Go、Python、前端都一样）
  java                  ← 源码根（src/<源码集>/java|kotlin|scala|groovy）自己占一行
    com.demo.order      ← 源码根底下的包用 . 连
```

在合并行上**新建、拖进来、重命名、移到废纸篓，都作用在最深那一层**（上例是 `order`）——
重命名框里写的就是 `order`。往链中间放进别的东西，这一行会自己拆开。

**生成物目录列出来，只是压暗**。里面几万个文件没有一个是手写的
（`target/` 在 lite-ide 自己的仓库里就有 1GB 多），但它们在树里、点得开，里面的文件照样打得开：

- `node_modules`、`target`、`venv`、`__pycache__` 只可能是生成物，见到就压暗；
- `dist`、`build`、`vendor` 也常常是源码（CMake 的 `build/` 放构建脚本、Go 的 `vendor/` 是提交进仓库的），
  所以**要问 git**：被忽略才压暗，没被忽略就是普通目录。不是 git 仓库时退回按名字压暗。

`⌘P` 和 `⇧⌘F` 跟树用**同一套生成物判据**：树里压暗的目录搜不到，没压暗的搜得到。
例外是点开头的文件和目录 —— 树里照列，搜索**一律不进**（`.github/` 也搜不到；⌘P 放行 `.env`）。

压暗的目录不参与上面的「合并单层目录」。原来生成物目录是直接不列的，
一个真叫 `build/` 的源码目录在这里完全够不着，见
[issue #13](https://github.com/Spc-jgs/lite-ide-mac/issues/13)。

整棵树只占一个 `Tab` 停靠点，进去之后用方向键走：

| 键 | 作用 |
|---|---|
| `↑` `↓` | 上下移动 |
| `→` | 目录收着就展开，已展开就进到第一个子项 |
| `←` | 目录展开着就收起，否则回到父目录 |
| `Home` `End` | 首 / 尾 |
| `↵` | 打开文件 / 展开收起目录 |
| `F2` | 重命名 |
| `⌫` / `⌘⌫` | 移到废纸篓（先确认；选了多个就是这几个）。打字定位的过程中 `⌫` 是删掉刚打的字母 |
| `⇧F10` / `≣` | 打开右键菜单（菜单里也用 `↑↓` 走，`↵` 执行，`Esc` 关） |

**右键菜单**（点头部那个项目名，是在项目根下操作）：

| | |
|---|---|
| 新建文件… / 新建文件夹… | 在目录上右键就建在里面，在文件上右键就建在它旁边。**撞名不会覆盖**，会告诉你已经有一个了 |
| 重命名… | 输入框里默认只选中扩展名之前那段。打开着的标签会跟着改路径 |
| 移到废纸篓 | 走系统废纸篓，**Finder 里可以「放回原处」**。有未保存的标签会在确认框里说清有几个 |
| 在 Finder 中显示 / 复制路径 / 复制相对路径 | |

这里**没有真删除**：整个应用里唯一的删除路径就是废纸篓。
但要注意废纸篓救得回来的是**磁盘上那一份** —— 编辑器里没保存的改动随标签一起没。

### 草稿

`⌘N`（或标签栏末尾的 `+`）给一张空白纸，光标已经在里面，不问名字、不问存哪 —— 它是
`~/Library/Application Support/com.liteide.app/scratches/2026-09-15 1511.md`
这样一个真实文件。**不用 ⌘S**：停止输入半秒、切走、关标签、退出，都会自动写盘；
关草稿标签也不会问「保存 / 丢弃」。一个字没写就关掉的会被自动丢掉。

标签栏上显示的是草稿的**第一行**（「周会要点」），不是那串时间戳。
翻旧的走导轨上的「草稿」（便签图标）：最近的在上，每条是「第一行 · 时间」，
点开只是叠一个标签，**不切项目**；右键有「在 Finder 中显示 / 移到废纸篓」。
`⌘P` 打时间戳也能找到它们（结果里标「草稿」）。

草稿标签**跟着它所在的那个窗口**：重启后回到那个窗口。草稿文件本身在草稿目录里，
任何一个窗口的「草稿」列表都看得到全部草稿。
「文件 → 在 Finder 中显示草稿目录」是去 Finder 里整理用的。

项目里的文件**不在停手时存**，这是有意的：打字停半秒就写盘，半成品会触发 watcher、
构建和 git 差异；草稿目录里没有任何东西盯着它，所以它可以。

但项目文件**离开就存**（照 IDEA）：窗口失焦（切到别的应用）、焦点进了内置终端时，
项目根下改过的文件会自动写盘 —— 「改完代码去终端跑 mvn」时编译的就是刚改的那份。
切标签、关标签、退出**不算**离开：关标签照旧有「关闭前会问」，退出不问 —— 改动进会话快照，
下次打开还在（见「十一」）。项目外的文件
（从 Finder 随手打开的）和按错编码读进来的文件（状态栏挂着 ⚠ 的）一律不自动存。

### 标签栏

中键点标签关闭；标签多到溢出时滚轮可以横向滚。**拖标签**可以排序，拖到另一组的
标签条上就是挪过去；钉住的只在钉住区里挪，没钉的进不了钉住区。

**右键菜单**（`⇧F10` 或 `≣` 键也能开）：

| | |
|---|---|
| 关闭 / 关闭其他 / 关闭右侧的 / 关闭全部 | 有未保存改动的标签会**逐个问**，确认框上会写还剩几个。中途点「取消」就整批停下 |
| 在文件树中定位 | 展开到它并滚过去 |
| 在 Finder 中显示 / 复制路径 / 复制相对路径 | 差异和冲突标签没有这几项 —— 它们对应的不是盘上的文件 |
| 向右分屏打开 / 移到另一组 | 见下面「分屏」。一组里只有一个标签时不出现 |

### 分屏

左右两组，各自一条标签条，中间那条线能拖。「左边看定义、右边改调用」是它的用途。

| | |
|---|---|
| `⌘\` | 向右分屏：把当前标签挪到右边那组（没有右组就建一个） |
| `⌃⌘→` | 移到另一组 |
| `⌥Tab` | 光标切到另一组 |
| 视图 › 合并分屏 | 右组并回左组 |

状态栏、面包屑、⌘S / ⌘W 都只讲**光标所在**的那一组；另一组的当前标签颜色会暗一档。
一组关到空就自动收起。同一个文件只能开在一组里 —— 在另一组里再打开它，光标会跳过去。
分屏状态和分隔线位置跨重启记得住。

未保存的改动**跨重启也留得住**：切标签留得住，退出应用再打开也还在，
标签上那个圆点会照旧亮着（提醒你还没存盘）。

重开时如果那个文件在外面被人改过了，会摆出「用磁盘上的 / 保留我的」让你选 ——
和应用开着的时候撞上外部改动是同一套。草稿恰好和磁盘上一样时直接丢掉，不算改动。

**一个例外**：单个文件的未保存改动超过 50 万字符就存不下了（会话快照存在
浏览器的 localStorage 里，写满会出问题）。真碰上会有一句提示让你 `⌘S`。

### 编辑器

**键位照 IDEA**（macOS 默认键位，2026-09-23 起；之前是 CodeMirror 自带的 VSCode 手感）：

| 键 | 作用 |
|---|---|
| `⌘Z` / `⇧⌘Z` | 撤销 / 重做 |
| `⌘F` / `⌘R` | 查找 / 替换；`⌘G` `⇧⌘G` 下一处 / 上一处 |
| `⌘/` / `⌥⌘/` | 行注释 / 块注释 |
| `⌘D` | 复制行（有选区时复制选区） |
| `⌘⌫` | 删除行 |
| `⌥⇧↑` / `⌥⇧↓` | 上移 / 下移行 |
| `⌥↑` / `⌥↓` | 扩大 / 缩小选区 |
| `⌃G` / `⌃⌘G` | 再选中下一个相同的词 / 选中所有相同的词 |
| `⇧⌘U` | 切换大小写 |
| `⌘[` / `⌘]` | 回退 / 前进（同 `⌥⌘←` / `⌥⌘→`） |

缩进用 `Tab` / `⇧Tab`（`⌘[` `⌘]` 让给了回退 / 前进）。`⌥` + 点击加多光标。
全表在「帮助 › 快捷键速查」。

**切标签不丢撤销**：切走再切回来，`⌘Z` 照样撤得回切走前打的字（光标、选区也在）。
切走期间文件被外面改了（git checkout、构建工具重写）就不接了 —— 旧的撤销步骤对不上新内容。

**右键菜单**：跳到声明、在项目里找这个名字、剪切 / 复制 / 粘贴、复制路径 / 相对路径、
在文件树中定位、在 Finder 中显示；Git 仓库里还有「查看这个文件的改动」「注解」。
右键点在选区外会先把光标挪过去 —— 菜单作用在点的那个词上。

**离开就存**：项目文件在两个时刻自动存盘 —— **切到别的应用**、**焦点进了内置终端**。
改完代码点进终端敲 `mvn`，编译的就是改完那份（IDEA 同样的规矩，用它的手从来不按 ⌘S）。
停手、切标签不存（半截代码写进盘会惊动构建工具和 Git）；关标签照旧会问，退出不问（改动进会话快照，下次打开还在）。
只存项目根下的文件；**编码认错（状态栏 ⚠）的不自动存** —— 写回去会把解不出的字节永久丢掉，换个编码重开再说。

**括号 / 引号自动配对**：打 `(` 出 `()`，光标在中间，Backspace 一次删一对。
**补全**：代码文件里打两三个字母就弹，来源是这个文件里出现过的词加语言包自带的关键字
（没有 LSP，这是立项时定的，见 PLAN.md）。`↑` `↓` 挑，`↵` 或 `Tab` 用，`Esc` 关。
Markdown / 纯文本里**不弹** —— 记笔记时每个词弹一个框是最败兴的事；括号配对照旧。

**软换行**：`.md` `.txt` `.log` 和没有扩展名的文件默认换行，代码不换；
「视图 → 自动换行」按标签切换（不记住，下次打开按默认来）。

**字号**：`⌘=` / `⌘-`（视图菜单里也有）临时放大缩小，所有窗口一起变、下次打开还是这样；
`⌘0` 回到设置文件里写的字号（`editor.fontSize`，没写就是 13）。只管编辑器，终端的字号在设置文件里单独配。

**焦点**：⌘N、⌘P、双击树、从 Finder 送进来的文件，光标直接在编辑器里，打字就是了。
单击树里的文件是预览，焦点留在树上——你多半正用方向键往下走。

**跳到声明**：按住 `⌘` 悬停，能跳的词出下划线，点它（或光标放上去按 `⌘B`）；`⌥⌘←` 回来。
**有下划线就一定跳得准，跳不准的一律不画** —— 这是这个功能唯一的承诺。能跳的：本文件里的声明、
`import` / 同包的类；Java 里还有局部变量、字段，以及 `repo.findById()` 这种成员（按 `repo`
写出来的声明类型去那个类里找）。不跳的：继承来的方法（在 jar 里的父类上）、参数个数一样的重载、
`var` 和链式调用 —— 这些要 LSP 才判得准。
**Java 着色照 IDEA**：注解黄、方法声明蓝、字段紫（使用处也紫）、static 斜体。
认不出来的名字（父类继承的字段、Lombok 生成的 `log`）保持白色，不猜。

### 日志视图

`↑` `↓` 逐行、`PageUp` `PageDown` 翻页、`Home` `End` 首尾。

**`⌘L` 跳到行或时间**：输 `200` 跳到第 200 行；输 `14:32` / `14:32:05` 跳到第一条不早于
那个时间的行（九百万行的文件也是二分，一眨眼）。不带日期时按正在看的那一天算，要换天
就写全 `2026-08-25 09:00`。认的时间戳：`2026-08-24 14:03:21`、`Aug 24 14:03:21`（syslog）、
nginx 的 `[24/Aug/2026:14:03:21`、JSON 里的 `"time"` / `"ts"` / `"timestamp"`。

**堆栈帧点了跳源码**：`at com.demo.OrderService.persist(OrderService.java:142)` 这种帧，
能在当前项目里唯一找到源文件的，「文件:行号」画成蓝色下划线，点了跳过去，`⌥⌘←` 回日志。
在 jar 里的（Spring、JDK）和多个模块撞名的不画 —— 所以一段堆栈里亮着的那几行就是你自己的代码。

### 差异视图

`F7` 下一处改动、`⇧F7` 上一处改动。工具栏上可以在**双栏对照**和**统一视图**
之间切换 —— 窄窗口用统一视图更合适。

**`⌥Z`（或工具栏的「换行」）开软换行**：长行折进列宽，整块差异不再横向滚。
一屏里有几条长 import 或长字符串时，双栏最容易出现「左边空着一大片、
右边的新增行却被切掉」—— 那正是开换行的时候。默认关着，因为代码差异
是按行读的，折行会把「这是一行」这个信息弄糊。

把一个文件暂存之后，它的改动就从工作区跑到了暂存区。差异标签会**自动跟过去**，
不会停在一句「没有差异」上。

## 六、Git

不是 Git 仓库时，下面这些入口整体不出现，不会碍事。

### 改动列表（侧边栏）

`⌘K`，或点侧边栏顶上那个分支图标。

- 分成**冲突中 / 已暂存 / 改动**三组，每行悬停时右边浮出 `＋`（暂存）
  和 `↺`（丢弃）
- 点文件名打开差异；点冲突文件打开合并界面
- 上面是提交框，`⌘↵` 提交。有未解决的冲突时提交按钮是灰的

### 提交历史（底部工具窗）

点左边导轨最底下那个**钟表**图标。
（导轨上它的邻居是终端；点当前亮着的那个就把面板收起来。）
提交列表支持 `↑` `↓`，在过滤框里按 `↓` 直接跳进列表。

左边是带泳道图的提交列表（合并、分叉都画出来），右边是选中提交的详情和
它动过的文件 —— 点文件名就能看那次提交里的差异。

上面可以按标题 / 作者 / sha 过滤，也可以只看当前文件的历史。

> 加了过滤条件之后泳道图会隐藏。因为筛掉一批提交之后，剩下的提交之间父子关系
> 是断的，硬画出来的线是假的 —— 一条看起来直连的线，中间可能隔着二十条被筛掉的
> 提交。宁可不画。

### 切分支 / 工作树

点标题栏上那个分支挂件（`⑂ main`），浮层从它底下掉下来。
里面是本地分支、工作树、远程分支三组：

- 选一条分支 → 切过去
- 选一条**远程分支** → 检出为同名的本地分支（`--track`，会多一个本地分支）
- 输入一个不存在的名字 → 出现「新建分支」，后面写着它从哪条分支分出来
- 选一个工作树 → 把那个目录当项目根打开。**打开的标签不会动**，提示里会说一句
- 「新建工作树…」→ 填目录和分支，建好之后自动打开

**每一行都有右键菜单**（也可以 hover 出行尾的 `⋯`，或者按 `⇧F10`）：
分支能「在新工作树中打开」和复制名字，工作树能在 Finder 里显示、复制路径、
以及**移除**（红色，会删掉那个目录，所以它只在菜单里）。

### 切不过去的时候

工作区有改动、而目标分支也改过同样的文件时，git 会拒绝 —— 这时不会弹一段
英文报错，而是列出**挡路的那几个文件**，给三个选择：

| | |
|---|---|
| 去提交 | 跳到 Git 改动列表，提交完再切 |
| 丢弃这些改动并切换 | 红色。丢掉那几个文件的改动，然后**自动把刚才那次切换重放一遍** |
| 取消 | 什么也不做 |

> 没有「暂存改动再切」（`git stash`）这一档。改动多又不想提交的时候，
> 用工作树：同一个仓库的第二个检出目录，可以在不打断当前改动的前提下
> 把另一个分支同时摊开在磁盘上。

工作树是同一个仓库的第二个检出目录 —— 可以在不打断当前改动的前提下，
把另一个分支同时摊开在磁盘上。改动多的时候比 `git stash` 顺手得多。

### 解决冲突

冲突文件在改动列表里是「冲突中」那一组，点开是逐块的合并界面：
每个冲突块左右并排显示两边的内容，各自可以「取这边」，也可以「两边都要」
或者取共同祖先。

- 全部决定完 → 按钮变成「保存并标记已解决」，保存的同时 `git add`
- 还有没决定的 → 按钮是「保存进度」，没决定的冲突块**原样保留标记**，
  回头可以接着处理

### 文件树上的颜色

改过的文件名会染色（蓝=改、绿=增、红=删、灰绿=未跟踪），右边还有一个状态字母。
两样都给是有意的：颜色扫得快，字母说得准。目录自己没改但里面有东西改了时，
右边是一个小圆点。

新建一整个目录时，文件树上目录本身是「未跟踪」的颜色，而**改动列表里列的是
里面那些文件** —— 一个目录点不开差异，摆在列表里那一行除了占位没有别的用。

## 七、编码

状态栏右边那一格显示当前文件的编码。lite-ide 会自动探测（先看 BOM，
再看是不是合法 UTF-8，最后才用统计探测去猜），**用什么编码读进来就用什么存回去**
—— 保存不会顺手把你的 GBK 文件转成 UTF-8。

点那一格打开选择器，里面两个按钮意思不同：

| 按钮 | 做什么 |
|---|---|
| 重新打开 | 按新编码**重新解码**文件内容。发现乱码时用这个 |
| 以此编码保存 | 只改「将来存成什么」，不动当前内容。按 `⌘S` 才真的落盘 |

如果那一格是**红色带 ⚠**，说明按当前编码解码时有解不出的字节，界面上显示成 `�`。
**这种状态下保存会把那些字节永久写成 U+FFFD。**换个编码重新打开试试。

支持 UTF-8 / GB18030 / GBK / Big5 / Shift_JIS / EUC-KR / UTF-16 / windows-1252 /
KOI8-R。日志模式同样认这些编码。

## 八、代码缩略图

编辑器右侧那条就是。

- 点一下跳过去，按住拖动连续滚
- 长文件滚动时不会卡：画好的内容缓存成一整块，滚动只是把需要的那段贴过来
- 左缘的彩色小条是相对 HEAD 的改动：绿=新增、蓝=修改、红=删除处
- 文件短的时候整份铺开；长到一屏画不下时，窗口跟着滚动位置滑动

不想要的话：双击 `⇧` 搜「缩略图」，选「切换代码缩略图」。设置会记住。

> 改动标记反映的是**磁盘上那份**。编辑器里改了还没保存时，标记不会跟着动，
> 保存之后会刷新。

## 九、两种模式

打开文件时会自动判定：

| 条件（任一满足） | 模式 |
|---|---|
| 大于 32MB | 日志模式（只读） |
| 估算超过 30 万行 | 日志模式 |
| 存在超过 1 万字符的长行 | 日志模式 |
| 含 NUL 字节（二进制） | 日志模式 |
| 其余 | 编辑模式 |

**自动判定只是默认值，不是死判决** —— 状态栏右边的「编辑模式 ⇄ / 日志模式 ⇄」
点一下就能切。切到编辑模式时如果文件超过 8MB 会先问一句，
因为编辑模式要把全文读进内存交给 CodeMirror。

日志模式里有级别 chips 过滤、文本搜索、跟随尾部（tail）；
编辑模式支持 67 种语言的语法高亮，Markdown 还带 live preview。

## 十、升级

重新打包覆盖即可：

```bash
pnpm app:bundle
```

打包细节、产物位置、发版流程见 [RELEASE.md](RELEASE.md)。

它等价于「打包 → 删掉旧的 → 拷过去」三步，合成一条是有原因的：

> **`pnpm app:build` 不会更新 `.app`。** 它只编出 `target/release/lite-ide`
> 这个可执行文件；`target/release/bundle/macos/lite-ide.app` 里那份是上一次
> `app:bundle` 留下的，可能已经很旧了。而你双击启动的正是后者。
>
> 这坑踩过一次：一个已经修好的 bug 又被报上来，照着现象查了半天代码，
> 最后发现跑的是前一天编出来的 `.app`。

**怎么确认自己跑的是哪个构建**：把鼠标停在标题栏左上角那个**项目挂件**上
（`▣ 项目名 ⌄`），提示的第二行就是构建时间。跟你上次 `pnpm app:bundle`
的时间对不上，就是旧的。

没有自动更新器 —— 自用工具不值得为它引入一套更新基础设施，
也就没有"更新服务器挂了怎么办"这类问题。

## 十一、多窗口与会话恢复

**一个项目一个窗口**，同时开几个都行 —— 照 IDEA。几种打开项目的方式都按同一条规矩走：

| 你做的 | 这个项目已经开着 | 没开着，当前窗口有项目 | 没开着，当前窗口是空的 |
|---|---|---|---|
| `⌘O`、「最近打开」、拖文件夹进窗口 | 回到那个窗口 | 开新窗口 | 就在当前窗口打开 |
| 分支浮层里「打开」一个工作树 | 回到那个窗口 | 开新窗口 | —— |
| `lite 目录` / Finder 拖文件夹到 Dock | 回到那个窗口 | 开新窗口 | 就在当前窗口打开 |

不会弹「当前窗口 / 新窗口」的选择框：真想在当前窗口换项目，先「文件 → 关闭项目」再打开。
窗口标题是项目名，「窗口」菜单和 `` ⌘` `` 能分清每个窗口。

**每个窗口各管各的**：菜单、`⌘S`、`⌘W` 只作用于你正在用的那个窗口；文件树、Git 状态
只因为自己项目里的变动刷新；终端属于开它的窗口，关掉别的窗口不会杀掉它；Git 控制台只显示、
只清空这个窗口的仓库跑过的命令；`⌘E`（最近文件）按窗口记，「最近打开」的项目全应用一份。

**关掉最后一个窗口，应用不退出**（macOS 的常规）：它留在 Dock 上，点 Dock 图标就把最后关掉
的那个项目开回来。`⌘Q` 才是退出 —— 退之前每个窗口会先把现场存好（最多等 2 秒），
所以打完字马上 `⌘Q` 也不会丢。Dock 右键「退出」、注销、关机不经过这一步，只靠
每 4 秒一次的定时落盘兜底。

**重开应用会回到上次退出时的样子**：开着的每个窗口（项目、位置、大小）都回来，每个窗口里
打开的文件（含哪个是活动的）、每个文件停在第几行、侧边栏与底部面板的开合和尺寸、分屏，
都是它自己那一份。上次退出前全关掉了窗口的话，开回最近关掉的那一个。项目目录已经不在了
（删了、挪了、外接盘没插）的窗口不恢复。

命令行、Finder 双击、拖 Dock 图标给了路径时（这几条走的是同一个口）：

| 你做的 | 行为 |
|---|---|
| `lite` / 点图标 | 恢复上次开着的窗口 |
| `lite 某文件` / 双击文件 | 落到项目包含它的窗口，开在那个窗口的现场上面 |
| `lite 另一个目录` / 拖文件夹到 Dock | 见上面那张表：开着就回去，没开着就开新窗口 |

**「文件 → 关闭项目」**回到没有项目的轻窗口：项目自己的干净标签关掉（有改动的留着，
关的时候会问），草稿标签不动，侧边栏只剩「打开文件夹…」和草稿。只看文件、记草稿
不需要项目；要项目就 `⌘O` 或者拖文件夹进来。没有项目的窗口启动时如果一个标签都没有，
会直接落在一份草稿里；为项目开的窗口没有标签就空着。

**未保存的改动**跨重启、跨关窗口都留得住（见「标签栏」那节）。**不会恢复的两样**：
日志模式的过滤条件、终端会话（pty 是活的子进程，跨进程恢复不了）。
（这里原来写着「未保存的改动不会恢复」，那是 2026-09-03 之前的事，一直没跟着改。）

上次开着的文件这次不在了（删了、改名了、切到了没有它的分支）会被静默跳过，
不弹错误。想从干净状态重来的话，把 `~/Library/WebKit/com.liteide.app` 和
`~/Library/Application Support/com.liteide.app/windows.json` 删掉即可
（`scripts/uninstall.sh` 覆盖这两个路径）。

## 十二、设置

**lite-ide → 设置…**（`⌘,`）在编辑器里打开设置文件。第一次打开时它会建一份模板：所有设置项都列着、
**全都注释着**（`//` 开头），旁边写着默认值和说明 —— 去掉行首的 `// ` 就生效。存盘立刻生效，所有窗口一起变，不用重启。

文件在 `~/Library/Application Support/com.liteide.app/settings.json`。你也可以用别的编辑器改它，lite-ide 照样能看到变化。
只写你要改的，没写的就是默认值；能写注释、最后一项后面多个逗号也没关系。

```jsonc
{
  // 我在外接屏上看，字大一点
  "editor.fontSize": 15,
  "editor.fontFamily": "Fira Code",
  "terminal.shell": "/opt/homebrew/bin/fish",
}
```

| 设置项 | 默认 | 说明 |
|---|---|---|
| `editor.fontFamily` | `"JetBrains Mono"` | 代码字体：编辑器、差异、日志视图。写具体的字体名，系统里没有就退回 JetBrains Mono |
| `editor.fontSize` | `13` | 代码字号（9–28）。`⌘=` / `⌘-` 在它上面临时加减，`⌘0` 回到这里写的值 |
| `terminal.fontFamily` | `""` | 终端字体，空 = 跟 `editor.fontFamily` 一样 |
| `terminal.fontSize` | `13` | 终端字号（9–28） |
| `terminal.shell` | `""` | 终端用的 shell，写完整路径；空 = 系统的 `$SHELL`。**只对新开的终端生效**，开着的不动（换 shell 等于杀掉重开） |

编辑这个文件时，在一行开头敲 `"` 会列出所有设置项，选一个就把它连默认值一起插进来。

**写错了不会让应用打不开**，而且一定会告诉你：

| 写错的样子 | lite-ide 怎么做 |
|---|---|
| JSON 本身坏了（少个括号、引号没收尾） | 启动时：全用默认值；用着的时候改坏了：**保留上一份好的**（不会字体先跳回默认再跳回来） |
| 某一项类型不对（`"editor.fontSize": "14"`） | 只有这一项用默认值，别的照常 |
| 不认识的设置项（`editor.fontsize`，大小写拼错） | 忽略它，并且说出来 —— 拼错时这是唯一的线索 |
| 数值超出范围（字号 200） | 夹回范围里 |
| `terminal.shell` 指的文件不存在或不能执行 | 终端用 `$SHELL` |

有问题时状态栏中间会常驻一个「设置有 N 处问题」，鼠标停上去看全部，点一下打开设置文件跳到那一行；
编辑器里有问题的那一行带底色，行尾写着原因。改好存盘，提示自动消失。

**按钮和快捷键改的那几样不在这个文件里**：代码缩略图开关、文件树「合并单层目录」「跟随标签」、Git 改动「按目录分组」、
`⌘=` 调出来的字号，存在旁边的 `ui-state.json` 里，由应用自己写，你不用管它（删掉就回到默认）。
分开放是为了**应用从不改你手写的那份**：按一下按钮就改写你的文件，你写的注释和排版会被冲掉。

**JDK / Python / Node 的路径不在这里配**：终端用的是你的登录 shell，读你的 `.zshrc`，和你平时一样。
以后的「通用任务运行」（#48）也会经过你的登录 shell 去跑命令。

```bash
./scripts/uninstall.sh            # 先 dry-run 看要删什么

```

窗口关闭，有单测卡着），配置只写 `com.liteide.app` 标准目录。
