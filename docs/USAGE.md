# 使用手册

从源码到 macOS 应用，以及日常怎么用。

---

## 一、日常开发

```bash
pnpm install          # 只需第一次
pnpm app              # 起 dev server 并打开窗口，改前端热更新
```

只改前端时不必重编译壳 —— 浏览器里打开 <http://localhost:1420> 就能调 UI，
会自动挂上一个 IPC 桩喂假数据（`src/lib/dev/mock-ipc.ts`），秒级热更新。
生产构建里这个桩会被 tree-shake 掉，一个字节都不会带进去。

---

## 二、打包成 App

```bash
pnpm app:bundle       # 生成 .app 与 .dmg
```

产物在：

```
src-tauri/target/release/bundle/
├── macos/lite-ide.app                    4.6 MB
└── dmg/lite-ide_0.1.0_aarch64.dmg        2.4 MB
```

只想要可执行文件、不打包（迭代时更快）：

```bash
pnpm app:build        # 只编译，产物 src-tauri/target/release/lite-ide
```

---

## 三、怎么用它

**不用装。** `pnpm app:bundle` 打完包，直接双击

```
src-tauri/target/release/bundle/macos/lite-ide.app
```

Spotlight 也搜得到它，`open -a lite-ide` 一样能开。

> 曾经往 `~/Applications` 复制过一份，结果是 Spotlight 里出现**两个**同名
> `lite-ide.app`。两份只要有一次「打包了没重装」就分叉，而你不会知道自己
> 点开的是哪一个 —— 这正好是踩过的那个坑（照着旧构建的现象查了半天代码）。
> 盘上只留一份，就没有点错的可能。
>
> 代价是 `cargo clean` 或删掉 `target/` 会把它一起带走。产物本来就是可再生的，
> 重新 `pnpm app:bundle` 即可。

### 关于 Gatekeeper

这个 app 用的是 **adhoc 临时签名**，没有开发者证书、没有公证
（自用工具，PLAN 里就定了不做签名分发）。

**自己本地构建的不受影响**：quarantine 标记是文件"从网络下载"时才会被打上的，
本地编译出来的没有，双击直接能开。实测确认过。

**如果把 .dmg 传到另一台机器**（AirDrop、网盘、U 盘、GitHub Release 都算），
那份文件会带上 quarantine，首次打开会弹"无法验证开发者"。两种处理：

```bash
# 办法一：去掉 quarantine 标记（推荐，一次就好）
xattr -dr com.apple.quarantine /Applications/lite-ide.app
```

办法二：在 Finder 里 **右键点图标 → 打开**，弹窗里再点一次"打开"。
之后双击就正常了。

## 四、命令行启动

```bash
open -a lite-ide                          # 空窗口
open -a lite-ide ~/some-project           # 打开一个项目目录
open -a lite-ide /var/log/system.log      # 打开单个文件
```

也可以给二进制做个软链，更顺手（在项目目录下执行）：

```bash
ln -sf "$PWD/src-tauri/target/release/bundle/macos/lite-ide.app/Contents/MacOS/lite-ide" \
       /usr/local/bin/lite
lite ~/some-project
lite huge.log
```

传目录 → 作为项目根打开；传文件 → 打开它并把父目录当项目根。

## 五、快捷键

### 全局

| 键 | 作用 |
|---|---|
| 双击 `⇧` | 随处搜索（文件 / 内容 / 操作，Tab 切范围） |
| `⌘P` | 按文件名找文件 |
| `⌘⇧F` | 在项目中搜内容 |
| `⌘⇧O` | 当前文件的结构大纲 |
| `⌘⇧G` | Git 改动列表 |
| `⌘S` | 保存 |
| `⌘W` | 关闭当前标签 |
| `⌘1` / `⌘B` | 收起 / 展开侧边栏 |
| `⌘J` | 收起 / 展开终端面板 |
| `⌃⇧\`` | 新建终端 |
| `Esc` | 关掉浮窗 |

搜索浮窗里：`↑` `↓` 选择、`↵` 打开、`Tab` 换范围、`Esc` 关闭。

### 日志模式里的搜索

在过滤框敲关键字之后，右边有一组「只看命中 / 全文」：

| | 什么时候用 |
|---|---|
| **只看命中** | 「这个订单号出现过几次」—— 视图里只剩命中行 |
| **全文** | 「这条报错前后发生了什么」—— 显示全文，在命中之间跳 |

跳转：`↵` 下一处、`⇧↵` 上一处（焦点在过滤框里时），或者 `F3` / `⇧F3`（任何时候），
也可以点计数旁边那两个箭头。计数显示 `2/4,167`，当前停的那一行左侧有一条蓝线。

跳到底会绕回第一条 —— 一直按「下一处」不会卡住。

### 最左边那条竖条

所有工具的入口都在那儿。上半截是侧边栏的：开关、文件树、Git 改动、搜索；
底下那两个是底部工具窗的：**终端**和**提交历史**（钟表）。

状态栏里**没有**这些的第二份 —— 打开哪个工具窗只有导轨这一处。
**收起侧边栏时它留着**，按钮位置不变 —— 不用每次去找开关跑哪儿去了。
Git 图标右上角的角标是未提交的改动条数（超过 99 显示 `99+`）。

点亮着的那个图标就把对应的面板收起来 —— 一个按钮既是「去那儿」也是「不看了」。

### 标题栏与状态栏

窗口顶上只有两个挂件：**项目**（点开是最近项目 / 打开文件夹 / 清除记录）和
**分支**（点开是分支与工作树）。右边那一大片是空的 —— 那是拖窗口的地方。

底下状态栏分左右两半：

- **左**：当前文件的路径。点其中的目录段会在文件树里定位到它。
  有提示消息时（「已保存」「已切到 xxx」）消息顶掉路径，过几秒自己回来。
- **右**：当前文件的状态，而且**点了都能改** —— 编辑/日志模式、语言、编码、
  有没有未保存的改动、有没有未提交的改动。窗口窄到 740px 以下时，
  「知道了也不改变下一步」的那几格会先退场。

### 文件树

**点文件和点目录一律列出来** —— `.gitignore`、`.github/`、`.env`、`.claude/`
这些天天要改的东西就在树里，不用靠 ⌘P 摸黑打开。`.git/` 也在，
树是懒展开的，不点开它就只占一行。

**不列的只有四个构建产物目录**：`node_modules`、`target`、`dist`、`build`。
它们不是「隐藏文件」，是别人生成的东西 —— 里面几万个文件没有一个是手写的
（`target/` 在 lite-ide 自己的仓库里就有 1GB 多）。这四个没有开关，
而且 `⌘P` 和 `⇧⌘F` 也跳过它们（外加 `.git` `.next` `.venv` 等几个），
所以一个真叫 `build/` 的源码目录在这里是够不着的 —— 见
[issue #13](https://github.com/Spc-jgs/lite-ide-mac/issues/13)。

整棵树只占一个 `Tab` 停靠点，进去之后用方向键走：

| 键 | 作用 |
|---|---|
| `↑` `↓` | 上下移动 |
| `→` | 目录收着就展开，已展开就进到第一个子项 |
| `←` | 目录展开着就收起，否则回到父目录 |
| `Home` `End` | 首 / 尾 |
| `↵` | 打开文件 / 展开收起目录 |
| `⇧F10` / `≣` | 打开右键菜单（菜单里也用 `↑↓` 走，`↵` 执行，`Esc` 关） |

**右键菜单**（点头部那个项目名，是在项目根下操作）：

| | |
|---|---|
| 新建文件… / 新建文件夹… | 在目录上右键就建在里面，在文件上右键就建在它旁边。**撞名不会覆盖**，会告诉你已经有一个了 |
| 重命名… | 输入框里默认只选中扩展名之前那段。打开着的标签会跟着改路径 |
| 移到废纸篓 | 走系统废纸篓，**Finder 里可以「放回原处」**。有未保存的标签会在确认框里说清有几个 |
| 在 Finder 中显示 / 复制路径 / 复制相对路径 | |

这里**没有真删除**：整个应用里唯一的删除路径就是废纸篓。
但要注意废纸篓救得回来的是**磁盘上那一份** —— 编辑器里没保存的改动随标签一起没。

### 标签栏

中键点标签关闭；标签多到溢出时滚轮可以横向滚。

**右键菜单**（`⇧F10` 或 `≣` 键也能开）：

| | |
|---|---|
| 关闭 / 关闭其他 / 关闭右侧的 / 关闭全部 | 有未保存改动的标签会**逐个问**，确认框上会写还剩几个。中途点「取消」就整批停下 |
| 在文件树中定位 | 展开到它并滚过去 |
| 在 Finder 中显示 / 复制路径 / 复制相对路径 | 差异和冲突标签没有这几项 —— 它们对应的不是盘上的文件 |

未保存的改动**跨重启也留得住**：切标签留得住，退出应用再打开也还在，
标签上那个圆点会照旧亮着（提醒你还没存盘）。

重开时如果那个文件在外面被人改过了，会摆出「用磁盘上的 / 保留我的」让你选 ——
和应用开着的时候撞上外部改动是同一套。草稿恰好和磁盘上一样时直接丢掉，不算改动。

**一个例外**：单个文件的未保存改动超过 50 万字符就存不下了（会话快照存在
浏览器的 localStorage 里，写满会出问题）。真碰上会有一句提示让你 `⌘S`。

### 编辑器

标准的 CodeMirror 键位：`⌘Z` / `⌘⇧Z` 撤销重做、`⌘F` 查找、`⌘/` 注释、
`⌥↑` `⌥↓` 移动行、`⌘D` 选中下一个相同词、`⌥` + 点击加多光标。

### 日志视图

`↑` `↓` 逐行、`PageUp` `PageDown` 翻页、`Home` `End` 首尾。

### 差异视图

`F7` 下一处改动、`⇧F7` 上一处改动。工具栏上可以在**双栏对照**和**统一视图**
之间切换 —— 窄窗口用统一视图更合适。

**`⌥Z`（或工具栏的「换行」）开软换行**：长行折进列宽，整块差异不再横向滚。
一屏里有几条长 import 或长字符串时，双栏最容易出现「左边空着一大片、
右边的新增行却被切掉」—— 那正是开换行的时候。默认关着，因为代码差异
是按行读的，折行会把「这是一行」这个信息弄糊。

把一个文件暂存之后，它的改动就从工作区跑到了暂存区。差异标签会**自动跟过去**，
不会停在一句「没有差异」上。

## 六、Git

不是 Git 仓库时，下面这些入口整体不出现，不会碍事。

### 改动列表（侧边栏）

`⌘⇧G`，或点侧边栏顶上那个分支图标。

- 分成**冲突中 / 已暂存 / 改动**三组，每行悬停时右边浮出 `＋`（暂存）
  和 `↺`（丢弃）
- 点文件名打开差异；点冲突文件打开合并界面
- 上面是提交框，`⌘↵` 提交。有未解决的冲突时提交按钮是灰的

### 提交历史（底部工具窗）

点左边导轨最底下那个**钟表**图标。
（导轨上它的邻居是终端；点当前亮着的那个就把面板收起来。）
提交列表支持 `↑` `↓`，在过滤框里按 `↓` 直接跳进列表。

左边是带泳道图的提交列表（合并、分叉都画出来），右边是选中提交的详情和
它动过的文件 —— 点文件名就能看那次提交里的差异。

上面可以按标题 / 作者 / sha 过滤，也可以只看当前文件的历史。

> 加了过滤条件之后泳道图会隐藏。因为筛掉一批提交之后，剩下的提交之间父子关系
> 是断的，硬画出来的线是假的 —— 一条看起来直连的线，中间可能隔着二十条被筛掉的
> 提交。宁可不画。

### 切分支 / 工作树

点标题栏上那个分支挂件（`⑂ main`），浮层从它底下掉下来。
里面是本地分支、工作树、远程分支三组：

- 选一条分支 → 切过去
- 选一条**远程分支** → 检出为同名的本地分支（`--track`，会多一个本地分支）
- 输入一个不存在的名字 → 出现「新建分支」，后面写着它从哪条分支分出来
- 选一个工作树 → 把那个目录当项目根打开。**打开的标签不会动**，提示里会说一句
- 「新建工作树…」→ 填目录和分支，建好之后自动打开

**每一行都有右键菜单**（也可以 hover 出行尾的 `⋯`，或者按 `⇧F10`）：
分支能「在新工作树中打开」和复制名字，工作树能在 Finder 里显示、复制路径、
以及**移除**（红色，会删掉那个目录，所以它只在菜单里）。

### 切不过去的时候

工作区有改动、而目标分支也改过同样的文件时，git 会拒绝 —— 这时不会弹一段
英文报错，而是列出**挡路的那几个文件**，给三个选择：

| | |
|---|---|
| 去提交 | 跳到 Git 改动列表，提交完再切 |
| 丢弃这些改动并切换 | 红色。丢掉那几个文件的改动，然后**自动把刚才那次切换重放一遍** |
| 取消 | 什么也不做 |

> 没有「暂存改动再切」（`git stash`）这一档。改动多又不想提交的时候，
> 用工作树：同一个仓库的第二个检出目录，可以在不打断当前改动的前提下
> 把另一个分支同时摊开在磁盘上。

工作树是同一个仓库的第二个检出目录 —— 可以在不打断当前改动的前提下，
把另一个分支同时摊开在磁盘上。改动多的时候比 `git stash` 顺手得多。

### 解决冲突

冲突文件在改动列表里是「冲突中」那一组，点开是逐块的合并界面：
每个冲突块左右并排显示两边的内容，各自可以「取这边」，也可以「两边都要」
或者取共同祖先。

- 全部决定完 → 按钮变成「保存并标记已解决」，保存的同时 `git add`
- 还有没决定的 → 按钮是「保存进度」，没决定的冲突块**原样保留标记**，
  回头可以接着处理

### 文件树上的颜色

改过的文件名会染色（蓝=改、绿=增、红=删、灰绿=未跟踪），右边还有一个状态字母。
两样都给是有意的：颜色扫得快，字母说得准。目录自己没改但里面有东西改了时，
右边是一个小圆点。

新建一整个目录时，文件树上目录本身是「未跟踪」的颜色，而**改动列表里列的是
里面那些文件** —— 一个目录点不开差异，摆在列表里那一行除了占位没有别的用。

## 七、编码

状态栏右边那一格显示当前文件的编码。lite-ide 会自动探测（先看 BOM，
再看是不是合法 UTF-8，最后才用统计探测去猜），**用什么编码读进来就用什么存回去**
—— 保存不会顺手把你的 GBK 文件转成 UTF-8。

点那一格打开选择器，里面两个按钮意思不同：

| 按钮 | 做什么 |
|---|---|
| 重新打开 | 按新编码**重新解码**文件内容。发现乱码时用这个 |
| 以此编码保存 | 只改「将来存成什么」，不动当前内容。按 `⌘S` 才真的落盘 |

如果那一格是**红色带 ⚠**，说明按当前编码解码时有解不出的字节，界面上显示成 `�`。
**这种状态下保存会把那些字节永久写成 U+FFFD。**换个编码重新打开试试。

支持 UTF-8 / GB18030 / GBK / Big5 / Shift_JIS / EUC-KR / UTF-16 / windows-1252 /
KOI8-R。日志模式同样认这些编码。

## 八、代码缩略图

编辑器右侧那条就是。

- 点一下跳过去，按住拖动连续滚
- 长文件滚动时不会卡：画好的内容缓存成一整块，滚动只是把需要的那段贴过来
- 左缘的彩色小条是相对 HEAD 的改动：绿=新增、蓝=修改、红=删除处
- 文件短的时候整份铺开；长到一屏画不下时，窗口跟着滚动位置滑动

不想要的话：双击 `⇧` 搜「缩略图」，选「切换代码缩略图」。设置会记住。

> 改动标记反映的是**磁盘上那份**。编辑器里改了还没保存时，标记不会跟着动，
> 保存之后会刷新。

## 九、两种模式

打开文件时会自动判定：

| 条件（任一满足） | 模式 |
|---|---|
| 大于 32MB | 日志模式（只读） |
| 估算超过 30 万行 | 日志模式 |
| 存在超过 1 万字符的长行 | 日志模式 |
| 含 NUL 字节（二进制） | 日志模式 |
| 其余 | 编辑模式 |

**自动判定只是默认值，不是死判决** —— 状态栏右边的「编辑模式 ⇄ / 日志模式 ⇄」
点一下就能切。切到编辑模式时如果文件超过 8MB 会先问一句，
因为编辑模式要把全文读进内存交给 CodeMirror。

日志模式里有级别 chips 过滤、文本搜索、跟随尾部（tail）；
编辑模式支持 67 种语言的语法高亮，Markdown 还带 live preview。

## 十、升级

重新打包覆盖即可：

```bash
pnpm app:bundle
```

打包细节、产物位置、发版流程见 [RELEASE.md](RELEASE.md)。

它等价于「打包 → 删掉旧的 → 拷过去」三步，合成一条是有原因的：

> **`pnpm app:build` 不会更新 `.app`。** 它只编出 `target/release/lite-ide`
> 这个可执行文件；`target/release/bundle/macos/lite-ide.app` 里那份是上一次
> `app:bundle` 留下的，可能已经很旧了。而你双击启动的正是后者。
>
> 这坑踩过一次：一个已经修好的 bug 又被报上来，照着现象查了半天代码，
> 最后发现跑的是前一天编出来的 `.app`。

**怎么确认自己跑的是哪个构建**：把鼠标停在标题栏左上角那个**项目挂件**上
（`▣ 项目名 ⌄`），提示的第二行就是构建时间。跟你上次 `pnpm app:bundle`
的时间对不上，就是旧的。

没有自动更新器 —— 自用工具不值得为它引入一套更新基础设施，
也就没有"更新服务器挂了怎么办"这类问题。

## 十一、会话恢复

重开应用会回到上次退出时的样子：项目根、打开的文件（含哪个是活动的）、
每个文件停在第几行、侧边栏与底部面板的开合和尺寸。

命令行给了路径时：

| 你敲的 | 行为 |
|---|---|
| `lite-ide` | 恢复上次的现场 |
| `lite-ide 某文件` | 恢复现场，再把这个文件开在上面 |
| `lite-ide 另一个目录` | 当作切项目，不恢复旧项目的标签 |

**不会恢复的三样**：未保存的改动（只存路径不存内容，恢复出来的永远是盘上
当前的样子）、日志模式的过滤条件、终端会话（pty 是活的子进程，跨进程恢复不了）。

上次开着的文件这次不在了（删了、改名了、切到了没有它的分支）会被静默跳过，
不弹错误。想从干净状态重来的话，把 `~/Library/WebKit/com.liteide.app` 删掉即可
（`scripts/uninstall.sh` 也覆盖这个路径）。

## 十二、卸载

见 [UNINSTALL.md](../UNINSTALL.md)。一句话版本：

```bash
./scripts/uninstall.sh            # 先 dry-run 看要删什么
./scripts/uninstall.sh --yes      # 确认后执行
```

本项目承诺零全局污染：不装全局 npm 包、无 LaunchAgent、无常驻进程
（终端子进程随窗口退出，有单测卡着），配置只写 `com.liteide.app` 标准目录。
