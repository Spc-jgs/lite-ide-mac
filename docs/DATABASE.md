# 数据库客户端：设计稿（docs/TAKEOVER.md MVP-9，D7）

> 状态：**设计稿，2026-10-27**。D7 定的是「要做、先写设计稿」；D11 起这类决定我来定，下面每个选择都写了为什么、怎么推翻。还没写一行代码。

## 1. 要什么、不要什么

取代 IDEA 的 Database 工具窗里**天天用的那一半**：

| 要 | 不要（这一版） |
|---|---|
| 连接管理（MySQL、PostgreSQL 起步；H2 / SQLite 给验收和本地开发用） | 表结构的图形化设计器（改表走 SQL） |
| 库 → 表 → 列 / 索引的树（懒加载） | ER 图、数据对比、迁移 |
| SQL 控制台：⌘↵ 跑光标所在的那条、历史、取消 | 存储过程调试 |
| 结果表格：几十万行不卡（分批取、虚拟滚动）、复制成 TSV / CSV / INSERT | Redis、MongoDB（另算，不在这一期） |
| 改单元格 → 先给你看要执行的 UPDATE，点了才执行 | 自动提交以外的事务界面（先做「手动提交」一个开关） |
| 导出结果 / 整张表（CSV、JSON、INSERT，边取边写盘） | |
| SQL 里的表名、列名补全（取元数据缓存） | Java 字符串 / MyBatis XML 里的 SQL 补全（第 6 节，后做） |

判据还是 DIRECTION 那句：**秒开不等、独立进程可关、正式包不变大**。数据库客户端不打开就一个字节不加载。

## 2. 驱动怎么带：比了三条路

| | A. JDBC，跑在内置的 Java 21 上（边车进程） | B. Rust 的驱动（sqlx / tokio-postgres / mysql_async） | C. 起 `mysql` / `psql` 命令行、解析输出 |
|---|---|---|---|
| 能连什么 | 所有有 JDBC 驱动的（MySQL、PG、Oracle、SQL Server、H2、达梦、OceanBase……）—— IDEA、DBeaver 都是这条路 | 每种库一个 crate；Oracle / SQL Server 基本没有能用的 | 装了哪个命令行连哪个 |
| 类型 | JDBC 的类型系统，`getObject` + 元数据，和 IDEA 看到的一样 | 每个 crate 各一套，DECIMAL / 时区 / JSON 各写一遍 | 全是字符串，NULL 和空串分不清 |
| 正式包 | **不变**：Java 21 运行时已经在包里（jdtls 用的）；驱动按需下（MySQL Connector/J 是 GPL，本来就不能打进包） | 变大：每种驱动 + TLS（rustls 一套就 1–2 MB） | 不变 |
| 启动 | 第一次开数据库工具窗起一个 JVM，约 0.3–0.6 秒（量过 jdtls 的冷启动 JVM 本身 0.2 秒）；闲 10 分钟收掉 | 0 | 每条 SQL 起一次进程 |
| 内存 | 边车 ~60–80 MB，只在用时 | 几 MB | 0 |
| 取消、流式 | `Statement.cancel()`、`setFetchSize` 分批 | 各 crate 不一样 | 杀进程 |

**选 A**。理由三条：能连的范围（国内 Java 后端会碰到 Oracle、达梦、OceanBase，只有 JDBC 有）；类型和 IDEA 一致（同一条 SQL 在两边看到同样的值）；
正式包不变大 —— Java 21 已经在包里，驱动按需下。代价是一个边车进程，和 jdtls 同一种形状（`lspsvc` 那套：进程组、stdin 说话、空闲收掉、`release_window` 收尸）。

**C 不选**：NULL 和空串分不清、类型全丢，这在看数据时是会骗人的。**B 不选**：Oracle / 国产库没有，正式包变大。

推翻它的条件：如果边车的冷启动实测超过 1 秒、或者常驻内存压不到 100 MB 以下，就退回 B、只做 MySQL / PG。

## 3. 边车长什么样

```text
lite-ide (Rust)                         lite-db.jar（Java 21，打包时用内置的 JDK 编，同 hotswap 的 agent）
  dbsvc crate ── stdin/stdout ──────────▶ 一行一条 JSON：{id, op, args}
    · 起 / 停 / 空闲收                        connect / meta / query / fetch / cancel / execute / close
    · 每条请求等多久（连接 10 秒，查询不设）    结果分批回：列定义一次，行每批 500，带「还有没有」
    · 输出设闸（单条消息 16 MB）
```

- **驱动**：`~/Library/Application Support/<id>/jdbc/` 下，第一次连某种库时从 Maven Central 下钉死的版本、核 sha256（同 JaCoCo，D10）。说清下的是什么、多大、什么许可证（MySQL Connector/J 是 GPL：下到你机器上自用没问题，不能打进我们的包）
- **一个连接一个 JDBC Connection**，边车里的线程按连接分，一条查询能单独 `cancel`
- **结果不全取**：`setFetchSize(500)`，界面滚到底再要下一批；导出是边车直接写文件（不经过 IPC，几百万行也不撑内存）
- **超时**：连接 10 秒；查询不设（同 git fetch：靠取消，不靠超时 —— 慢查询本来就要等）

## 4. 连接、密码、存在哪

- 连接的配置（主机、端口、库、用户、驱动、颜色标记）存在**应用数据目录**里、按项目一份（同运行配置，「不往项目里写」）
- **密码进钥匙串**：`security add-generic-password -s lite-ide.db -a <连接 id> -w`（系统自带的命令行，不加依赖），连的时候 `find-generic-password -w` 取。
  不写进任何文件、不过 IPC 回前端
- **从 IDEA 导入**：项目里有 `.idea/dataSources.xml` 就列出来、一键导入主机 / 端口 / 库 / 用户（同运行配置从 workspace.xml 导入）。IDEA 的密码在它自己的钥匙串条目里，不去读 —— 第一次连时问你一次
- **生产库标记**：连接可以标成「生产」（标题栏那一格变红）；生产库上 UPDATE / DELETE 先弹对话框说影响几行（先 `SELECT COUNT(*)` 同条件），不带 WHERE 的直接拦下要你确认

## 5. 界面放哪（照 IDEA，连层级一起抄）

- **数据库工具窗**（侧边栏一个视图，同 Maven / Gradle 工具窗）：连接 → 库 / schema → 表 / 视图 → 列 / 索引 / 外键，懒加载，⇧⇧ 能搜表名
- **SQL 控制台**：每个连接一份 `.sql` 文件（应用数据目录里，同草稿），就是普通的编辑器标签 —— 语法高亮、多光标、本地历史全是现成的。⌘↵ 跑光标所在的那条（按 `;` 和空行分）、选中了就跑选中的
- **结果**：底部工具窗一个「数据库」页（同运行窗），一条 SQL 一个结果标签；表格用日志视图那套虚拟滚动（几十万行只画看得见的）。改单元格只在有主键时允许，改完先列出要执行的 UPDATE、点了才执行
- **历史**：每个连接执行过的 SQL（最近 1000 条，带耗时和影响行数），⌘E 那种浮层里搜

## 6. 分几步做

| 步 | 做什么 | 验收 |
|---|---|---|
| DB-1 | 边车（dbsvc + lite-db.jar）、连接管理、钥匙串、测试连接、表结构树 | db.sh：H2（内存库，脚本自己建表）连上、树里看得到表和列；MySQL / PG 本机有就连、没有记「未验」；密码不落任何文件（grep 应用数据目录） |
| DB-2 | 控制台、⌘↵、结果表格（分批取）、取消、历史 | 10 万行的表：首屏 < 300 ms、滚到底分批取；慢查询（`SELECT SLEEP(30)`）点取消 1 秒内停 |
| DB-3 | 改单元格（先预览 UPDATE）、导出、表名列名补全、生产库保护 | 导出 100 万行内存不涨；生产库不带 WHERE 的 DELETE 被拦 |
| DB-4 | 从 IDEA 的 dataSources.xml 导入、更多驱动（按 URL 认） | 拿你项目里真的 dataSources.xml 导一次（只读，不改它） |

DB-1 之前先做**第 0 步实测**（同 AI.md、IDEA.md 的规矩）：边车冷启动、常驻内存、H2 / MySQL 驱动加载时间 —— 数字不达标（第 2 节最后一段）就换路。

## 7. 和现有东西的接口

- 进程纪律：`dbsvc` 照 `lspsvc` 的形状（rust.md「起子进程的三条硬纪律」：stdin 是说话的管道，单条消息设闸，读线程不在上面答话）
- 按窗口登记：连接表用 `Owned<K, V>`，`release_window` 里收（state.rs 那条测试会卡住漏收）
- 下载：照 D10 / D11，只从 Maven Central、钉版本、核 sha256、说清大小和许可证
- 入口包：数据库工具窗、结果表格、控制台的扩展全部懒加载；入口里只多导轨上一项（并进已有的 `{#each}`）
