# 走到哪了、往哪去（2026-09-24）

## 1. 一句话结论

**定位（2026-09-24 用户定的）：取代 Sublime 的代码编辑器 —— Java、Python、前端都要用；代码智能现阶段不加码。**
这一个月实际长成的样子偏向「给 Java 后端的轻量 IDE」（git 全家桶、Java 专项跳转），这次把方向拉回初衷。
分层架构（不依赖 Tauri 的服务 crate → 薄命令层 → 可测的状态层 → 懒加载的视图）这一个月经住了考验，
**不需要推倒重来**。要调整的是三件事：

1. **定位和边界要重写** —— PLAN 里有四条前提已经不成立了（第 2 节）；
2. **四个单文件巨石到了该拆的时候** —— 不拆，后面每加一个功能都在跟它们搏斗（第 4 节）；
3. **给下一阶段补三块地基**：多窗口（天天要用）、配置文件（开源和多语言要用）、agent 会话子系统（ACP 要用）（第 6 节）。

## 3. 现在的架构，哪些要守住

```
视图层     Svelte 组件：shell / editor / git / logview / search / terminal   （重的一律懒加载）
  │
状态层     *.svelte.ts：tabs / docs / tabflow / git / project …            ← 裸 node 能测（tests/runes/）
纯函数     tree-rows / jump / diff-parse / autosave / keymap …             ← 裸 node 能测
  │
IPC        ipc/*.ts ⇄ DTO ⇄ mock-ipc.ts（浏览器桩）                         ← dto_sync.rs 卡漂移
  │
命令层     commands/（按领域分文件，DTO 在 dto.rs）：88 个命令，只解包、转错误，重活进阻塞池
  │
服务 crate logengine · gitsvc · fsservice · searchsvc · ptysvc · excludes · applog   ← 不依赖 Tauri
```

这一个月证明**值得守住**的五条，后面加任何东西都照着来：

| 守住的 | 为什么值 |
|---|---|
| 服务 crate 不依赖 Tauri | 日志引擎、git 加固、子进程上限都能脱离界面单测；这是整个项目测试密度的来源 |
| 重的东西懒加载 + CI 卡入口包 | 入口包现在 142,813 B，一个月里靠「每轮重量、说得出是谁」守住了秒开 |
| 两侧拷贝靠测试卡漂移（`dto_sync` / `menu_sync`） | 不靠自觉。桩和真实现分叉、菜单和键位表分叉，都是编译不报错的那种 bug |
| 规则写成数据 | 生成物名单、语言表、键位表、源码根判定、隐藏名单 —— 加一条是加一行，不是加一个分支 |
| 子进程纪律 | 输出设上限、杀进程组、背压、stdin 接空 —— 每一条都是踩过的坑（见 `.claude/rules/rust.md`） |

## 5. 需要拍板的

### D1 定位 —— ✅ 已定（2026-09-24）

「**取代 Sublime 的代码编辑器：Java、Python、前端都要用。看日志是它独有的强项，git 够用；代码智能现阶段不加码。**」

**现在的真实场景**（用户 2026-09-24 说的）：手上的项目都还没上线，正经的用法是**从服务器把日志拉下来看**，
以及**随手记** —— 这两件正是 Sublime 的场景。所以「看日志」不是附带功能，是和「编辑」并列的核心；草稿同理。

三点要说清，免得以后误读：

- **取代的是 Sublime 的「位置」，不是它的键位和长相。** 随手开、秒开、什么文件都敢打开、占用小 —— 这是 Sublime 的位置。
  键位和界面照 IDEA，是 2026-09-23 定的（用户的手是 IDEA 的手），两件事不冲突。
- **「一个窗口一个文件夹、同时开很多个」是真实用法**（2026-09-24 看了用户的桌面：IDEA 开着 4 个窗口，全是同一个仓库的
  不同 git 工作树 —— 有 Codex 在 `.codex/worktrees/` 里干活的那几份；VS Code 一个窗口开着前端仓库）。不是 VS Code
  那种「一个窗口里放几个根目录」。见第 6 节「多窗口」。
- **「多语言」是判据**：以后要加的能力，先问三门语言是不是都受益。只让一门受益的（比如 Maven 专用启动器、Java 专项分析）排后面，
  能换成通用形态的先换（见 D4）。

以前那几次讨论照这个判据重看：调试器 → 不做（IDE 的活）；设置 → 做配置文件（开源和多语言都需要，shell / 解释器路径各人不同）；
Maven 启动器 → 换成通用的任务运行（D4）。

### D2 代码智能 —— ✅ 已定：现阶段冻结

- 已有的 Java 专项（1,606 行）**只维护、不扩展**；TS / Python 不追平。
- 以后要加码时，**先考虑跨语言的**（LSP 按项目手动开启、或靠 agent），而不是再给某一门手写一套 ——
  手写的路子每加一门语言就是再写一遍，这和「多语言」的定位冲突。
- 为什么现在不做：jdtls 一个 JVM 就 300MB 起，冲内存预算；而且对「取代 Sublime」来说，Sublime 本来也没有语言智能。

### D4 从「Maven 启动器」改成「通用的任务运行」（待定）

按 D1 的多语言判据，只服务 Java 的启动器不合适了。换成 **Sublime 的 Build Systems 那种形态**：
项目里配几条命令（`mvn spring-boot:run`、`python main.py`、`pnpm dev`），⌘B 跑、⇧⌘B 选，**输出进日志视图** ——
着色、过滤、跟随、堆栈帧跳源码全是现成的，这正是日志强项的延伸，而且三门语言都受益。
停止时杀进程组（`mvn` 会再派生 `java`，只杀 `mvn` 端口就还占着）。命令存在项目里（`.lite-ide/tasks.json` 之类），不进全局配置。

## 6. 下一阶段要补的三块地基

### 配置文件 —— ✅ 2026-10-09（#44，设计和全过程见 [SETTINGS.md](SETTINGS.md)）

下面是原来的设想。做的时候实测改了两处：工具路径不放（终端走登录 shell 本来就对，`.zshrc` 也会盖掉配置里的值，挪到 #48 经过登录 shell 跑）；
界面缩放不做（窗口左上角的红绿灯不跟着缩）。5 个偏好进的是应用自己写的 `ui-state.json`，不是你手写的那份。

- `~/Library/Application Support/com.liteide.app/settings.json`，Rust 侧读写，文件变了热加载（`fsservice::watch` 现成）。
- 现有 5 个 localStorage 偏好迁过去；**读失败一律用默认值、不许抛**（启动路径上的规矩）。
- 菜单「打开设置」直接在编辑器里打开这个文件（Zed 的做法）。界面以后再说。
- 第一批该有的：终端用哪个 shell、三门语言的工具路径（`JAVA_HOME`、Python 解释器、Node）、界面字号缩放、代码字体（有人不要 JetBrains Mono）。
  从 Finder 启动的 .app 没有 shell 的环境变量（`LANG` 那次就是这个坑），工具路径只能靠这里给。

### agent 会话子系统（ACP）

提前把落点想好，免得做的时候临时往现有模块里塞：

```
crates/acpsvc/        新 crate，不依赖 Tauri
  - 起 agent 子进程（进程组、stdin/stdout 上的 JSON-RPC、stderr 设闸）
  - 请求 / 响应配对、取消、会话生命周期（应用退出、会话结束都要杀干净）
commands/agent.rs     薄命令层
src/lib/agent/        懒加载
  - agent.svelte.ts   会话状态（可测）
  - AgentPane.svelte  对话视图；权限请求复用 .confirm 卡片；改动审阅复用 DiffView
```

两个**这个项目里从没有过的东西**，要提前设计：

1. **反方向的 RPC**。现在所有调用都是「前端问、Rust 答」。ACP 里是 agent 问宿主「读一下这个文件」—— 而正确答案
   是**编辑器里未保存的内容**，只有前端知道。于是要有「Rust 发事件给前端 → 前端算好 → 再调一个命令把答案送回去 →
   Rust 按请求 id 交给等着的 agent」这一整条链，还要处理前端不回话的超时（ptysvc 背压那条「前端不回话时必须放弃、不能挂住」同样适用）。
2. **agent 写文件要走编辑器，不能直接写盘**。直接写盘的话，开着的标签不知道、未保存的改动被覆盖。
   应该让写入先落进 `docs` 状态（和「外部改动」同一套冲突裁决），审阅通过才存。

安全边界：写只许在项目根内；执行命令一律走权限卡片；每次授权在 `app.log` 留一行。
内存：宿主不为 agent 进程的内存负责，但**要为它的生命周期负责** —— 不能留下孤儿进程。

### 多窗口（一个窗口一个文件夹）

> **✅ 2026-10-08 做完。** 完整设计（含 #41 关窗不退出）和每一步的实测见 [MULTIWINDOW.md](MULTIWINDOW.md)。下面这张表是最初的轮廓，
> 设计时又查出几处它没列到的（关一个窗口杀掉所有终端、快照清理会误删别的项目），以那份为准。

现在只有一个窗口：`tauri.conf.json` 里一个 `main`，权限配置也只写了 `main`，Rust 发给前端的事件（菜单、文件变动、
打开文件）全是 `app.emit` 广播。要改的地方：

| | 现在 | 要变成 |
|---|---|---|
| 前端状态 | 全局单例（tabs / project / git …） | **不用改**：每个窗口是独立的 WebView，状态天然隔离 |
| 事件 | `app.emit` 广播给所有窗口 | 按目标发：菜单事件给当前聚焦的窗口；文件变动给开着那个项目的窗口 |
| 文件监听 | 一份 | 按项目根一份，没有窗口开着就关掉 |
| 打开文件夹 / `lite 路径` / Finder 双击 | 换掉当前窗口的项目根 | 这个文件夹已经开着就聚焦那个窗口，没开就开一个新窗口（IDEA 的「在新窗口中打开」） |
| 会话恢复 | 上次那一个项目 | 上次开着的**那几个窗口**，各自的项目、标签、位置 |
| 分支浮层里「打开工作树」 | 换掉当前项目根 | 在新窗口里开 —— 这正是你在 IDEA 里对 Codex 工作树的用法 |

偏好（localStorage）同源共享，本来就该共享；会话快照已经按项目存（#33 ㉓），省了一半事。

## 6½. 取代 Sublime 还缺的

照 D1 对了一遍 Sublime 用户最常用的几样：

| Sublime 的 | 我们 | 缺口 |
|---|---|---|
| 秒开、低占用、大文件 | ✅ 日志模式 1GB 0.38ms；启动 152–158MB | 大的**非日志**文件（>50MB 的 JSON / SQL dump）要能只读打开而不是拒绝 —— 待核实现状 |
| 多光标、选下一个相同的词、全选相同 | ✅ ⌘Click / ⌃G / ⌃⌘G（IDEA 键位） | —— |
| Goto Anything（⌘P 里 `@符号`、`:行`） | ✅ 2026-10-09（#43）：`文件@符号`、`文件:行:列`、单独的 `@` / `:`；没打开的文件现读现解析（Lezer，同大纲那套） | —— |
| 命令面板 | ✅ ⇧⇧ 的「操作」 | —— |
| 跨文件查找**替换** | 只有查找（⇧⌘F） | 缺。这是编辑器的基本功，三门语言都要 |
| Hot exit（不问就存、重启回来） | ✅ 草稿 + 离开就存 + 会话里带草稿 | —— |
| 构建系统（⌘B） | 无 | 见 D4 |
| 设置文件 | 无（localStorage） | 见第 6 节 |
| 同时开几个文件夹 | **只有一个窗口**（窗口名写死 `"main"`） | 缺，而且是用户天天要用的。做成「一个窗口一个文件夹」，见第 6 节 |
| 浅色主题 | 只有深色 | 开源之后会被问；优先级低 |
