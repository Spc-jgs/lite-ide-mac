# 几份日志按时间合成一条（2026-10-14）

> 状态：**做完了**。Rust 侧 `crates/logengine/src/merge.rs`（14 条测试，四种错版本各自验过红）；前端 `logview/MergeBar.svelte`、
> `logview/merge-path.ts`、`state/merge-ops.ts`；真 `.app` 验收 `scripts/accept/merge.sh` 15/15。

## 0. 一句话

网关、订单服务、库存服务各一份日志，从服务器拉下来，想看**「这一次请求在三个服务里各发生了什么」**。
原来只能一份一份开、对着时间戳来回切 —— 人在脑子里做归并。现在：文件树里多选几份 → 右键「按时间合并查看」，
一个标签里按时间交织成一条时间线，每行行首一格颜色说它来自哪份，行号栏是**那一份里的行号**（对着原文件找得到）。

这条是 DIRECTION D1 那句「看日志是独有的强项」的延伸：真实场景就是「从服务器把日志拉下来看」，而一个请求从来不只落在一份日志里。
Sublime 和 IDEA 都给不了；lnav 能做，但它是终端程序。

## 1. 用起来什么样

| | 怎么做 |
|---|---|
| 打开 | 文件树里多选（⇧ 连选 / ⌘ 点选）2–32 份 → 右键「按时间合并查看（N 份）」；或者单文件日志的过滤条上点「合并…」，选别处的文件（拉下来的日志多半在「下载」里） |
| 只看某几份 | 图例上点一份 = 只看它，再点复原（和级别胶囊同一个手感）；和级别、关键字一起筛 |
| 跨服务追一个请求 | 过滤框里输 traceId：几个服务里带它的行按时间排好 |
| 时区 / 钟不准 | 图例上每份的「±」：`+8h`、`-350ms`、`+1m30s`。改了整份重新合并 |
| 再加一份 | 图例右边「加一份…」：新开一个合并标签，原来那个关掉 |
| 跳到时间 | ⌘L 输 `14:32`：按**合并后的时间线**跳（加过偏移的，按加完之后的钟） |

单文件日志视图的一切照旧：级别着色、过滤、只看命中 / 全文、F3 跳命中、堆栈帧跳源码、折叠堆栈、会话恢复（标签和「读到哪」都回来）。

## 2. 语义：五条规矩，每条都是为了「看着对，而且真的对」

1. **从不改一份文件内部的先后。** 归并只决定「下一行从哪份取」，取的永远是那份的下一行。多线程写乱了几毫秒的日志，
   合并后还是原文件的顺序 —— 不然人拿着行号回原文件找，对不上。
2. **没时间戳的行跟着上一行走。** 堆栈帧、多行 SQL、Python 的 Traceback 沿用这份文件里上一条有时间戳的行的时间。
   于是一条报错和它的四十行堆栈在合并后仍然连在一起：键相同、来自同一份，别的文件插不进来。
3. **同一毫秒按「第几份」定先后。** 不是按到达顺序 —— 那样同一毫秒的两条记录每次合并结果都可能不一样。
4. **文件开头没时间戳的那几行（启动横幅）用这份文件第一条时间戳**，排在它第一条记录的前面，而不是整个时间线的最前面。
5. **借来的东西要说出来。** 只有时分秒的（行首裸的 `14:03:21`）借第一份带日期的那天；没有年份的（syslog）借它的年；
   图例上用一行字说「inventory 只有时分秒，按 2026-08-24 对齐」。不说的话人会以为几份日志本来就对得上。
   只有时分秒的文件**往回跳超过 12 小时算过了午夜**，往后加一天（23:59:58 之后的 00:00:01 是第二天的，不能排到当天最前）。

## 3. 怎么做的

### 归并：k 路，一个小顶堆，再加「连着吐一段」

每份一个游标，每次取「当前行时间最早」的那份吐一行 —— k 路归并。k 很小（几份），用一个小顶堆，每行 O(log k)。
**省力的地方**：取出最早那份之后，只要它的下一行还不晚于堆顶（第二早的那份），就接着吐它，不回堆。
日志是一段一段的（一条带堆栈的报错几十行、一次请求的几行），连着吐一段只做一次堆操作。

### 存什么：一行一个字节

合并的结果完全由「第 i 行来自第几份」这一串决定 —— 每份内部顺序不变，知道来源就知道是那份的第几行。
所以只存这一串（`sel`，每行 1 字节），外加每 1024 行一个**检查点**：那一刻每份文件的游标（行号 + 字节偏移）。
定位第 r 行 = 找到它前面最近的检查点，把这段 `sel` 走一遍（最多 1023 步，每步一次 memchr）。

这和单文件的稀疏行索引（`index.rs`）是同一个思路：**用一点扫描换掉大部分内存**。

| 每行存什么 | 3 份共 144MB、128 万行 | 3 份各 1GB（约 2400 万行，按比例推） |
|---|---|---|
| (文件, 行号) 两个 u64 | 19.6 MB | 约 370 MB |
| **来源 1 字节 + 每 1024 行一个检查点**（现在） | **1.28 MB**（每行 1.05 字节） | 约 25 MB |

原文件一个字节都不复制（还是那几份 mmap）。

### 首屏不等合完

每合好 6.5 万行（一块）发布一次快照，读的人拿 `Arc` 去用、不用锁 —— 同单文件索引的「后台推进 + 快照发布」。
块一旦发布就不再变。合并在后台线程里，关掉标签（`MergedLog` 析构）就叫停；改偏移是起一次新的、叫停旧的。

### 时间怎么比

`seek::ts_key` 认出来的键是「年月日时分秒毫秒」拼成的整数，不是真正的时刻：`23:59:59` 加 2 秒不会进位到第二天。
合并换成**毫秒数**（公历日期 → 1970 年以来的天数，Howard Hinnant 的 `days_from_civil`，闰年的 4 / 100 / 400 三条折成几次整除），
才能做加减（偏移、跨午夜）。不管时区：时区靠手动偏移（见第 5 节）。

### 过滤：每份各筛一遍，再沿着合并结果换行号

每份文件用它**自己的**级别表和单文件那套过滤循环（`filter::run`）各跑一遍，得到各自的命中行号；
再沿着合并结果走一遍，把「第 s 份的第 l 行」换成合并后的行号 —— 走一遍出来就是按合并顺序排好的，不用再排序。
「只看某几份」不额外扫：那几份标成「整份都算」或「整份不算」，不把几百万个行号真的列出来。

### 和单文件共用一套命令

`AppState` 多一张 `merges` 表，和日志文件共用句柄计数器。`log_stat` / `log_lines` / `log_filter` / `log_seek_time` /
`log_lines_filtered` / `log_filter_map` 按句柄先查合并表、再查文件表 —— **前端的日志视图分不出、也不用分**。
多出来的只有三条：`open_merged`、`merge_rows`（一段行各自来自哪份、是那份第几行）、`merge_set_offsets`。

## 4. 实测（M 系列 Mac，`--release`，`examples/bench_merge.rs`）

三份 `gen_log` 造的 Java 日志，64 + 48 + 32 = 144MB、128.6 万行：

| | 数 |
|---|---|
| 打开（三份 mmap + 各扫前 1MB） | 1.05 ms |
| 首屏出现（第一块合好） | 3.66 ms |
| 合完 | 28–30 ms 缓存热（约 5 GB/s）；刚重编完、页缓存冷的那次 104 ms |
| 合并索引内存 | 1.28 MB |
| 随机取一行（最坏走 1023 步） | 0.0039 ms |
| 连续取 1000 行 | 0.015 ms |
| 按时间跳 | 0.13 ms |
| 过滤一个异常名（含等三份的级别扫描跑完） | 58 ms → 24 条，和 `grep -c` 对得上 |
| 只看第 1 份（不扫，整份标「都算」） | 2.5 ms |

没量 1GB × 3：那要往盘上写 3GB，不值得为它把机器跑满（memory 里那条）。按比例推，合完约 0.6 秒，期间首屏照样 4ms 出来。

## 5. 取舍和没做的

| | 为什么 |
|---|---|
| **不猜时区** | `Z`、`+0800` 认得出来，但「没写时区的那份是哪个时区」认不出来。猜错比不对齐更糟：看着对齐了，其实差 8 小时。手动偏移一次说清 |
| **偏移不跨重启**（v1） | 标签按 `path` 认，偏移放进 path 会让「同样几份文件」变成两个标签。图例上没有偏移就是没有，看得见 |
| **不跟 tail**（v1） | 拉下来的日志是静的。跟的话每份长了都要接着归并，「已经发布的块不再变」这条就得改 —— 等真有人要看「几个正在跑的服务的实时合并」再做 |
| **编码按第一份认** | 几份多半出自同一套部署。真不一样的，状态栏那格照样能改 |
| **最多 32 份** | 图例上一份一个颜色，十几份就分不清了；「只看哪几份」是一个 u32 位掩码 |
| **文件树多选不看扩展名** | `.out`、`catalina.2026-08-24`、没后缀的都可能是日志。认不出时间戳的那份图例上会说（整份排在最前），比在菜单上猜「像不像日志」诚实 |
| 跟着 traceId 走、模板归类（Drain）、两份日志按模板比较 | 下一步：都踩在这一层上（归并 + 每份各自的过滤）。见 2026-10-14 那次头脑风暴（JOURNAL） |

- `cargo test -p logengine merge`：14 条。四种「真会写出来的错」各自验过红：没时间戳的行不沿用上一条、同键时不比第几份、不处理跨午夜、检查点记在吐完那行之后

- `scripts/accept/merge.sh`（真 `.app`、测试通道）：15 条，含两份各 10MB 的跨块定位、会话恢复、关标签收句柄、不抢焦点
