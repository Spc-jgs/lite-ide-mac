# 跨文件查找替换（issue #42）—— 设计

> 状态：**已拍板、第 0 步已实测**（2026-10-09，Q1–Q5 都按建议）。第 2½ 节是拍板前补的业内调研，第 8 节是实测结果，第 12 节是三处硬伤的解法 —— 前面各节已经按它们改过，以正文为准。

## 0. 一句话

在 ⇧⌘F 的浮层上加一行「替换为」，先列出每一处「改前 / 改后」，勾选后才写；写的时候**每个文件都重新读一遍、核对没变过**，
开着的文件改进编辑器而不是盘上，整次替换能撤销。**匹配只有一个实现**（Rust），预览和执行用的是同一个函数。

## 1. 现状

| 有 | 在哪 |
|---|---|
| ⇧⌘F 只能查找，结果最多 60 条 | `QuickSearch.svelte` 的「内容」范围 → `grep_project` → `searchsvc::grep` |
| 文件内替换 ⌘R | CM6 的查找面板 |
| 保存语义：权限位、软链写真身、硬链接原地写、编码 / BOM / 换行符原样写回 | `fsservice::write_text_as` |
| 外部改动：干净的标签静默重读，脏的标为冲突让人裁决 | `docs.checkExternalChanges` |

## 2. 摸底时撞见的：⇧⌘F 的两条路语义不一样（原来就有）

`grep` 装了 rg 走 rg（`rg -e <词> --smart-case`），没装走内置实现（`memmem` 字面量、区分大小写）。2026-10-09 实测：

| 搜 | 装了 rg | 没装 rg |
|---|---|---|
| `a.b` | 命中 `axb` **和** `a.b`（被当成了正则） | 只命中 `a.b` |
| `foo` | 也命中 `Foo`（smart-case：全小写就不分大小写） | 只命中 `foo` |

`两条实现路径结果必须一致` 那条测试只用了 `needle` —— 没有正则字符、全小写，所以测不出来。对**查找**这只是结果略有出入；
对**替换**就是「预览给你看的那一批」和「真正改掉的那一批」可能不是同一批。所以这一轮要一起修（第 9 节 Q1）。

## 2½. 业内怎么做、痛在哪（2026-10-09 调研）

看了 VS Code、IntelliJ、Sublime、Zed、Visual Studio、Notepad++ 的做法和用户的抱怨。**大家栽的坑高度集中在四处**，
每一处都对应到下面的一条设计：

| 痛点 | 谁、什么样 | 我们怎么办 |
|---|---|---|
| **替换完留下一堆没存的标签** | Sublime：Find in Files 替换会把每个受影响的文件开成没保存的标签；论坛里有人改了约 5000 个文件，一个个弹「要不要保存」，最后强退、改动全丢；GitHub 上有 2000 个标签逐个问保存、应用卡死的报告。Zed 的 Replace in Project 初版作者自己写着「关掉结果页时对几百个改过的文件逐个问保存」，想要一个「全部保存 / 全部丢弃」 | **关着的文件直接写盘，不开标签**；开着的干净标签改完就存（Q4）。一次替换结束时，盘上的状态就是你在预览里勾的那样，不留一屏待处理的标签 |
| **撤销只撤得了一个文件** | Visual Studio 文档写明：只有替换后仍然开着的文件能撤销，没开的没有撤销。Notepad++ 有人全局替换后按 ⌘Z 只撤了眼前那一份。Cursor 论坛有人误把匹配替换成空、撤不回来，只能翻 diff。IntelliJ 的多文件撤销要靠所有改动同在一个 command 里（插件开发者问答），大家实际的兜底是 git 回滚 / Local History | **整次替换一条撤销**（第 6 节），而且撤之前核对「此刻还是替换后的样子」—— 被你又改过的跳过并说明，不盲写 |
| **预览和实际改的不是同一份** | Sublime：开着的文件搜的是内存里那份，和盘上对不上，结果「过期」。Zed 修过一个「用过期的查询执行 Replace All，第一次按什么都没发生」。写编辑工具的人总结：替换前从盘上重读，别信缓冲区 | **执行时每个文件重读、比对预览时的指纹**，变了就跳过（第 5 节）；开着的文件预览和执行都用编辑器里那份 —— 用户看到的就是被改的 |
| **预览看不全、排除要换个窗口** | IntelliJ 的 Replace in Path 浮层只预览前 100 条，要逐条排除得点「Open in Find Window」到另一个工具窗里做 | 浮层里就能逐处 / 逐文件勾掉，上限 5000（第 7 节）；**按文件分组、可折叠，列表虚拟化**（只画看得见的几十行） |

另外三条小的：
- **软链让同一处出现多次**：VS Code 默认跟随软链，有人一个定义搜出三份，还有软链目录让 rg 跑满 CPU 的报告 —— 我们不跟软链目录，软链文件按真实路径去重（第 4 节）
- **换行符被悄悄改掉**：Cursor 的编辑工具把 CRLF 改成 LF，整个文件在 git 里全红 —— 我们走 `write_text_as`，换行符和编码原样写回
- **「全部替换」太容易误触**：Cursor 论坛有人抱怨一次误点、没有确认、没有撤销。我们**不加确认框，靠撤销兜底**：按钮上写清「替换 5 处 · 3 个文件」，
  做完是一张带「撤销」的卡片 —— 确认框点多了人会条件反射地点「是」，撤销才是真的退路

**大小写**：smart-case（全小写就不分大小写）是 rg 的选项；VS Code 的项目搜索把它做成一个可选设置，界面上主要靠「区分大小写」开关；
IntelliJ 是显式的 Match case。Q1 照显式开关走。

## 3. 匹配：一个实现，三个开关

- **三个开关**：区分大小写（Aa）、整词（W）、正则（.*），⇧⌘F 和替换共用；默认三个都关（IDEA 的默认）。
  把开关显式传下去，**不再用 smart-case**：它让「foo」和「Foo」的语义不一样，而界面上看不出来。
- **Rust 侧一个 `Matcher`**（`searchsvc`），字面量也编成正则（转义后）。查找、替换预览、替换执行全走它。
- **整词按 rg 的意思算，不套 `\b…\b`**（第 0 步实测改的）：「整词」= 命中的前一个和后一个字符都不是词字符。
  `\b-x\b` 在 `a -x b` 里配不上、在 `foo-x` 里反而配上了 —— 和人想的正相反，rg 的 `-w` 是对的。`regex` 没有前后断言，
  所以先按原样找候选、再查两边的字符，不合格就从下一个位置接着找。**中文字算词字符**：整词模式在一串中文里配不到，界面上写一句。
- **替换不用 rg**（第 0 步实测改的）：5 万个小文件上 rg 光列出「哪些文件有」就要约 600ms，而我们自己 4 线程读完全部再逐个算位置约 400ms ——
  瓶颈在开文件读文件，不在匹配。所以替换走 `list_files_capped`（⌘P 那份索引，同一套跳过规则）+ `Matcher`，4 线程扫，一条路，没有「两条路对不上」。
- **⇧⌘F 照旧用 rg**（要的是前 60 条、够数就掐掉，那是 rg 的长处），但开关显式翻译成 `-F` / `-i` / `-s`，**不传 `-w`**，
  整词由 `Matcher` 在 rg 给回的行上再过一遍；没装 rg 的那条内置实现换成 `Matcher`。
- **`$1` 只在正则模式下生效**；字面量模式下替换串原样写（`regex` 的 `NoExpand`）。

## 4. 预览

```
[ 搜索词              ] [Aa][W][.*]
[ 替换为              ]               ← ⇧⌘R 打开时带这一行；⇧⌘F 打开时点「替换」展开
☑ OrderService.java                3 处
   ☑ 42  private final OrderClient client;   →  private final OrderGateway client;
   ☐ 57  …
☑ api/AdminController.java         2 处
                              [替换选中的 5 处]
```

- 每处一行「改前 → 改后」（改的那一段高亮），可以逐处、按文件勾选。按文件分组、可折叠，列表虚拟化。
- **浮层关掉不丢活**：替换的查询、替换串、取消勾选的那几处记在 store 里，⇧⌘R 再开回到原样（重新扫一遍，没变的勾选状态保留）。
  IntelliJ 靠「Open in Find Window」换到一个不会关的窗口来解决这件事；我们的浮层一 Esc 就关，不记的话误按一下前功尽弃。
- **改替换串不重新扫盘**：Rust 侧按（根目录、查询、开关）记住上一次的匹配，替换串变了只重算「改后」。第 0 步量过：5 万个文件一次完整预览约 0.45s，这层要做。
- **开着的标签用编辑器里的文本做预览**（可能有没存的改动），不读盘 —— 前端把这几份文本交给 Rust，用同一个 `Matcher` 算。
- 同一个真实文件只出现一次：⇧⌘F 现在会同时搜到软链和它指向的文件（#19），**按规范化路径去重**，
  不然 `link.txt` 和 `real/config.txt` 会各替换一次。硬链接同理（按 `dev + ino`）。
- 跳过的写出来：二进制、超过 8MB、解码有损（`lossy`：带着它写回会把解不出的字节永久换成 U+FFFD）、生成物目录 ——
  预览顶上一行「跳过了 N 个文件：…」，不静默。

## 5. 执行

按文件分三类，走的路不一样，但**都进同一份替换日志**（12.1），撤销一视同仁：

| 文件 | 怎么改 | 落盘 |
|---|---|---|
| 关着的 | Rust 两段提交（12.2）：准备段重读、核对预览时的指纹、算新内容、写临时文件；提交段逐个 rename | 是 |
| 开着、没有未保存改动的 | 盘上那份和编辑器里的一样，所以**和关着的一起走两段提交**；提交完 Rust 给回每一处的位置（UTF-16 偏移）和替换串，前端在编辑器里 dispatch 成一笔事务、更新文件指纹（不触发「外部改动」重读）—— 编辑器里 ⌘Z 也撤得回（Q4） | 是 |
| 开着、有未保存改动的 | 预览用的就是编辑器里的文本；执行时前端先核对编辑器文本还是预览时那份，再 dispatch。**只改编辑器、不保存**，圆点还在 —— 用户的没存改动和这次替换一起，等他自己决定（issue 验收第 2 条）。日志里记一条「只在编辑器里」：改前的编辑器文本、改后的指纹 | 否 |

细节：

1. **核对指纹**（长度 + 哈希），变了就把这个文件剔出去，执行前列给人看「预览之后被改过：…」—— 不在一份没给人看过的内容上动手
2. 只替换勾选的那几处，**按「第几处」认**，不按行号（前面的替换会让后面的行列挪位）
3. 写回走 `fsservice` 拆出来的准备 / 提交两半（12.2）：编码 / BOM / 换行符照原样，权限位、软链、硬链接那三条保存语义都在这条路上，不另写
4. 「只在编辑器里」的那类，崩溃时改动本来就没落盘，中断恢复不管它们（会话恢复里的草稿照常）

## 6. 撤销

一次替换记成一条「替换日志」，**先落盘再动文件**（12.1）：每个文件改前的全文、改后的指纹。只留**最近一次**，应用重启之后也能撤。

「撤销这次替换」逐个文件：**此刻的内容还等于「改后」才写回「改前」**，否则跳过并说明（替换之后你又改过它）。
**走哪条路按撤销那一刻算，不按替换那一刻**：替换后你可能关掉了那个标签、也可能新开了一个 ——
此刻开着就比编辑器里的文本、改编辑器，没开就比盘上的、写盘（也走两段提交）。界面上是一张卡片：「已替换 3 个文件 12 处 · 撤销」，
下一次替换、或者你点掉卡片它就没了；应用重启后在那个项目的窗口里再出现一次。
「只在编辑器里」的那类，如果你后来没存就关了标签，盘上那份根本没被替换过 —— 此刻内容不等于「改后」，照规则跳过并说明。

## 7. 上限

| | 上限 | 超了 |
|---|---|---|
| 命中 | 5,000 处 | 预览照常列前 5,000，**「替换」按钮不可点**，写明「命中太多，缩小范围再替换」—— 不替换一半 |
| 单个文件 | 8MB | 跳过并列出（同搜索） |
| 替换日志（12.1） | 64MB 的改前全文 | 超了这一次就不给撤销，执行前就说（「这次改动太大，撤销不了，仍然替换？」） |

## 8. 第 0 步：实测结果（2026-10-09）

**1. `regex` 和 rg 的语义**（同一份语料，rg 15.2 对 `regex` 1.13.1，逐行比命中）：

| | 结果 |
|---|---|
| 字面量带元字符 `a.b` `foo(bar)` `$x` `\d`（转义后） | 一致 |
| 不分大小写：`foo`、德文 ß、希腊语 σ/ς、土耳其 İ、开尔文符号 K | **一致**（两边都是 Unicode 简单大小写折叠；ß 不折成 SS，两边都不） |
| 整词：`订单` `order` `order_id` `foo` | 一致 |
| 整词：`-x` `.foo`（以非词字符开头或结尾） | **不一致**：rg 命中 `a -x b`、`\b…\b` 命中 `foo-x` —— 改设计（第 3 节），按 rg 的意思实现 |
| 整词 `订单` 在 `查询订单状态` 里 | 两边都**不命中**：中文字是词字符。界面上说一句 |

**2. 编辑器里一笔改很多处**（1 万行、72 万字符的文档，`EditorState.update` 一笔事务）：100 处 2.7ms、500 处 2.5ms、2000 处 3.8ms。
开着的标签走编辑器没有性能问题（视图只画看得见的那几十行）。

**3. 5 万个文件的仓库**（合成，每个约 1KB，热缓存，M 系列 18 核）：

| 做法 | 耗时 |
|---|---|
| `list_files_capped` 列出 5 万个 | 37–57ms |
| rg `-l` 预筛（命中 1% / 50% 的文件） | 约 600ms / 约 590ms |
| 预筛之后读命中的文件、算出每一处的行和 UTF-16 列 | 500 个文件 8–18ms；2.5 万个文件 350–390ms |
| 不预筛，自己读全部 5 万个：1 线程 / 4 线程 / 8 线程 | 690–760ms / **400–420ms** / 520–560ms（8 线程抢文件系统，反而慢） |

结论：替换不用 rg（第 3 节），4 线程。一次完整预览约 0.45s —— 一次可以，**每改一个字都重扫不行**，所以第 4 节「改替换串不重新扫盘」那层缓存要做。
不边扫边推结果：0.45s 等得起，边扫边推要处理「列表在你勾的时候还在变」。

## 9. 拍板记录（2026-10-09，五条都按建议）

下面是拍板时的原文，留着看当时为什么这么选。

**Q1 匹配语义统一，⇧⌘F 的行为会变。** 去掉 smart-case 和「装了 rg 才是正则」，改成显式的三个开关，默认字面量、不分大小写。
⇧⌘F 搜 `a.b` 不再命中 `axb`、搜 `Foo` 会命中 `foo`（之前装了 rg 时不命中）。**建议：统一**（修第 2 节那个不一致，替换的前提）。

**Q2 加依赖：`searchsvc` 直接依赖 `regex`。** 它已经在依赖树里（`logengine` 用它，`Cargo.lock` 里只有一份 1.13.1），
二进制不变大，但 AGENTS.md「加依赖先问」。**建议：加。** 不加就要自己写正则引擎，或者只支持字面量（替换的 `$1` 也就没了）。

**Q3 界面放哪。** (a) **IDEA 的做法**：⇧⌘F 那个浮层加「替换为」一行和勾选列表，⇧⌘R 直接带替换行打开（IDEA 的 Replace in Path 就是这个键，
我们的 keymap 里空着）；(b) VS Code 的做法：侧边栏一个常驻的搜索视图。**建议 (a)**：键位和层级跟 IDEA（键位那条记忆），
浮层已经有了；缺点是浮层关掉预览就没了 —— 但替换本来就是「看一眼、勾一下、执行」一口气做完的事。

**Q4 开着的干净标签：替换后要不要自动保存。** 建议**存**（第 5 节）：不然「关着的文件改到了盘上、开着的没有」，
同一次替换两种结果，用户要挨个标签去按 ⌘S 才知道哪些真落盘了。脏的标签不存（那是用户自己的未完成工作）。

**Q5 撤销只留最近一次、只在这个窗口里。** 建议**是**：多级撤销要处理「撤第二次之前第一次的文件又被改了」的交错，
收益小、坑多。

> 补（12.1 改的）：替换日志落盘之后，撤销**跨重启**也在；仍然只留最近一次，整个应用一份 —— 在另一个窗口里再替换一次，上一次的撤销就没了，卡片上写明是哪个项目的。

## 11. 验收（issue #42 那四条，加四条）

1. 三个文件里各有两处 `OrderClient`，替换成 `OrderGateway`：预览 6 处，取消勾 1 处，执行后改 5 处
2. 其中一个文件开着且有未保存改动：替换进了编辑器、圆点还在，盘上那份没被覆盖
3. 被替换的脚本文件执行权限还在
4. 「撤销这次替换」之后三个文件都回到原样
5. （加）软链和它指向的文件都在结果里时，只替换一次
6. （加）预览之后在外面改了其中一个文件：执行时它被跳过并说明，其余照常
7. （加）替换完 ⌘Q 再打开：「撤销上次的替换」卡片还在，点了三个文件回到原样（12.1）
8. （加）`@Autowired\n    private` 这种跨行的词：预览标「跨 2 行」，替换后 CRLF 文件的换行符没变（12.3）

## 12. 三处硬伤和它们的解法（2026-10-09 补；都在 #42 里做完，不留到以后）

初稿把这三处写成「还不满意的地方」。不满意不能只是记着 —— 每一处都要有解，排进第 10 节的步骤，**#42 做完它们才关**。

### 12.1 撤销记录只在内存里 → 先落盘、再动文件（预写日志）

**问题**：替换完应用崩了（或者被 ⌘Q 掉、机器断电），撤销跟着内存一起没了，只剩 git —— 而不在 git 里的文件、没提交的改动，git 也救不回来。

**解法**：动任何一个文件**之前**，先在应用数据目录写一份「替换日志」并 fsync：

```
Application Support/<id>/replace-journal/
  manifest.json   根目录、时间、状态（准备中 / 提交中 / 已完成 / 已撤销）、每个文件：路径、编码 / BOM / 换行符、改前与改后的指纹
  before/0001     每个文件改前的全文（原样的字节，不是解码后的文本 —— 撤销要一个字节不差地写回去）
```

- 日志里只存**改前**的全文；「改后」只存指纹（长度 + 哈希）—— 撤销时核对「此刻还是改后的样子」只需要指纹，体积省一半
- **只留最近一次**：新的替换开始时删掉上一份。用户点「撤销」或者关掉那张卡片也删
- 启动时发现有一份「已完成」的日志：照常给「上次的替换可以撤销」卡片（应用重启了也能撤）
- 体积上限 64MB（第 7 节）。超了**执行前就说**「这次改动太大，撤销和中断恢复都做不了，仍然替换？」—— 这是唯一一处要确认的地方

**排除的路**：存在 localStorage（WebKit 的那份，大小有限、和窗口绑着，而替换是 Rust 做的）；只存改后的 diff（撤销要反向打补丁，
补丁打歪了就是第二次事故，存全文最笨也最稳）。

### 12.2 多文件写不是原子的 → 两段提交 + 日志兜底

**问题**：改到第 7 个文件时失败（权限、盘满、文件被锁），前 6 个已经改了、后面的没改 —— 一个「改了一半」的仓库，人得自己去分哪些改了。

**先说清楚做不到什么**：POSIX 文件系统没有跨文件的事务，「多个文件要么全换要么全不换」在系统层面就不存在。能做到的是：
**常见的失败一个文件都不动；罕见的中途中断（崩溃、断电）能在下次启动时恢复成一致的状态。** 这是数据库在同一个约束下的标准答案（预写日志 + 两段提交），
git 自己改工作区也是这个思路（先写对象，最后才动 index）。

**解法**：

1. **准备段（不碰任何原文件）**：每个文件重读、核对指纹、算出新内容、写成同目录下的临时文件并 fsync、抄好权限。
   核对不过的（预览之后被改过）**在这一段就剔出去**，执行前列给人看。准备段任何一个失败（盘满、目录不可写）→ 删掉全部临时文件，**一个原文件都没动**
2. 写日志（12.1），状态记成「提交中」，fsync
3. **提交段**：逐个 `rename` 临时文件盖上原文件。同目录 rename 不经过数据拷贝，几乎不会失败；这一段的窗口是毫秒级
4. 日志状态改成「已完成」

**中途中断**（第 3 步里崩了）：下次启动看到「提交中」的日志 → 一张卡片「上次的替换中途中断：已改 6 个、未改 9 个」，
默认动作是**全部退回改前**（按日志里的改前全文，只退指纹还是「改后」的那些），另一个选项是保留现状；顺手清掉残留的临时文件。

**硬链接是例外**：它只能原地覆写（rename 会把它从链接组里摘出去，`fsservice` 那条保存语义），原地覆写没有「准备好再一下子换上」这回事。
它们放在提交段的**最后**写，崩在它们中间的话由日志恢复。如实写在这儿：硬链接文件的「一致」靠的是恢复，不是原子。

**要改 `fsservice`**：现在的 `write_bytes` 是「写临时文件 + rename」一口气做完的，拆成 `prepare`（解软链、写临时文件、fsync、抄权限）和
`commit`（rename 或原地覆写）两半，**普通保存继续走「两半连着调」**，三条保存语义的测试一条不改照样要绿。

### 12.3 正则不跨行 → 跨行的命中照样找、照样画

**问题**：想把 `@Autowired\n    private` 换成别的、或者删掉一个三行的注释块 —— 跨行替换正是「跨文件查找替换」最值钱的用法之一，挡掉就是砍掉一块功能。

**解法**：

- `Matcher` 本来就在整份文本上匹配（不是逐行），`\n` 天然能用。读进来的内容换行已经统一成 `\n`（`read_text` 那一层），
  所以 CRLF 的文件里写 `\n` 一样命中，写回时换行符照原样恢复（单测里要有一条 CRLF 文件里的跨行替换）
- `^` `$` 开多行模式（`(?m)`）：按行首行尾算，和人在编辑器里的直觉、和 rg 一致；`.` 不跨行（默认），要跨行写 `(?s)` 或 `[\s\S]`
- **预览怎么画**：命中跨行时，那一行显示首行 + 一个「跨 3 行」的标记，展开是改前 / 改后两块完整的片段（等宽、保留缩进）。列表里每处仍然一行高，不让一个大块把列表撑乱
- **⇧⌘F 也要认**：词里有 `\n` 时给 rg 加 `-U`（多行模式）；不加的话 rg 直接报错「不许有字面的 \n」，界面上是一条看不懂的错误
- 上限另算：单处命中超过 200 行的，预览里只显示前后各 20 行（中间折叠），执行不受影响

**放在第 5 步**（主体做完之后），但 #42 不做完它不关。

## 12½. 第 2 步落地时改的（2026-10-09）

- **换行符混用的文件跳过**（`Why::MixedEol`）：写回去会被统一成 LF —— 编辑器里手动保存时状态栏会说，批量替换里悄悄改掉就是 2½ 节里 Cursor 被骂的那个坑
- **只在有命中时才说「跳过」**：有损、混用换行符的文件，没命中就不列（列了是噪音）；二进制只给个数不列名字；超过 8MB 的如实列「没有看」
- **去重只对有命中的文件取身份**：5 万个文件每个 stat 一次是几百毫秒，有命中的通常几十个。同一个文件留哪条路径：编辑器里开着的 > 不是软链的 > 排在前面的
- **提交段在运行中失败（不是崩溃）当场退回**：改前的字节就在内存里，不用等下次启动；只有进程真没了才走启动时的恢复卡片
- **撤销也走准备 / 提交**：撤到一半崩了，日志还在、状态还是「完成」，再撤一次 —— 已经退回去的此刻不等于「改后」，会被跳过，剩下的接着退
- **准备中**状态在准备段之前就写进日志：准备到一半崩了，下次启动知道去哪儿收拾临时文件（日志只记目标文件，临时文件名可以推出来，`fsservice::tmp_path_for`）
- **指纹**用自己写的 FNV-1a 64，不用 `DefaultHasher`：后者不保证跨 Rust 版本一致，而日志要跨升级读回来

## 12¾. 第 3 步落地时改的（2026-10-09）

- **替换是一个单独的浮层（`ReplacePanel`），不是 ⇧⌘F 浮层里的一个模式**：骨架一样（输入、三个开关、分组结果、脚栏），
  但数据来源不同（替换要全部命中、要扫描缓存，⇧⌘F 只要前 60 条）。塞进同一个组件，两套数据流挤在一个 500 行的文件里。
  从 ⇧⌘F 过去：脚栏写着 ⇧⌘R，按下去带着当前的词切过来
- **点命中那一行是勾选，不是跳过去**：替换浮层里的主动作是「挑哪些改」；跳到那一处看上下文以后再加（一行里已经带着前后文）
- **开着的标签怎么跟上**：干净的走「外部改动重读」那条路（`settled` + `savedTick`，已挂载的编辑器换成一笔事务，⌘Z 撤得回），
  **顺手更新文件指纹** —— 不然窗口下次拿焦点时会再被当成外部改动重读一遍、还弹一句「已被外部修改」；
  有未保存改动的，改动落在编辑器的实时文本上、作为草稿交回去（`stashed`），没存的那几行和圆点都还在
- **撤销卡片只在那个项目的窗口里出**；点撤销前先确认日志还是那一次（别的窗口可能又替换过，日志整个应用一份）

## 13. 这一轮明确不做

- 多级撤销、跨窗口撤销（Q5）
- 保留大小写的替换（`foo→bar` 时 `Foo→Bar`）：IDEA 有，用得少，以后单独加
- 在文件名上替换（批量改名）
- 替换生成物目录、被 git 忽略的文件 —— 和搜索同一个范围
