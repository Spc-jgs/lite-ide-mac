# 跨文件查找替换（issue #42）—— 设计

> 状态：**已拍板**（2026-10-09，Q1–Q5 都按建议），第 2½ 节是拍板前补的业内调研，几处设计跟着改了。下一步第 0 步实测。

## 0. 一句话

在 ⇧⌘F 的浮层上加一行「替换为」，先列出每一处「改前 / 改后」，勾选后才写；写的时候**每个文件都重新读一遍、核对没变过**，
开着的文件改进编辑器而不是盘上，整次替换能撤销。**匹配只有一个实现**（Rust），预览和执行用的是同一个函数。

## 1. 现状

| 有 | 在哪 |
|---|---|
| ⇧⌘F 只能查找，结果最多 60 条 | `QuickSearch.svelte` 的「内容」范围 → `grep_project` → `searchsvc::grep` |
| 文件内替换 ⌘R | CM6 的查找面板 |
| 保存语义：权限位、软链写真身、硬链接原地写、编码 / BOM / 换行符原样写回 | `fsservice::write_text_as` |
| 外部改动：干净的标签静默重读，脏的标为冲突让人裁决 | `docs.checkExternalChanges` |

## 2. 摸底时撞见的：⇧⌘F 的两条路语义不一样（原来就有）

`grep` 装了 rg 走 rg（`rg -e <词> --smart-case`），没装走内置实现（`memmem` 字面量、区分大小写）。2026-10-09 实测：

| 搜 | 装了 rg | 没装 rg |
|---|---|---|
| `a.b` | 命中 `axb` **和** `a.b`（被当成了正则） | 只命中 `a.b` |
| `foo` | 也命中 `Foo`（smart-case：全小写就不分大小写） | 只命中 `foo` |

`两条实现路径结果必须一致` 那条测试只用了 `needle` —— 没有正则字符、全小写，所以测不出来。对**查找**这只是结果略有出入；
对**替换**就是「预览给你看的那一批」和「真正改掉的那一批」可能不是同一批。所以这一轮要一起修（第 9 节 Q1）。

## 2½. 业内怎么做、痛在哪（2026-10-09 调研）

看了 VS Code、IntelliJ、Sublime、Zed、Visual Studio、Notepad++ 的做法和用户的抱怨。**大家栽的坑高度集中在四处**，
每一处都对应到下面的一条设计：

| 痛点 | 谁、什么样 | 我们怎么办 |
|---|---|---|
| **替换完留下一堆没存的标签** | Sublime：Find in Files 替换会把每个受影响的文件开成没保存的标签；论坛里有人改了约 5000 个文件，一个个弹「要不要保存」，最后强退、改动全丢；GitHub 上有 2000 个标签逐个问保存、应用卡死的报告。Zed 的 Replace in Project 初版作者自己写着「关掉结果页时对几百个改过的文件逐个问保存」，想要一个「全部保存 / 全部丢弃」 | **关着的文件直接写盘，不开标签**；开着的干净标签改完就存（Q4）。一次替换结束时，盘上的状态就是你在预览里勾的那样，不留一屏待处理的标签 |
| **撤销只撤得了一个文件** | Visual Studio 文档写明：只有替换后仍然开着的文件能撤销，没开的没有撤销。Notepad++ 有人全局替换后按 ⌘Z 只撤了眼前那一份。Cursor 论坛有人误把匹配替换成空、撤不回来，只能翻 diff。IntelliJ 的多文件撤销要靠所有改动同在一个 command 里（插件开发者问答），大家实际的兜底是 git 回滚 / Local History | **整次替换一条撤销**（第 6 节），而且撤之前核对「此刻还是替换后的样子」—— 被你又改过的跳过并说明，不盲写 |
| **预览和实际改的不是同一份** | Sublime：开着的文件搜的是内存里那份，和盘上对不上，结果「过期」。Zed 修过一个「用过期的查询执行 Replace All，第一次按什么都没发生」。写编辑工具的人总结：替换前从盘上重读，别信缓冲区 | **执行时每个文件重读、比对预览时的指纹**，变了就跳过（第 5 节）；开着的文件预览和执行都用编辑器里那份 —— 用户看到的就是被改的 |
| **预览看不全、排除要换个窗口** | IntelliJ 的 Replace in Path 浮层只预览前 100 条，要逐条排除得点「Open in Find Window」到另一个工具窗里做 | 浮层里就能逐处 / 逐文件勾掉，上限 5000（第 7 节）；**按文件分组、可折叠，列表虚拟化**（只画看得见的几十行） |

另外三条小的：
- **软链让同一处出现多次**：VS Code 默认跟随软链，有人一个定义搜出三份，还有软链目录让 rg 跑满 CPU 的报告 —— 我们不跟软链目录，软链文件按真实路径去重（第 4 节）
- **换行符被悄悄改掉**：Cursor 的编辑工具把 CRLF 改成 LF，整个文件在 git 里全红 —— 我们走 `write_text_as`，换行符和编码原样写回
- **「全部替换」太容易误触**：Cursor 论坛有人抱怨一次误点、没有确认、没有撤销。我们**不加确认框，靠撤销兜底**：按钮上写清「替换 5 处 · 3 个文件」，
  做完是一张带「撤销」的卡片 —— 确认框点多了人会条件反射地点「是」，撤销才是真的退路

**大小写**：smart-case（全小写就不分大小写）是 rg 的选项；VS Code 的项目搜索把它做成一个可选设置，界面上主要靠「区分大小写」开关；
IntelliJ 是显式的 Match case。Q1 照显式开关走。

## 3. 匹配：一个实现，三个开关

- **三个开关**：区分大小写（Aa）、整词（W）、正则（.*），⇧⌘F 和替换共用；默认三个都关（IDEA 的默认）。
  把开关显式传下去，**不再用 smart-case**：它让「foo」和「Foo」的语义不一样，而界面上看不出来。
- **Rust 侧一个 `Matcher`**（`searchsvc`），字面量也编成正则（转义后），整词套 `\b…\b`。查找、替换预览、替换执行全走它。
- **rg 只当「哪些文件可能有」的预筛**：把同一组开关翻译成 rg 的参数（`-F` / `-i` / `-w`），拿到文件名列表，
  每个文件再由 `Matcher` 自己扫一遍算位置。rg 的默认引擎和 `regex` crate 用的是同一套语法（都建在 `regex-syntax` 上，第 0 步实测确认）；就算预筛多给了文件，
  也只是多扫一份，不会多改 —— **改哪里只由 `Matcher` 说了算**。
- **`$1` 只在正则模式下生效**；字面量模式下替换串原样写（`regex` 的 `NoExpand`）。

## 4. 预览

```
[ 搜索词              ] [Aa][W][.*]
[ 替换为              ]               ← ⇧⌘R 打开时带这一行；⇧⌘F 打开时点「替换」展开
☑ OrderService.java                3 处
   ☑ 42  private final OrderClient client;   →  private final OrderGateway client;
   ☐ 57  …
☑ api/AdminController.java         2 处
                              [替换选中的 5 处]
```

- 每处一行「改前 → 改后」（改的那一段高亮），可以逐处、按文件勾选。按文件分组、可折叠，列表虚拟化。
- **浮层关掉不丢活**：替换的查询、替换串、取消勾选的那几处记在 store 里，⇧⌘R 再开回到原样（重新扫一遍，没变的勾选状态保留）。
  IntelliJ 靠「Open in Find Window」换到一个不会关的窗口来解决这件事；我们的浮层一 Esc 就关，不记的话误按一下前功尽弃。
- **改替换串不重新扫盘**：Rust 侧按（根目录、查询、开关）记住上一次的匹配，替换串变了只重算「改后」。第 0 步量一下要不要这层。
- **开着的标签用编辑器里的文本做预览**（可能有没存的改动），不读盘 —— 前端把这几份文本交给 Rust，用同一个 `Matcher` 算。
- 同一个真实文件只出现一次：⇧⌘F 现在会同时搜到软链和它指向的文件（#19），**按规范化路径去重**，
  不然 `link.txt` 和 `real/config.txt` 会各替换一次。硬链接同理（按 `dev + ino`）。
- 跳过的写出来：二进制、超过 8MB、解码有损（`lossy`：带着它写回会把解不出的字节永久换成 U+FFFD）、生成物目录 ——
  预览顶上一行「跳过了 N 个文件：…」，不静默。

## 5. 执行

逐个文件，**每个文件都是「重读 → 核对 → 改 → 写」**：

1. 重读（用预览时记下的编码），和预览时的内容指纹比（长度 + 哈希）。**变了就跳过这个文件**，报「预览之后被改过」——
   不在一份没给人看过的内容上动手。
2. 用同一个 `Matcher` 重新算位置，只替换勾选的那几处（按「第几处」认，不按行号：前面的替换会让后面的行列挪位）。
3. `fsservice::write_text_as` 写回，编码 / BOM / 换行符照原样 —— 权限位、软链、硬链接那三条保存语义都在这条路上，不另写。
4. **开着的标签不写盘**：Rust 给回每一处的位置（UTF-16 偏移）和替换串，前端在编辑器里 dispatch 成**一笔**事务。
   - 干净的标签：改完照常保存（和关着的文件结果一样：盘上是新的），编辑器里 ⌘Z 也撤得回。
   - **脏的标签：只改编辑器，不保存**，圆点还在 —— 用户的没存改动和这次替换一起，等他自己决定（issue 验收第 2 条）。

多文件写不是原子的：中途失败（权限、盘满）就停在那里，**报清楚哪些改了、哪些没改**，已改的可以撤销。

## 6. 撤销

一次替换记成一条：每个文件「改前全文 / 改后全文」，存在 Rust 侧（按窗口登记 owner，窗口关掉就收 —— rust.md「活的资源表」）。
只留**最近一次**。

「撤销这次替换」逐个文件：**此刻的内容还等于「改后」才写回「改前」**，否则跳过并说明（替换之后你又改过它）。
**走哪条路按撤销那一刻算，不按替换那一刻**：替换后你可能关掉了那个标签、也可能新开了一个 ——
此刻开着就比编辑器里的文本、改编辑器，没开就比盘上的、写盘。界面上是一张确认卡片：「已替换 3 个文件 12 处 · 撤销」，下一次替换或关掉窗口就没了。

## 7. 上限

| | 上限 | 超了 |
|---|---|---|
| 命中 | 5,000 处 | 预览照常列前 5,000，**「替换」按钮不可点**，写明「命中太多，缩小范围再替换」—— 不替换一半 |
| 单个文件 | 8MB | 跳过并列出（同搜索） |
| 撤销记录 | 64MB 的改前 / 改后全文 | 超了这一次就不给撤销，执行前就说（「这次改动太大，撤销不了，仍然替换？」） |

## 8. 第 0 步要实测的

1. `regex` 的语法和 rg 的是否一致到「预筛不漏」：转义后的字面量、`\b` 整词在中文前后、`(?i)` 和 rg 的 `-i`（Unicode 大小写）
2. 编辑器里一次 dispatch 几百处的耗时；UTF-16 偏移从 Rust 的字节偏移换算（`settings.rs` 的 `pos_of_offset` 已经做过一次）
3. 5 万文件的仓库里预筛 + 逐个扫的耗时（判断要不要边扫边推结果）

## 9. 拍板记录（2026-10-09，五条都按建议）

下面是拍板时的原文，留着看当时为什么这么选。

**Q1 匹配语义统一，⇧⌘F 的行为会变。** 去掉 smart-case 和「装了 rg 才是正则」，改成显式的三个开关，默认字面量、不分大小写。
⇧⌘F 搜 `a.b` 不再命中 `axb`、搜 `Foo` 会命中 `foo`（之前装了 rg 时不命中）。**建议：统一**（修第 2 节那个不一致，替换的前提）。

**Q2 加依赖：`searchsvc` 直接依赖 `regex`。** 它已经在依赖树里（`logengine` 用它，`Cargo.lock` 里只有一份 1.13.1），
二进制不变大，但 AGENTS.md「加依赖先问」。**建议：加。** 不加就要自己写正则引擎，或者只支持字面量（替换的 `$1` 也就没了）。

**Q3 界面放哪。** (a) **IDEA 的做法**：⇧⌘F 那个浮层加「替换为」一行和勾选列表，⇧⌘R 直接带替换行打开（IDEA 的 Replace in Path 就是这个键，
我们的 keymap 里空着）；(b) VS Code 的做法：侧边栏一个常驻的搜索视图。**建议 (a)**：键位和层级跟 IDEA（键位那条记忆），
浮层已经有了；缺点是浮层关掉预览就没了 —— 但替换本来就是「看一眼、勾一下、执行」一口气做完的事。

**Q4 开着的干净标签：替换后要不要自动保存。** 建议**存**（第 5 节）：不然「关着的文件改到了盘上、开着的没有」，
同一次替换两种结果，用户要挨个标签去按 ⌘S 才知道哪些真落盘了。脏的标签不存（那是用户自己的未完成工作）。

**Q5 撤销只留最近一次、只在这个窗口里。** 建议**是**：多级撤销要处理「撤第二次之前第一次的文件又被改了」的交错，
收益小、坑多。

## 11. 验收（issue #42 那四条，加两条）

1. 三个文件里各有两处 `OrderClient`，替换成 `OrderGateway`：预览 6 处，取消勾 1 处，执行后改 5 处
2. 其中一个文件开着且有未保存改动：替换进了编辑器、圆点还在，盘上那份没被覆盖
3. 被替换的脚本文件执行权限还在
4. 「撤销这次替换」之后三个文件都回到原样
5. （加）软链和它指向的文件都在结果里时，只替换一次
6. （加）预览之后在外面改了其中一个文件：执行时它被跳过并说明，其余照常

## 12. 还不满意的地方（如实记着）

- **撤销记录只在内存里**：替换完应用崩了，撤销就没了，只剩 git。落盘要处理「下次启动时这份记录还算不算数」，这一轮不做
- **多文件写不是原子的**：中途失败停在一半。能报清楚、能撤销已改的，但做不到「要么全改要么全不改」——
  那要先把所有新内容写成临时文件、全部成功再逐个 rename，而 rename 那一步本身仍可能中途失败，只是窗口小了。第 2 步时再权衡
- **正则不跨行**：内容是按整份文本匹配的，`\n` 理论上能用，但预览按行展示，跨行的命中怎么画还没想好；第 1 步先把跨行匹配挡在外面并说明

## 12. 这一轮明确不做

- 多级撤销、跨窗口撤销（Q5）
- 保留大小写的替换（`foo→bar` 时 `Foo→Bar`）：IDEA 有，用得少，以后单独加
- 在文件名上替换（批量改名）
- 替换生成物目录、被 git 忽略的文件 —— 和搜索同一个范围
