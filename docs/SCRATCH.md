# 草稿：定位与方案（M10）

2026-09-16 定的。起因是一个问题：**「它凭什么让我用它记东西，而不是备忘录或 Sublime？」**

## 一、结论先行

**今天不凭什么。** 记东西这件事上它是第三名：

| | 赢在 | lite-ide 有没有 |
|---|---|---|
| 备忘录 | 随时随地：手机上也在、锁屏 Quick Note、跨设备同步 | 没有，也不打算有 |
| Sublime | 编辑器本身：100ms 起动、hot exit 一字不丢、二十年的手感 | 起动够快，不丢字这轮刚修好 |
| lite-ide 草稿 | 自动保存的 `.md` 目录 + 首行当标题 + 关了原样 | —— 这两样对手**都有** |

「不比对手差」是门槛，不是理由。所以问题不是「加什么功能能赢」，是
**哪一类笔记它们结构上做不到**。只有一类：

> **关于眼前这段代码的笔记。**
> 「orderId=8842011 那条为什么 142ms」「这个分支改完要记得回滚 pom 的 scope」
> 「第 47 行那个 timeout 是临时的」。

这类东西写在备忘录里三天后读不懂 —— 丢了上下文（哪个项目、哪个分支、哪个文件
哪行、当时 HEAD 在哪）；写在 Sublime 里是个孤儿文件。备忘录和 Sublime **不知道你
在看什么代码**，这不是功能差距，是结构差距。

**定位一句话：调试时的草稿纸。** 那个位置今天是空的。

~~**判据一句话：一条笔记如果离开这个项目还能读懂，它就不该在 lite-ide 里。**~~

**2026-10-13 改**：9-24 整个应用的定位改成了「取代 Sublime」（DIRECTION.md D1），而用户打开 Sublime 多半是「临时记、粘一段文本」——
正是上面那条判据要排除的。两份文档各自写得认真，只是写在不同的时间，新定位没回头改旧判据。现在是：
**项目窗口里的草稿带上下文（锚点），草稿本里的是一张白纸。** 两种都在 lite-ide 里，各有去处（第七节）。
以后每个草稿功能拿它过一遍。

**不做：** 通用笔记本。那是拿业余时间打两个满配的对手，而且自己也不会用 —— 手机上没有它。
「从别的应用过来记一笔」（全局热键 / 菜单栏常驻）也先不做：要常驻，而现在有意不装进
`/Applications`。

## 二、现状（改之前长什么样）

- 草稿存 `~/Library/Application Support/com.liteide.app/scratches/*.md`，
  **不按项目分目录**（issue #40 定的：草稿不属于任何项目，导轨上它不在 `{#if root}` 里）。
- `ScratchEntry { name, path, mtimeMs, firstLine }`，列表按 mtime 排，首行当标题。
- ⌘N 新建，半秒一次自动保存，废纸篓，关了原样恢复。
- 随处搜索（⇧⇧）**只按文件名**命中草稿，内容不搜。
- 编辑器是 CM6 的 markdown 模式；粘进去的日志 / diff / 堆栈都是纯文本。

## 三、三件事

按性价比排。每件先写「为什么它是结构差距」，再写做法和边界。

### 1. 草稿带锚点 —— 已做（2026-09-16，见 JOURNAL「M10 草稿锚点」）

**为什么：** 这是「关于眼前这段代码」四个字的落点。没有锚点，草稿和备忘录里的一条没区别。

**做法：**

- ⌘N 时**静默**记下四样，写进文件头的 frontmatter：

  ```yaml
  ---
  project: /Users/you/code/order-service
  branch: main
  head: b6176f3
  at: src/lib/git/GitPane.svelte:347
  ---
  ```

  四样都可以为空（没开项目时 ⌘N 就是一份普通草稿）。静默是硬要求 —— 记一笔的动作
  仍然是「⌘N 然后打字」，多一个问句人就回备忘录了。
- `ScratchEntry` 加 `anchor?: { project, branch, head, at }`，Rust 侧列表时解析头部
  （现在本来就读每份的头 4KB 取首行，顺路）。
- 列表里一个 chip：`lite-ide · main · GitPane.svelte:347`，长了从左省略（路径那套 rtl）。
  **打开项目时默认先列这个项目的，其余折叠成一个「其他 N 条」组** —— 不是过滤掉，
  是排序：切了项目还想翻上一个项目的笔记是常事。
- 点 chip 跳到 `at` 那一行。分支不同时照跳（行号可能漂，先认了）；文件不存在时说一句
  「文件已不在 main 上」而不是静默失败。

**边界：**

- 和 #40 那条**不冲突**：那条说的是存放位置不按项目分，锚点是软的、存放不变。
  要在 #40 那条注释旁边补一句，不然下一个人会以为定位改了。
- 行号会漂。用 `head` 的 sha + blame 追行号是后话，第一版只记不追。
- 不做「一个文件多条笔记的旁注视图」（VS Code 的 comments 那种）。那是另一个产品。

**验证：** 桩上 ⌘N → 列表出 chip → 切项目后分组变化 → 点 chip 跳行。
Rust 侧 frontmatter 解析要有测试：没有头、头不完整、头里带 `---` 的正文，三条。

### 2. 粘什么就变成什么 —— 2a 日志段、2b diff 段 / JSON 围栏 都已做（2026-09-16）

> **实际做法和下面写的有一处不同**：判定和着色都在前端，没走 Rust。LogView 本来就有一套
> 前端解析器（`logview/parse.ts`，按格式切成时间戳 / 级别 / 线程 / logger / 正文），
> 用同一套，「两边颜色一致」就是同一份代码；走 Rust 只拿得到级别拿不到分段，还得每敲
> 一个字把整份草稿送一趟 IPC。段的判据也从「认出级别」改成「认出格式」（有时间戳 /
> 结构化键）—— 更严，误判比漏判难受。

**为什么：** 调试笔记里一半是粘进去的：一段日志、一段 diff、一个堆栈。备忘录把代码糟成
富文本，Sublime 是纯文本。而这个仓库**已经有三套渲染器**（日志引擎的级别着色、DiffView、
CM6 的折叠），只是没接到草稿里 —— 这一条是现成的，别人要从零做。

**做法（分两步，先做日志）：**

- **日志段：** 草稿里连续 ≥ 3 行被 `logengine::level::detect` 认出级别的，当作一段日志：
  行按级别着色（复用 LogPane 的那套色），段头一个小工具条「只看 WARN+」。
  判定放 Rust 侧（`detect` 在那儿），前端拿到的是 `[{from, to, kind: "log"}]` 的段表。
  不做过滤后的重排 —— 过滤就是把不匹配的行折叠掉，正文一个字不动。
- **diff 段：** 以 `diff --git` / `@@` 开头的连续行，按 DiffView 的统一视图着色。
  堆栈 / JSON：CM6 本来就能折叠，用 markdown 的 fenced code block 就行，
  粘贴时检测到「像 JSON」自动包一层 ```` ```json ```` 就够，不另做渲染器。

**边界：**

- **正文永远是纯文本 `.md`。** 渲染是叠在上面的装饰（CM6 decoration），文件里不写任何
  私有标记。用 Sublime 打开这份草稿要一样能读 —— 这是「不丢东西」的另一面。
- 段的判定不能太贪：一行 `ERROR` 不是日志，三行才是。误判的代价是把正文着了色，
  比漏判难受。
- 不做「粘贴日志自动进日志模式」。草稿是纸，日志视图是另一个东西；纸上一段日志
  能看清就够，要真分析就把它存成文件打开。

**验证：** 段表的判定纯函数测：三行 INFO 是一段、两行不是、中间夹一行空行算不算
（算，日志里有空行）。视觉上截图对比同一段在 LogPane 和草稿里颜色一致。

### 3. 草稿和代码一起搜 —— 已做（2026-09-16）

**为什么：** 「上次那个坑我记在哪了」—— 备忘录里要切应用再搜一次。
⇧⇧ 打 `8842011` 应该同时翻出笔记和代码。

**做法：** 随处搜索的 `content` 范围（现在是 rg 搜项目）加一路：草稿目录也过一遍 rg，
结果并进同一列表，分组头「草稿」。命中行带锚点 chip（第 1 件做完才有）。
草稿目录不大（几十份），不用另做索引。

**边界：** 只搜内容，不搜 frontmatter（搜 `main` 不该把所有 main 分支上写的草稿都翻出来）。

这些不是差异化，但缺一样人就回备忘录。列出来是为了**每轮改完都过一遍**：

| 门槛 | 现在 |
|---|---|
| 起动快 | 够 |
| ⌘N 零提示，写了就存 | 有（半秒自动保存） |
| **存了没存一眼看得到** | 有（2026-09-17）：状态栏「自动保存… / 已自动保存 / 失败 · ⌘S 重试」，草稿标签的圆点只在写失败时亮（警示色）—— 原来那颗「未保存」的点每敲一串闪一次，还写着「关闭前会问」 |
| 关了再开原样 | 有（会话恢复带草稿） |

| 搜得到 | 有：⇧⇧ 按名 + 按内容都命中草稿（第 3 件） |

## 七、草稿本：开着项目时也有一张白纸（2026-10-13 设计，同日做完）

### 7.1 缺的是什么

开着项目时想随手记一句和代码无关的，现在只有 ⌘N —— 它在**项目窗口里**开一张草稿，旁边是文件树，标题栏是项目和分支，
草稿和项目文件的标签挤在一排。从别的应用切过来（⌘Tab）落进的也是项目窗口。缺的不是「一个开窗口的动作」，是**一个固定放随手记的地方**：
下次还在那儿，不越开越多。

### 7.2 先定命令，再定入口

快捷键、Dock 右键、菜单不是三选一，是**同一个命令的几个入口**。所以先把命令定死：

**「在草稿本新建」**（菜单名是动词，Apple HIG · Menus：做动作的项写动词；和上一行的「新建草稿」同一个动词，只差地方）：
草稿本 = 全应用只有一处 —— **没有项目的那个窗口**。

| 情形 | 做什么 |
|---|---|
| 没有「没项目的窗口」 | 开一个，落在一张新草稿里 |
| 有，在后台 | 切过去 |
| 切过去时它当前那张草稿是空的 | 就用这张，光标进去 |
| 当前那张不是空的（或者没有标签） | 开一张新草稿 |
| 有好几个没项目的窗口（「关闭项目」变出来的） | 去最近用过的那个 |

为什么不新造一种窗口：「没项目的窗口」本来就有（冷启动、关闭项目、全关了再从 Dock 新建草稿），会话恢复、草稿自动存、无锚点都是现成的 ——
草稿本就是**给它一个随时够得着的入口**。新造一种「草稿窗口」就得再写一遍恢复、路由、标题，而且多一个概念要人记。

和 ⌘N 的分工（**⌘N 不变**）：

| | 在哪儿开 | 带不带上下文 |
|---|---|---|
| `⌘N` 新建草稿 | 当前窗口里多一张 | 在项目窗口里带锚点（项目、分支、HEAD、正在看的行） |
| 草稿本 | 那个没项目的窗口 | 白纸 |

在草稿本里按 ⌘N 就是再开一张白纸 —— 两条规则不冲突。

**它有自己的身份**（评审第 1 条）：五个入口把人带进来，进来之后得认得出「这是草稿本」—— 标题栏挂件是**便签图标 +「草稿本」**
（和项目窗口的「首字母方块 + 项目名」同一个形状；点开照样是打开项目 / 最近打开），窗口标题（⌘`、「窗口」菜单、Mission Control）也叫「草稿本」。
这推翻了 2026-10-12 的走查改动 E1（没项目时写「打开项目」）：那时只想到「别像一个叫 lite-ide 的项目」，这个窗口还没有身份。

**标签不越积越多**（评审第 3 条）：草稿本里一张草稿**三天没改过**，下次打开草稿本（会话恢复）时就不再摆在标签栏上 —— 文件还在，
草稿列表里、⌘P 里都找得到。标签栏放这几天的，列表放全部的。只管草稿本、只管草稿：项目窗口和散文件不动。

**散文件也会落进来**（Finder 双击的、哪个项目都不包含的）：接受。Sublime 那个窗口本来就是「散文件 + 未命名的纸」——
所以叫「草稿本」不叫「便签」：它装的是不属于任何项目的东西。

### 7.3 入口：每一个都放在人在那个时刻手边的地方

| 你当时在 | 入口 | 理由 |
|---|---|---|
| 别的应用里（浏览器、企业微信） | **Dock 图标右键 →「在草稿本新建」**（应用没在跑时 Dock 菜单里没有它，macOS 只给运行中的应用挂菜单；那时点 Dock 图标会恢复上次的窗口） | 切应用时手就在 Dock 上；备忘录的「新建备忘录」、Safari 的「新建窗口」都放这儿 |
| lite-ide 任何窗口里，手在键盘上 | **`⇧⌘N`** | 见 7.4 |
| lite-ide 里，找菜单 | **「文件」菜单，紧挨「新建草稿 ⌘N」下面：「在草稿本新建 ⇧⌘N」** | 两个挨着，一眼看出一个是「这里多一张」、一个是「去那个本子」。Apple 惯例单例窗口进「窗口」菜单，但那儿没人找「记东西」 —— 可发现性优先 |
| 翻旧草稿时 | **侧边栏「草稿」列表顶上一行「在草稿本新建」** | 正在看草稿的人，下一步多半是再写一张 |
| 随处搜索 | `⇧⇧` 搜「草稿本」/「在草稿本新建」 | 键位表里登记了就自动有，不用另做 |
| 一个窗口都没有 | 「文件 → 草稿本」照样可点（`menu_without_window`），Dock 右键也行 | 应用还在 Dock 上，就该够得着 |

不做：全局热键、菜单栏常驻（第一节的理由不变：要常驻后台）。

### 7.4 快捷键：`⇧⌘N`

| 候选 | IDEA（键位跟它） | Sublime / VS Code | macOS 惯例 | 本应用现在 | 结论 |
|---|---|---|---|---|---|
| **`⇧⌘N`** | **新建草稿文件**（Scratch File） | **新建窗口** | 新建窗口 / 文件夹 | 空着 | **两边的肌肉记忆都指向它**：IDEA 的人按它要草稿，Sublime 的人按它要一个新窗口 —— 草稿本正好是「一个窗口里的草稿」 |
| `⌥⌘N` | 编辑器里「内联」 | —— | —— | 空着 | 编辑器键照 IDEA，以后一旦做重构就撞（memory「菜单快捷键别和 IDEA 编辑键撞」） |
| `⌃⌘N` | —— | —— | —— | 空着 | 不撞，但两边都没有这个记忆，要硬记 |

### 7.5 怎么验

- Rust（`windows.rs`）：「去哪个窗口」是纯函数 —— 没有就开、有就去最近用过的、好几个时挑对 —— 单测。
- 状态层：切过去时「空的那张复用、不空就开新的」—— `tabflow` 测。
- 测试 `.app`：菜单「文件 → 草稿本」三种情形（没有 / 有一个在后台 / 当前那张空）走测试通道验；
  **Dock 右键测不到** —— 测试身份是 Accessory 应用（不进 Dock，免得抢焦点，#54），只能在正式包上点一下。
  （2026-10-13 用户在正式包上点过：右键 Dock 图标有「在草稿本新建」，点了去草稿本。测试应用里能验的只有「菜单建出来了」的回读）
- 键位：`keymap.test.ts` 卡撞键、`menu_sync.rs` 卡菜单和键位表一致。
