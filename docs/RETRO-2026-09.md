## 三、做对了的（要继续）

1. **先啃唯一的技术未知数。** PLAN 里说日志引擎是「全项目唯一值得单写的硬骨头」，M0 那天就做了垂直切片，
   1GB 0.38ms / 98MB。最大的风险在第一天就排掉了，后面的一个月里它几乎没出过事。
2. **教训一次就变成机制，而不是停在「下次注意」。**
   - 桩和真实现分叉 → `dto_sync.rs`；菜单和键位表分叉 → `menu_sync.rs`
   - 入口包悄悄长胖 → CI 卡线
   - 测试不会失败 → 「改坏验红」写进 AGENTS.md
   - 一直手工验收 → `smoke.sh`
   - 子进程的坑 → `rules/rust.md` 那几条纪律

   效果看得见：这一轮做剪贴板的时候，读 `pbpaste` **一开始就设了输出上限**，没人提醒。
3. **JOURNAL 记全过程，连同坑当时长什么样。** 这是让 agent 能接着干活的东西 ——
   每一轮开头读的规矩文件（`rules/*.md`）都是从这里提炼的。
4. **规则写成数据。** 生成物名单、语言表、键位表、源码根、隐藏名单：加一条是加一行。
5. **大重构拆成小步。** App.svelte 4,380 → 974 分了九步，每步都能验证；中间 grok review 还抓到一处「零功能改动」里藏着的改动。

## 四、做得不好的（按代价排）

### 1. 先铺功能，后补质量 —— 而且补的顺序不对

四天做完 M0–M20，然后花了两周多去补。最该早补的那层补得最晚：
**09-03 审出两个丢数据的 bug，都在状态层；而状态层直到 09-18 才有测试**。中间这两周，
状态层又出过 M25 切标签丢未保存、09-09 快照回滚这类问题，全靠间歇红的 smoke 兜底。

教训：**会丢数据的那一层，第一个有测试**。功能铺得再快，那一层也要先有保护。

### 2. 视觉反复推倒

- **换皮**：09-03 到 09-04 两天换了三次（IDEA Darcula → 更暗更中性 → 照 ChatGPT 的配色 → 「材质分层」）。
- **按钮**：09-16 发现按钮有八套写法。
- **图标**：前后四轮（09-03 收编、09-06 新图标、09-18 `.ibtn` 原语、09-24 整套换成官方的）。

每一轮单看都有道理，合起来是**没有参照系**：每次都按当时的感觉改。09-24 定下「照 IDEA 新 UI、只抄一个来源」之后才收住。

教训：**视觉先定参照系，再做功能**。选一个来源、抄全，比每次凭感觉调省得多。

### 3. 定位在漂，没有写下来

PLAN 写的是「借鉴 VS Code 与 Sublime」、四个场景。实际越做越像 IDEA 化的 IDE：#33 二十多条对齐 IDEA、
git 全家桶、Java 专项。09-24 你把它拉回「取代 Sublime、多语言」。

漂移本身不全是坏事，IDEA 的手感是你真实的习惯。问题在于**定位没写下来，就没法对一个功能说「不」**。
这个月讨论过的调试器、Maven 启动、设置页、插件，都是一次次从头判断。现在有了 D1，以后先对照它。

### 4. 验收环节反复出错

同一类错犯了好几次，都是**验证的对象和真正交付的东西不是同一个**：

- 用 `cargo build` 验证，其实跑的是开发模式的壳；`app:build` 更新了但 `.app` 没更新；盘上有两份 `.app`（都写进 AGENTS.md 了）
- CI 红了两天没人发现（09-23）：本地只跑了部分测试
- 在自动化浏览器里验不了的东西，差点写成「验过了」（`frontend.md` 那张表）
- 我这边在这个月的最后一天也犯了同类错：改文档只读了一个函数、图标只看名字、重启了你正在用的应用

教训：**验证要落在真正执行的那一行、真正分发的那个产物上**。

### 5. 大文件越积越大

四个文件超过 1,700 行（gitsvc 3,614 行）。每加一个功能都先要在里面找位置。拆分已经排进 DIRECTION 的阶段 A。

## 五、跨事件的规律

- **最常见的 bug 是「不报错的失败」**：装了不生效、按了没反应、焦点掉进 body、剪贴板读出 GB18030。
  它们不崩溃、不报错，只让人觉得「不太对」。对策一直是同一套：真机验收、可观测性（app.log、调试版自报家门）、
  把「看不见」变成「测得出」。
- **同类问题很少复发**。在这个仓库里，一个坑一旦写进规矩文件或变成测试，后面就基本不再出现。
  这是 JOURNAL + rules 这套做法最大的回报。
- **AI 协作放大了两头**：一天十来个提交的速度是真的，「先做再补」的冲动也被放大了。
  grok 的第二轮 review 抓到过 P1（09-10、09-14），**多一双眼睛**这件事值得保留。

## 六、对你自己（这个项目也是为了成长）

这个月你的角色主要是提需求和验收：方向、手感、取舍都是你定的，实现是 agent 写的。
每轮的「这次学到什么」积累了不少原理，但它们大多是**听过**，还不是**做过**。

建议下个月挑一块，从「看懂」走到「能改」：

- **日志引擎**（`crates/logengine`）：内存映射、稀疏索引、分块读、二分查找。这是项目里最硬的技术，
  也是你想要的「把性能和底层原理算清楚」的现成教材。我可以带你读，每次一个概念，读完你亲手改一处，看数字怎么变。
- 或者 **ACP 客户端**：协议、流式、agent 的工具调用，正好对准 AI 方向。它是新写的，可以从第一行就参与设计。
