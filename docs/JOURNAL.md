## 2026-08-26 · 架构评审与工具链治理

### 对 PLAN 的七处修正

评审后落地 `docs/ARCHITECTURE.md`，对原方案做了七处修正，其中三处是关键的：

| # | 原方案 | 改为 | 为什么 |
|---|---|---|---|
| 02 | 全量行偏移索引 | 稀疏 checkpoint（每 1024 行） | 全量偏移在 1GB 时索引本身就吃 64MB，10GB 吃 640MB，"内存与文件大小无关"当场破功 |
| 03 | （未提 IPC 层） | 数据面强制走二进制 | Tauri 默认 invoke 走 JSON，传 1000 行约 15ms vs 二进制约 1ms；60fps 单帧预算才 16ms |
| 05 | M0 地基 → M1 日志引擎 | M0 直接做日志垂直切片 | 地基是确定能做成的已知工程，引擎是唯一未知数。先花三周做确定的事再去撞唯一可能撞不通的墙，是最坏的排序 |

另外四处：50MB 阈值改复合判据、日志模式不复用 CM6、内存目标 <100MB 放宽到 <200MB、
Java 不上 LSP（jdtls 启动 5–10s、常驻 1GB+，与轻量定位冲突）。

### Rust 工具链治理

诊断发现：Rust 本来就装在本机标准位置（`~/.cargo` + `~/.rustup`），
问题是**只装了最小组件** —— rustfmt / clippy / rust-analyzer / rust-src 全缺，
还往 `~/.profile` 写了一行 zsh 根本不读的垃圾。

按用户要求彻底卸载重装：
- `rustup self uninstall` 清空，确认 shell 配置无残留
- 用 `--no-modify-path --profile default` 重装，rustup 不再自作主张改任何 shell 文件
- PATH 由 `~/.zshenv` 中一段带 `RUST_TOOLCHAIN v1` 标记的配置独家负责，将来删那五行即可
- 补 `rust-analyzer` + `rust-src`
- 移除 rust-docs 离线文档，`~/.rustup` 从 1.4G 降到 571M

一处返工：`rust-toolchain.toml` 起初 pin 了具体版本 `1.98.0`，触发 rustup 把它当成
独立 toolchain 又下一份（约 500MB）。改回 `channel = "stable"` 并卸载多余的那份 ——
个人项目不值这个磁盘，真出现版本漂移再 pin 不迟。

## 2026-08-26 · M0 垂直切片

**目标**：用最小成本回答"mmap + 稀疏索引 + 二进制 IPC + 虚拟滚动这条链路到底通不通"。
丑没关系，只验性能。

**做了什么**
- `crates/logengine`：零 Tauri 依赖，可独立 `cargo bench`
  - `index.rs` 稀疏 checkpoint 索引
  - `block.rs` 紧凑二进制块编码
  - `lib.rs` mmap 管理 + 后台索引
- Tauri 命令层（只做解包与错误转换，业务全在 crate 里）
- 前端：Svelte 5 + Vite（不用 SvelteKit，桌面 app 不需要路由/SSR），虚拟滚动 + 块级 LRU

**过程中撞到的**

1. **后台索引线程把读者饿死**。首屏 50 行读取 1112ms，几乎正好等于全量索引耗时——
   窗口开了但一行读不出来。原以为 `RwLock` 每 16MB 放一次锁读者就能插进去，
   实际写者放锁后立刻重新申请，读者根本抢不到。改成后台无锁构建 + 快照发布
   （`Mutex<Arc<LineIndex>>`，读者只克隆 Arc），**1112ms → 0.008ms**。

2. **mmap 顺序扫描没给内核提示**。索引吞吐只有 0.77 GB/s，而 memchr 本身能跑 5–10 GB/s；
   瓶颈是 1GB 映射的约 26 万次 page fault。加 `MADV_SEQUENTIAL` 后 **→ 6.87 GB/s**。

3. **WebKit 元素高度上限**（设计阶段就绕开）。914 万行按 20px 是 1.6 亿 px，
   远超上限（量级 3000 万 px），直接设会让滚动条静默截断、行号全错。
   前端用比例映射把 scrollTop 换算成行号。

**结果**：打开 0.38ms、首屏读取 0.02ms、索引占用 69.8KB（省 1024×，正好等于 stride）、
进程数 4、二进制 3.7MB。技术路线确认可行。

**提交**：`05b28f4`（51 文件 +7543 行），merge 为 `6e0b0f4`。

## 2026-08-26 · M1 日志模式

**目标**：日常真能拿它替代 `less` 看线上日志。

**做了什么**
- `level.rs`：行首 64 字节内的快速级别探测；`LevelMap` 以 4bit/行 打包存储
- `filter.rs`：级别 + 文本组合过滤，只返回命中行号，可取消
- tail：`refresh()` 检测追加并重新 mmap，`unseal()` 让末尾半行能被续写；
  inode 变化或文件变短判定为 logrotate
- `read_block_at()`：按命中行号回表，相邻行号走顺序推进
- 前端：行分段解析（时间戳/级别/线程/logger/消息各自着色）、chips 过滤栏、
  搜索高亮、堆栈续行缩进压暗、过滤态显示物理行号

**三处偏离原架构**（理由已就地写进 ARCHITECTURE.md）

1. **级别统计不塞进索引**。顺路统计看似省一遍遍历，实测把索引从 143ms 拖到 870ms（6×）——
   级别探测要逐字节看行首，成本远高于 memchr 找换行。索引是关键路径，必须保持纯粹。
   改为并行的第二个后台任务，88ms 跑完。
2. **过滤不起 rg 子进程**。文件已 mmap 在内存，rg 会重新 IO 一遍 1GB；
   单文件搜索也用不上它的多文件遍历。改用 aho-corasick 进程内实现。rg 留给 M4 全局搜索。
3. **tail 不用 notify**。macOS FSEvents 对单文件有秒级合并延迟，500ms 轮询更快更可控。

**过程中撞到的**

4. **`cargo build` 产出的是 dev 模式二进制**（最严重的一个）。
   停掉 vite dev server 后 app 启动即白屏：窗口在、WebKit 子进程在、`run()` 也进了，
   但 `page_load` 从不触发。根因是 Tauri 的 dev/prod 之分**不看 cargo profile**，
   而由 `tauri build` 命令决定 —— `cargo build --release` 出来的二进制，
   窗口 URL 仍是 `http://localhost:1420/`。
   **代价**：此前几次"端到端验证通过"其实都是经由当时开着的 dev server 加载前端，
   并没有验证到真正的交付物，误判横跨 M0 到 M1 中段。
   换成 `pnpm app:build` 后立刻又逮到一个真 bug：标题栏拖不动窗口，
   缺 `core:window:allow-start-dragging` —— ACL 拒绝在前端只是一条静默 rejection。

5. **改了前端却毫无变化**。只改前端时 `cargo build` 看 Rust 代码没动就跳过编译，
   二进制里留着上一版 dist。`build.rs` 补 `rerun-if-changed=../dist` 解决。

6. **过滤时闪一帧空白**。过滤刚启动、命中数还没回来时就切到过滤视图，行数是 0。
   改成拿到第一批计数之前继续显示旧视图。

一处自我更正：排查白屏时一度怀疑顶层 await 并把结论写进了注释，
后来定位到真因是上面第 4 条，顶层 await 是无辜的 —— 已改掉那处错误归因（`7c7f71a`）。

**结果**：索引 143ms 与级别扫描 88ms 并行、过滤 86–284ms、常驻内存 98MB、
37 单测通过、二进制 3.8MB。

**范围缩减**：堆栈折叠缩为视觉区分（缩进 + 压暗）。折叠交互需要一套
"视图行→物理行"映射，与过滤是同一机制，叠加后复杂度陡增，留待后续。

**未实测**：tail 的前端轮询 + 吸底循环没有在真实追加写入场景下跑过（引擎侧有 4 个单测覆盖）。

**提交**：`3dfbe02` + `7c7f71a`（28 文件 +2126 行），merge 为 `e6ab1aa`。

## 2026-08-26 · M2 编辑模式

**目标**：能舒服地改代码。CodeMirror 6 + 四语言高亮 + 文件树 + 多标签 + IDEA Dark 主题落地。

**做了什么**

- `probe.rs`：终于兑现修正 01 的**双模式分流**。判据是复合的 ——
  大小 > 32MB、估算行数 > 30 万、最长行 > 1 万，任一超标即走只读日志模式；
  含 NUL 字节判为二进制。只读文件头部 2MB 采样外推，不加载全文。
- `crates/fsservice`：目录列举（目录在前、构建产物默认隐藏）与文本读写。
  保存走"写临时文件 + 原子 rename"，中途崩溃不会留下半个文件。
- CodeMirror 6 集成：IDEA Dark 主题（编辑器外壳 + 语法着色两层）、
  四语言按需加载、⌘S 存盘、搜索面板、折叠、括号匹配。
- 文件树：**扁平化渲染**而不是递归组件 —— 把展开的树拍平成带 depth 的列表，
  渲染就是一个 each，将来给大仓库加虚拟滚动也直接可用。
- 多标签：脏标记（关闭按钮变圆点）、关闭脏标签时弹确认条
  （保存并关闭 / 丢弃 / 取消），而不是静默丢改动或静默保存。
- 把 M1 的日志逻辑抽成 `LogPane` —— 多标签之后每个日志页签都要有
  自己的过滤与 tail 状态，不能再挂在 App 上。

**一处关键的性能取舍**

CodeMirror 6 核心约 340KB，静态引入会把入口包从 **71KB 顶到 412KB**，
与"秒开"的立身之本直接冲突 —— 而日志模式一点也用不上它。
改成打开第一个可编辑文件时才 `import()`，入口回到 **80KB**，
本地加载只有几毫秒。顺带把组件 ref（`bind:this`）换成一个 `savedTick` 计数器：
动态组件上 ref 不好使，而且这样耦合更松。

**过程中撞到的**

7. **文件树 effect 自己依赖自己**。`$effect` 里写 `children`，
   而同步调用的 `load()` 开头又读 `children` 判重 —— Svelte 5 据此建立依赖，
   于是写触发读、读触发写，直接 `effect_update_depth_exceeded` 爆栈。
   修法是把写操作包进 `untrack`，让 effect 只依赖 `root`。

8. **`lite-ide <目录>` 静默无反应**。`initial_file` 的实现只认 `is_file()`，
   传目录被过滤掉，返回 None。改成 `initial_path`，文件和目录都接受 ——
   目录成为项目根，文件则打开并把父目录当根。

9. **拖放注销抛异常**。`un.then(f => f())` 没有 catch，
   注销失败会把整个 effect 清理链炸掉。加了保护。

顺带给 `openPath` 加了防重（同一路径正在打开时忽略），
避免双击或事件重放时重复探测与读取。

**结果**：入口包 80KB（8 个 chunk，语言与编辑器全部按需）、二进制 4.0MB、
48 单测通过（logengine 43 + fsservice 5）、clippy 0、fmt 0、svelte-check 0 错 0 警告。
生产二进制打开项目目录常驻 28MB。

**验证方式**：新增 `src/lib/dev/mock-ipc.ts` —— 浏览器里的 Tauri IPC 桩，
喂与 Rust 侧严格同格式的数据（含 log_lines 的线格式二进制）。
调 UI 不必等壳编译（40 秒 → 毫秒），生产构建里被 tree-shake 掉。
M2 的编辑模式、语法着色、多标签、脏标记、保存、双模式分流都是先在桩上验证，
再用生产二进制复核。

## 2026-08-26 · M3 终端

**目标**：能跑 gradle / npm。

**做了什么**

- `crates/ptysvc`：`portable-pty` 封装。起的是**登录 shell**（`$SHELL -l`），
  读用户自己的 `.zshrc`，PATH 与别名跟平时一致；`TERM=xterm-256color` 让
  ncurses 类程序知道终端能力。
- 命令层：输出走 `Channel` 流式回传，输入 / resize / kill 各一条命令。
- 前端：xterm.js + FitAddon，配色与 `app.css` 的 IDEA Dark token 同源；
  `ResizeObserver` 把容器尺寸同步给 pty，否则 vim / less 的排版会错位。
- 底部面板：⌘J 开合，可拖拽调高，带「重启」按钮。

**两个必须做对的细节**

- **slave 端要尽早 drop**。不丢掉它，shell 退出后 reader 永远不会 EOF，
  读线程就一直挂着。
- **退出必须带走 shell**。`Session::drop` 里 kill + wait，
  外加窗口 `Destroyed` 事件兜底清空 pty 表。这是 UNINSTALL.md
  「无常驻进程」承诺的兑现点，专门写了单测卡住：
  `drop_之后子进程必须已退出`。实测 app 退出后 `zsh -l` 残留为 0。

**过程中撞到的**

10. **终端被创建了两次**。`{#key `${root}-${termEpoch}`}` 让终端跟着项目根走，
    而 `root` 是异步就绪的 —— 先用 `/` 起了一个，`root` 到位后又重建。
    切项目就把正在跑的命令连根重启是很讨厌的行为（IDEA 也不这么干），
    改成 **cwd 创建时快照一次**，想换目录点「重启」。
    顺带在 Rust 侧加了兜底：cwd 不是有效目录就回落 `$HOME`，而不是把用户扔到 `/`。

11. **MutexGuard 活过了它借用的 Arc**。`sess.lock().….map_err(…)` 直接当返回值时，
    guard 作为临时值活到函数返回，而 `sess` 在函数体结束时就析构了。
    落成局部变量让 guard 提前释放即可。

12. **pty 测试挂死终端**。`Read::read` 是阻塞的，在主循环里判 deadline 根本判不到 ——
    没数据时就卡死在那儿。改成读线程 + channel `recv_timeout`。

**结果**：入口包 84KB（xterm 与 CM6 一样按需加载）、二进制 4.2MB、
51 单测通过、clippy 0、fmt 0、svelte-check 0 错 0 警告。

## 2026-08-26 · M4 导航

**目标**：手不离键盘。

**做了什么**

- `crates/searchsvc`：项目文件索引（跳过 `.git` / `node_modules` / `target` 等噪声目录，
  上限 5 万文件、深度 24 层、不跟软链）＋ 全局内容搜索。
  内容搜索**优先起 rg**（多文件遍历正是它的主场，也是架构原本的规划），
  机器上没有 rg 就回落到进程内实现。
- 模糊匹配放在**前端**：每敲一个字符都往 Rust 跑一趟，IPC 往返会让输入发木；
  几万条路径在内存里跑一遍子序列匹配是微秒级的。
  打分偏好：命中文件名 > 连续成段 > 落在词首（`/`、`-`、`_`、`.` 或驼峰处）> 整体靠前。
- 随处搜索浮窗：双击 Shift 唤起，四个范围（全部 / 文件 / 内容 / 操作），
  Tab 切换范围、↑↓ 选择、↵ 打开、Esc 关闭。⌘P 直接进文件范围，⌘⇧F 进内容范围。
- 跳转到行：编辑模式与日志模式都支持。目标带 nonce，
  连点同一条搜索结果也能重新定位（不带的话第二次点没反应）。
- 内置操作：切换侧边栏 / 终端、重启终端、保存、关闭标签、关闭全部。

**过程中撞到的**

13. **rg 与内置实现结果不一致**。内置实现靠硬编码的 `SKIP_DIRS` 跳过 `node_modules`，
    而 rg 靠 `.gitignore` —— 项目没有 `.gitignore` 时，两边搜出来的东西就不一样了。
    「装没装 rg」不该改变搜索结果。给 rg 显式加上 `--glob '!**/<dir>/**'` 与内置对齐，
    并写了 `两条实现路径结果必须一致` 这个 parity 测试把不变量钉死。

14. **rg 的退出码判断写反了**。rg 无命中时返回 1，那是正常情况；
    原来的条件会把它当成执行失败。只有 `>= 2` 才是真出错。

15. **双击 Shift「不工作」——其实是测试方法的问题**。

## 2026-08-26 · M5 Markdown live preview

**目标**：笔记体验对齐 Obsidian。

**做了什么**

`markdown-live.ts` —— 用 CodeMirror 的 decoration 实现，**不是把文档转成 HTML**：
文档模型自始至终是那份 Markdown 源码，渲染纯粹是显示层的事，
磁盘上永远是纯 `.md`（PLAN 里定的红线）。

核心行为：**光标所在的行显示原始语法，其余行渲染**。
这样既所见即所得，又随时能看到并编辑真正的标记。

覆盖的元素：标题（六级，藏 `#`）、粗体、斜体、删除线、行内代码、
链接（显示文字藏掉 URL）、引用（左边框 + 藏 `>`）、无序列表（`-` 换成 `•`，
有序列表保留数字）、分隔线（`---` 渲染成横线）、围栏代码块（整块底色）。

**两个实现细节**

- decoration 必须**按位置排序**后再交给 `Decoration.set`。
  `syntaxTree.iterate` 是前序遍历，父节点先于子节点，位置不保证递增 ——
  直接用 `RangeSetBuilder` 会因为乱序而报错。
- 只处理 `view.visibleRanges` 内的节点。长文档全量遍历会让每次光标移动都卡一下，
  而「光标一动就重算」正是这个交互的前提。

**过程中撞到的**

16. **删除线不渲染**。`markdown()` 默认用的是 `commonmarkLanguage`，
    而 `~~删除线~~` 属于 GFM 扩展。换成 `markdown({ base: markdownLanguage })`
    即可（后者带 GFM：删除线、表格、任务列表）。

17. **验证时误判「`#` 没隐藏」**。第一行的 `#` 一直显示着，一度以为 decoration 没生效 ——
    其实那正是设计行为：光标打开文件时就在第 1 行，而光标行本来就该显示源码。
    把光标点到第 14 行后，第 1 行立刻变成 `lite-ide`，第 14 行的反引号则显现出来。
    这类「预期即正确」的现象，验证时容易当成 bug。

**结果**：入口包 92KB（10 个 chunk，Markdown 相关全部按需）、二进制 4.2MB、
57 单测通过、clippy 0、fmt 0、svelte-check 0 错 0 警告。

## 2026-08-26 · M7 外部文件修改检测

**目标**：文件在编辑器外被改动时不能装作没看见。

**做了什么**

- `fsservice::stamp`：用 **mtime + size** 作为文件指纹，不用内容 hash ——
  hash 要把整个文件读一遍，而这个检查会在窗口每次获得焦点时对所有打开的标签跑一遍。
  两个字段一起看，实际使用中足够可靠。
- 检查时机选在**窗口获得焦点**时：用户从别处切回来才是他关心这件事的时刻，
  不必为此常年跑轮询。另配一个 10 秒兜底轮询，应付「一直没离开窗口但文件被后台进程改了」。
- 两种处理分支：
  - **本地没改过** → 直接重新加载，状态栏提示一句。这是最常见也最无害的情况，
    弹窗问一遍纯属打扰。
  - **本地也改过** → 冲突条，给「保留我的 / 用磁盘上的」两个出路。不自动选边。
- `write_text` 改成返回新指纹 —— 前端必须拿它更新记录，
  否则**自己的保存会在下一次检查时被当成外部修改**，无限自我告警。

**结果**：59 单测通过（fsservice 从 5 涨到 7）。

**起因**：用户建议「对常用的编程语言和日志都适配一下」。
当时只有 18 种语言，日志只认 Java 一种格式 —— 其余全部降级成纯文本。

### 语言：18 → 67 种

新增 C#/Kotlin/Scala/Swift/Objective-C/Dart、Ruby/Perl/Lua/R/Julia、
Haskell/Clojure/Erlang/Elm/Scheme/Lisp、Groovy/PowerShell/VB/Pascal/Fortran、

**150 个扩展名 + 22 个特殊文件名**（Dockerfile、Makefile、.zshrc、Cargo.lock、
CMakeLists.txt、Gemfile 这类没有扩展名的）。全部按需加载，入口包一个字节都没为它们买单。

### 日志：1 → 8 种格式

原来的解析器写死了 Java/Logback 的形状。重构成**格式探测 + 多解析器**：

| 格式 | 样例 |
|---|---|
| Java / Logback | `2026-08-24 14:03:21.442 INFO [thread] c.l.Svc - msg` |
| ISO 时间戳 | `2026-08-24T14:03:21.442Z DEBUG [worker] cache - msg` |
| Python logging | `2026-08-24 14:03:21,442 - module - WARNING - msg` |
| Rust env_logger | `[2026-08-24T14:03:21Z INFO module] msg` |
| logfmt (Go) | `time="..." level=error msg="..." retries=3` |
| JSON 结构化 | `{"@timestamp":"...","level":"warn","msg":"..."}` |
| Nginx / Apache | `10.0.0.7 - - [24/Aug/2026:...] "GET /api HTTP/1.1" 503 1234` |
| syslog | `Aug 24 14:03:21 host sshd[4711]: msg` |

两个设计决定：

- **解析结果是通用分段列表而不是固定字段**。每种格式吐自己的段（`ts`/`level`/
  `thread`/`logger`/`key`/`meta`/`msg`/`dim`），渲染层只按类别上色 ——
  加一种新格式不必动渲染代码。
- **格式靠投票探测，不看第一行**。日志开头常有启动横幅、空行、乱七八糟的东西，
  只看一行很容易被带偏。取前 60 行投票。
- Nginx access log 没有级别字段，**用状态码推**：5xx 当 error，4xx 当 warn。

### Rust 侧的级别探测也得跟上

`level=error` / `"level":"warn"` 的值是**小写**的，原来只扫大写关键字，
这些行会全部落进「其他」。加了结构化探测路径，且**必须放在大写扫描之前**——
JSON 行的正文里常有大写 ERROR 字样，先扫大写会把 `msg":"Connection ERROR"` 误判。

**过程中撞到的**

18. **结构化探测让级别扫描慢了 6 倍**（88ms → 517ms）。
    我加的 SIMD 快速排除窗口取了 200 字节，而测试日志正文里的
    `orderId=8842011` 正好落进窗口，快速排除全部失效。
    收紧到 **48 字节**后回到 96ms —— logfmt 的首个 `=` 必在开头附近
    （`time=...`），JSON 行首就是 `{`，而传统日志正文里的 `=` 都在时间戳、
    级别、线程名、logger 之后，48 字节根本够不着。

19. **ISO 格式被误判成 Java**。java 的时间戳正则写了 `[ T]`，把 ISO 也吃了。
    改成 java 只认空格分隔、T 分隔归 iso。顺带发现两者「时间戳之后」的结构
    完全一样，抽出 `parseTimestampedRest` 共用 —— 否则同一种结构维护两遍，迟早分叉。

**验证**：八种格式逐一验证识别与分段正确；造了 40MB 的 JSON 与 logfmt 日志，
级别统计比例与样本设计完全吻合，**「其他」为 0**——每一行都被识别，没有漏网。

## 2026-08-26 · M10 堆栈折叠

**目标**：长堆栈可折叠。M1 时缩水成了视觉区分，因为真正的折叠需要行号重映射。

**做法：复用过滤机制，而不是另起炉灶**

折叠和过滤要解决的是同一个问题 —— 「哪些物理行出现在视图里」。
M1 的过滤已经建好了这套映射（命中行号列表 + 回表读取），
折叠只是往 `FilterSpec` 加一个 `collapse_stacks` 开关，
在收集命中行时跳过连续栈帧的后续几帧。整个改动不到 40 行。

**折叠什么、保留什么**

只折叠**栈帧**（`at ...` / `... 12 more` / Python 的 `File "..."` / Go 的 `/path.go:123`），
**不折叠异常首行与 `Caused by:`** —— 那两类带着异常类型和根因，
是排查时最该看的东西，折掉等于把关键信息藏了。
每个连续帧块还保留第一帧，因为「异常发生在哪」通常就在那一行。

**效果**（95,000 行、每 4 条日志跟一段 12 帧堆栈的样本）

```
95,000 行  →  45,000 行（砍掉 52.6%）
```

= 20000 INFO + 5000 ERROR + 5000 异常首行 + 5000 第一段首帧
  + 5000 Caused by + 5000 第二段首帧。5 万个冗余栈帧被折叠，
关键信息一行没少。

## 2026-08-26 · M11 符号大纲

**目标**：看陌生代码时能快速摸清文件结构。

**关键决定：不引入 tree-sitter**

架构原本写的是「tree-sitter WASM 懒加载」。真做的时候发现没必要 ——
**CodeMirror 为了高亮本来就把文档解析好了，语法树就在它手上**。
再挂一套 tree-sitter 等于同一份代码解析两遍，而每种语言的 wasm 有几百 KB，
与「秒开」的立身之本直接冲突。

PHP / CSS / HTML / Markdown 等 18 种），走 legacy stream parser 的语言没有语法树。
**界面会明说「这门语言没有语法树，无法提取结构」，不假装**。

**做了什么**：⌘⇧O 打开文件结构浮窗，符号可模糊过滤、↑↓ 选择、↵ 跳转。
Markdown 的大纲就是标题层级（H1–H6），笔记场景直接可用。

**过程中撞到的**

20. **Java 的符号名提取错了**。`private final OrderRepository repo;` 显示成
    `OrderRepository`，`public Order persist(...)` 显示成 `Order` —— 全是类型名。
    根因是我按**集合**匹配「可能是名字的节点类型」，而 Java 的字段/方法节点里
    `TypeName`（类型）和 `Definition`（名字）都在，先撞上谁算谁。
    改成**按优先级查找**：声明名（Definition 系）必须排在类型名前面。

**验证**：Java（类/字段/构造/方法）、Python（类/函数）、Markdown（H1–H3 层级）

## 2026-08-27 · M13 Git 版本管理

按 IDEA 的形态做了一整套：改动列表在侧边栏、提交历史在底部工具窗、
分支与工作树做成弹出选择器、差异双栏对照、冲突逐块解决。

### 定调：起 `git` 子进程，不链 libgit2

和 `searchsvc` 起 `rg` 同一条路子，理由也一样：

| | 起子进程 | 链 libgit2 / gix |
|---|---|---|
| `.gitignore` 优先级、`core.excludesfile`、worktree、submodule、稀疏检出 | git 本身就是这些规则的定义 | 永远在追一个移动靶 |
| 二进制体积 | 0 | +约 2MB（整个 `.app` 现在才 4.6MB） |
| 每次调用开销 | 约 5–15ms 进程启动 | 约 0 |

那 5–15ms 是可以接受的，因为**刷新是事件驱动而不是轮询**：窗口获得焦点时、
保存之后、做完任一 git 动作之后各刷一次。用户在终端里 commit 完切回来，
焦点事件正好把状态带新。常年轮询才是白烧电。

两条硬纪律写进了 `gitsvc` 的模块注释：
1. **绝不拼 shell 字符串**，全部走 `Command::arg`，路径前一律加 `--`
   —— 否则一个叫 `-f` 的文件就能变成命令行开关。
2. **绝不让 git 卡住等输入**：`GIT_TERMINAL_PROMPT=0` 关掉凭据提问，
   `GIT_OPTIONAL_LOCKS=0` 让 `status` 不抢 index 锁（用户正在终端里跑
   `git rebase` 时，后台刷新不该把它顶失败）。

还有一条容易漏的：`env_remove("GIT_DIR")`。从终端里启动 lite-ide 时，
这个环境变量可能指向另一个仓库，会让所有查询悄悄串到别处去。

### 用 `--porcelain=v2 --branch -z`

v2 把分支名和 ahead/behind 一起带出来，省掉第二次进程启动；`-z` 用 NUL 分隔
记录，路径不做 C 风格转义 —— v1 遇到带空格或中文的路径会加引号并转义，
解析端要反过来再解一遍，纯属自找麻烦。

代价是 `-z` 下**改名条目占两条记录**（新路径一条、源路径一条），解析器必须
有状态地把下一条吃掉。这是最容易写错的地方，专门写了一条测试守着。

### 坑一：整个未跟踪的目录会被折叠成一条

测试当场逮到的：`--untracked-files=normal` 把 `有 空格/中 文.md` 报成了
`有 空格/` 一条。这其实是对的行为 —— 新建一个目录不该在 Git 面板里炸出几百行 ——
但文件树必须知道这回事，否则目录里的文件不会被标记。

处理是给 `Entry` 加显式的 `is_dir`，前端据此做前缀匹配。**别让前端去猜末尾的斜杠**。

### 坑二：`git log` 默认序会把泳道图画歪

第一版泳道图跑出来，主线莫名其妙断掉跳到别的泳道。原因是 `git log` 默认按
**提交时间**排序，而 `75c0e9b`（M12 分支尖端）和它的子提交 `08ba067`（合并）
时间戳相同 —— 于是父提交排到了子提交前面。

泳道算法的前提是「子先于父」：一条提交出现时认领正在等它的泳道。父先出现，
这个前提就塌了。

修法是 `--topo-order`，gitk 和 IDEA 用它也是为这个。加了一条回归测试：
造一个所有提交**时间戳完全相同**的仓库（这样默认序必然出错），断言每条提交的父
都排在它后面。光靠注释挡不住以后有人把这个参数删掉。

### 坑三：冲突文件同时出现在三个分组里

`UU` 状态下 index 和 work 都是 `U`，按字面判 `staged()` 和 `unstaged()` 都成立，
于是同一个 `app.py` 在「冲突中」「已暂存」「改动」三组里各出现一次。

冲突条目哪一组都不属于 —— 它得先解决完才谈得上暂存。两个方法都加了
`!self.conflicted`。顺带把「有未解决冲突时禁用提交」也做了：git 自己也会拒绝，
但等它报错太晚了，用户已经把提交信息敲完了。

### 冲突解决：以工作区文件为准

读的是**工作区那份带冲突标记的文本**，而不是 `git show :2:` / `:3:` 三个暂存位。
工作区那份才是用户此刻真正会提交的东西 —— 他可能已经手改过一部分，
从暂存位重建会把那些手改悄悄抹掉。

解析器有一条往返保证并写了测试：**一个选择都不做时，`compose()` 必须一字不差
还原原文**。这样「保存进度」才敢做 —— 半成品文件写回去不能悄悄丢内容。

还有个安全兜底：`<<<<<<<` 开了却没有配对的 `>>>>>>>` 时，整段当普通文本还回去。
一份讲冲突解决的文档不该被解析成半个冲突块。

### 双栏对照

一个 grid、四列（行号·左文·行号·右文），而不是两个并排的滚动容器 ——
一个容器意味着纵向滚动天生同步，不用写一行同步代码，也不会有「两边差一帧」的抖动。

列宽用 `minmax(max-content, 1fr)`：下限是最长那行（长行不截断，溢出时整个 grid
横向滚动），上限是 1fr（窗口宽时两栏平分、背景铺满，右边不留没上色的空白）。

对面没有对应行的地方画成斜纹底，一眼看出「这里本来就没东西」，而不是「这里是空行」。

行内高亮沿用 M13 之前就有的思路：一段删除后面跟等长的一段新增时 1:1 配对，
砍掉公共前后缀，中间那一小截才是真正改的。长度不等就不猜 ——
**猜错的高亮比没有高亮更误导**。

### 入口包纪律

GitPane / DiffView / GitLog / BranchPicker / MergeView 五个组件全部按需加载。
静态引入时入口包从 120KB 涨到 140KB，而只看日志的人一次都不会用到它们。
文件树上的 git 染色不在此列 —— 那只是 FileTree 里的一个 `$derived`，没有额外模块。

### 顺带修掉的老 bug：⌘⇧G 按不出来

写 `e.key === "g" && e.shiftKey` 是错的：按住 Shift 时 `e.key` 给的是**大写** `"G"`
（规范如此，`key` 是修饰后的字符值）。这条判断永远不成立。

同样的写法在 **⌘⇧O（符号大纲）和 ⌘⇧F（全局搜索）**上也存在 —— 也就是说这两个
快捷键从 M4 / M11 起就一直是失效的，只是没人按到过。统一改成先小写化再比。

## 2026-08-27 · M14 编码集与代码缩略图

### 编码：从「拒绝」改成「探测 → 记住 → 原样写回」

M0 起的策略是**只支持 UTF-8，非 UTF-8 一律拒绝**。那条理由当时是对的：
lossy 解码之后保存会把原文件写坏，比打不开糟糕得多。

但对中文项目代价太大了 —— 老 Java 工程、Windows 上生成的日志、一堆
`.properties`，GBK 遍地都是。现在改成：用什么编码读进来的，就用什么编码存回去。
**保存不再是「顺手转成 UTF-8」这种擅自的决定。**

依赖选了 `encoding_rs` + `chardetng`（Firefox 里抽出来的那两个，纯 Rust）。
自己写 GBK/Big5 的映射表是不可能维护对的 —— 光 GB18030 就是四字节变长、
带 Unicode 补充平面映射的一大张表。代价是二进制从 4.6MB 涨到 4.9MB，
这 0.3MB 就是那几张表，认了。

**探测顺序不能反**：

1. BOM —— 有就信它，这是文件自己的声明
2. UTF-8 合法性校验 —— 通过就是 UTF-8（纯 ASCII 也走这条）。这不是猜
3. 统计探测（chardetng）—— 到这一步才开始猜

先跑统计探测的话，一份纯 ASCII 文件可能被判成 windows-1252，存回去就带上了
错误的编码标签。写了一条测试专门守这个顺序。

#### 坑：UTF-16 会被悄悄编成 UTF-8

Encoding Standard **只定义了 UTF-16 的解码**，`encoding_rs` 的 `encode()`
遇到 UTF-16 会退回 UTF-8。也就是说一份 UTF-16 的文件打开能看、一保存就变成
UTF-8 了，而且不报错。手写了那十几行 UTF-16 编码，并加了一条测试断言
`"abc"` 编出来必须是 6 字节 —— 退回 UTF-8 就是 3 字节，一测就露。

#### 日志模式不在 Rust 侧解码

日志走的是另一条路：Rust 只探测出编码标签，解码交给 WebView 自己的
`TextDecoder`。WebKit 原生就带 GBK / Big5 / Shift_JIS 这些表，让 Rust 再解一遍
等于把整块字节多搬一次 —— 而这条是 60fps 滚动的主路径。
`TextDecoder` 按标签缓存，因为它对 CJK 编码的构造并不便宜。

#### 「重新打开」和「另存为」是两件事

状态栏那一格点开是个选择器，里面两个按钮分得很清：
- **重新打开** —— 按新编码重新解码字节（发现乱码时用这个）
- **以此编码保存** —— 只改「将来存成什么」，不动当前内容

解码有损时状态栏那格变红带 ⚠，选择器顶上是一条红色告警：
「保存会把它们永久写成 U+FFFD」。这件事必须说出来，不能只做成一个安静的标签。

### 缩略图：canvas，不是第二套 DOM

CM6 官方没有缩略图。社区包（`@replit/codemirror-minimap`）的做法是**把整份文档
再渲染一遍真 DOM 然后 CSS 缩放** —— 一份两万行的文件在页面上有两套两万行的 DOM，
滚动时两套都要重排。

canvas 版本只画当前窗口里那几百行的矩形，一次重绘是几百次 `fillRect`，
**代价与文档长度无关**。这跟日志引擎里「虚拟滚动 + 只渲染视口」是同一条思路。

长文档画不下时**滑动**：只画一个窗口，位置跟着编辑器滚动比例走。
硬把十万行压进 800 像素，每行不到 0.01 像素，画出来是一团糊，不如不画。

#### 坑：不能在 update() 里读布局

第一版直接在 `update()` 里读 `scrollTop` / `clientHeight` / `lineBlockAtHeight`，
CM6 当场抛 `Reading the editor layout isn't allowed during an update`。

它把一帧切成「读」和「写」两个阶段，正是为了避免读写交替触发的强制重排。
改成 `view.requestMeasure({ read, write })`：量布局排进 read，画 canvas 排进 write。

#### 坑：半透明背景会让长行透出来

缩略图底色本来是 `rgba(0,0,0,.10)`，结果超出宽度的长行从底下透上来，糊成一片。
改成不透明的 `#1e1f22`。VSCode 也是不透明的，现在知道为什么了。

#### 配色只定义一次

缩略图要用和编辑器一样的语法配色，但 `HighlightStyle` 产出的是 **CSS 类名**，
canvas 上没法用。把色表抽成 `HIGHLIGHT_SPEC` 定义一次：编辑器走
`HighlightStyle`，缩略图走 `tagHighlighter`（它能把标签映射成任意字符串，
正好直接映射成色值）。让两边各写一份色值，迟早会走样。

#### 改动标记

缩略图左缘画相对 HEAD 的改动行：绿=新增、蓝=修改、红=删除处。
数据源是 `git diff` 而不是前端自己算 —— 算法现成的，而且和差异视图用的是
同一份输出，两处显示不会打架。

已知的不足：标记反映的是**磁盘上那份**。编辑器里改了还没存时标记不会跟着动。
要做到 IDEA 那种实时跟随，得拿 HEAD 版本在前端跑一遍 diff，那是另一件事。

### 顺带：把 LogPane 也改成按需加载

量入口包时发现 `LogPane` 一直是**静态引入**的，而 `Editor` 是按需的 ——
等于只写代码的人一直在为整套日志视图（虚拟滚动 + 过滤条 + 8 种格式的解析着色）
付钱。改对称之后：

| | 入口包 |
|---|---|
| M12 | 120.0 KB |
| M13 完成时 | 133.5 KB |
| M14 加完编码 + 缩略图 | 137.4 KB |
| **把 LogPane 也改成按需** | **121.7 KB** |

加了整套 Git、编码、缩略图之后，入口包比 M12 只多 1.7 KB。

顺带纠正一个我自己在 M13 中途报过的数字：当时说「M13 入口包 126.6 KB」，
那是 M13 做到一半时量的，完整的 M13 是 133.5 KB。

### 收尾：GBK 日志满篇「锟斤拷」

编码那套做完之后，拿一份 41MB 的 GBK 日志一试，屏幕上全是「锟斤拷」。

这四个字是有信息量的：**它是 `U+FFFD` 的 UTF-8 字节被当成 GBK 解出来的结果**。
也就是说编码探测成功了（前端确实按 GBK 在解），但字节在到达前端之前
就已经被烙上 U+FFFD 了。

罪魁是 `block::encode`：

```rust
match std::str::from_utf8(clipped) {
    Ok(s) => out.extend_from_slice(s.as_bytes()),
    Err(_) => out.extend_from_slice(String::from_utf8_lossy(clipped).as_bytes()),
}
```

这段代码在「只支持 UTF-8」的年代是完全正确的 —— 那时候非 UTF-8 字节确实就是
坏数据，替换掉是对的。编码支持做进来之后它就变成了错的，而且**没有任何测试会发现**，
因为所有既有测试喂的都是 UTF-8。

改成原样透传，并加了两条测试守着：「非法 UTF-8 字节要原样透传」和
「GBK 字节往返不变」。顺带还省掉了热路径上的一次分配。

一句话教训：**转换必须发生在知道编码的那一层。** `block::encode` 不知道，
所以它就不该转。

### 同源的第二处：GBK 日志里搜中文搜不到

过滤器拿 `spec.pattern.as_bytes()` 去比对文件字节 —— 前端敲的「订单」是 UTF-8 的
六个字节，而文件里是 GBK 的四个字节，永远不会命中，而且**零命中看起来像是
「确实没有」，不像是 bug**。

把 `FilterSpec.pattern` 从 `String` 改成 `Vec<u8>`，由命令层按文件编码先编一次。
logengine 这一层只管字节比对，不掺和编码 —— 它也确实不知道编码。

测试直接用 GBK 字节构造日志，断言「GBK 的『订单』能命中、UTF-8 的『订单』不能」。

## 2026-08-27 · M15 交互打磨

一轮以「用起来别扭」为线索的修复。列在这里的每一条都是使用中真被绊到的。

### 侧边栏开关：位置一致 > 贴着它控制的东西

M12 时把收起按钮从标题栏挪进了侧边栏头部（贴着文件夹名）。结果是：
展开态按钮在 x≈310，收起态在 x≈20 —— 同一个按钮在两个状态间**横跳约 290 像素**，
每次收起再展开都要重新找它在哪。

这两个诉求是不可兼得的：要么位置一致，要么贴着文件夹名。选了位置一致 ——
控件的位置得是肌肉记忆能记住的，而「贴着谁」只是初次学习时的一点便利。

做法是加一条**常驻的 34px 竖条**（IDEA 的工具窗侧边栏就是这个形态），
把开关、文件树、Git、搜索、底部面板都放进去。收起侧边栏时竖条留着。
量下来展开与收起时按钮都在 (4, 43)，**一个像素都没动**。

顺带一个白捡的好处：以前收起侧边栏 = 搜索和 Git 入口一起消失，
现在它们还在竖条上。

### 缩略图：瓦片缓存

三个问题叠在一起，用户的说法是「有点卡、有点丑、有 bug」。

**卡**：每个滚动帧都在做完整重绘 —— 重设 `canvas.width`（等于重新分配并清空
整块位图）、跑一遍 `highlightTree`、再发几千次 `fillRect`。

改成**瓦片**：一次把「当前位置上下共三屏」渲染进离屏画布，滚动时只做一次
`drawImage`。实测（900 行文档，滚过前 30%）：

| | 绘制次数 | 瓦片重渲染 | 平均每次绘制 |
|---|---|---|---|
| 一轮滚动 | 33 | **1** | **0.079 ms** |

瓦片重渲染本身 1.3–3.2ms，但一轮滚动只发生一两次。跳到文档末尾时瓦片
正确未命中并重渲染（1 → 2 次），内容跟着更新。

**bug**：失效键用的是 `doc.length`。把一个字符换成另一个字符时长度不变，
**缩略图就再也不更新了**。这个 bug 只在「改了但没增删字符」时出现，
平时敲字（长度一直在变）根本看不出来。改成自己维护一个文档版本号，
在 `docChanged` 时自增。改动标记同理：以前比的是 `marks.size`，
条数没变但内容变了照样漏。

**丑**：整体压了 0.75 透明度显得灰扑扑；改动标记和代码墨迹挤在一起。
改成 0.92、把改动标记单独给 3px 一列、宽度 84→88。

顺带修了两处会掉帧的写法：滑块改用 `transform` 移动（不再每次触发布局）、
尺寸没变时不再重设 canvas。

### 差异面板：往 `$state` 数组里的原始对象上写，不会触发重渲染

这是「git 显示差异那里有 bug」的根因，也是这轮里最值得记的一条。

```js
const tab = { id, ... };
tabs = [...tabs, tab];   // tabs 是 $state
activeId = tab.id;       // 这里已经渲染了一次，此时 diffRaw 还是 undefined
await reloadDiff(tab);   // 往原始对象上写
tab.diffRaw = raw;       // ← 数据改了，但没有任何信号
```

`tabs` 是 `$state`，数组元素在**读取时**被包成代理。`tab` 这个局部变量拿的是
创建时那个原始对象，往它上面写确实改得动底层数据，**但不产生信号**，
界面不会重渲染 —— 差异面板因此一直停在「没有差异」，直到别的操作
（比如一次 git 状态刷新）碰巧引起一次重绘。

异步流程尤其容易踩：`await` 回来时手上那个引用早已不是响应式的那一份。

修法是加一个 `tabById(id)`，所有异步路径都按 id 重新从 `tabs` 里取。
`openDiff` / `openCommitDiff` / `openMerge` / `toggleDiffSide` / `reloadDiff` 全改了。

（`openPath` 不受影响：它的所有字段都在 push 进数组**之前**填好。）

其余三处差异面板的修复：

- **跳转会跳到空处**：`changeBlocks` 在全部行上算，但只渲染前 3000 行。
  超长差异里按「下一处改动」会滚到一片空白。改成只在渲染出来的行上算。
- **统一视图跳转有累积偏移**：跳转按 `下标 × 19px` 算位置，而 hunk 行带上下
  边框比普通行高 2px。给所有行锁死 19px（box-sizing 是 border-box，边框算在内）。
- **粘性行号栏漏字**：行号列是 `position: sticky` 的，但增删行的背景是半透明的，
  横向滚动时正文从行号底下透出来。用「半透明色叠一层不透明底色」而不是另写
  一组死色值 —— 色值只有一份，以后改 `--diff-*-bg` 不会漏掉这里。
- **暂存后差异变空**：把文件暂存之后改动跑去了暂存区，工作区侧变空，
  标签上只剩「没有差异」，看着像坏了。现在这一侧空了会自动跟到另一侧。

### 分支切换：`git switch origin/foo` 是会失败的

远程分支那一组传的是全名，而 `git switch origin/foo` 直接报
`fatal: a branch is expected, got remote branch 'origin/foo'`。
git 的 DWIM（自动建跟踪分支）**只对短名生效**：本地没有 `foo` 而 `origin/foo`
存在时，`git switch foo` 才会自动建；传全名反而不行。

界面上必须列全名（要区分 `origin/foo` 和 `upstream/foo`），所以这层翻译
得在 gitsvc 里做：本地有同名分支就切它，是远程分支就走 `--track`。
测试真克隆了一个仓库跑完整流程。

**文件树切完分支不刷新**：`children` 缓存只在换项目根时清空。切分支之后
新增/删除的文件在树上看不见。加了 `reloadTick`，重新拉取**已展开的目录**
但保住展开状态 —— 把整棵树收回根节点是最烦人的刷新方式，而刷新最常
发生在切完分支之后，正是最不想丢上下文的时候。

**git 的错误说明是多行的**（「你有未提交的改动，涉及这些文件：…」），
塞进状态栏那一格会被截断成一句没头没尾的话。这类消息改走可关闭的横幅。

### 手感

- **文件树键盘导航**：↑↓ 走、→ 展开/进入、← 收起/回父级、Home/End、↵ 打开。
  同时改成**游标式 tabindex**：整棵树只占一个 Tab 停靠点。以前每一行都是普通
  button，按 Tab 要一个一个走过几百个文件才能离开文件树。
- **标签栏**：中键关闭、滚轮横向滚、切换时把当前标签滚进视野
  （标签多到溢出时，用 ⌘P 打开一个滚出视野的标签，界面上会「什么都没发生」）。
- **Git 日志**：提交列表 ↑↓ 走，过滤框里按 ↓ 直接跳进列表。
- 侧边栏收展加了 130ms 过渡，拖拽时自动关掉（否则是追不上手的橡皮筋）。
- `⌘B` 作为 `⌘1` 的别名 —— 很多人手指记的是 VSCode 那个。
- 竖条上的 Git 图标带未提交改动的小红点，侧边栏收起也知道有东西。

### 开发期：`LITE_IDE_POS=x,y`

多显示器下窗口会记住上次开在哪，而副屏/别的 Space 上的窗口截不到图。
加了个和 `LITE_IDE_ONTOP` 同类的开关把窗口摆到指定位置。

## 2026-08-28 · M18 全面审计：内存 · CPU · 安全 · 架构漂移

不加功能，只做一件事：把「有没有问题」这句话变成有数字的答案。

### 先把基线量出来

打开 1GB 日志（`/private/tmp/big.log`，914 万行）之后：

| 进程 | phys_footprint |
|---|---|
| lite-ide 主进程 | **34 MB** |
| WebKit.WebContent | 105 MB |
| WebKit.GPU | 16 MB |
| WebKit.Networking | 4.5 MB |
| **合计** | **≈ 160 MB** |

ARCHITECTURE §7 写的是 <200MB，兑现了。

**但 `ps` 报的 RSS 是 1,156,816 KB —— 1.1GB。** 这个数字会吓人，得说清楚：
`vmmap` 里那 1040MB 全在 `mapped file` 一栏，是 mmap 进来的**干净的、
文件背书的页**，内核随时可以回收，不占 swap。Activity Monitor 的
「内存」列看的是 phys_footprint（34MB），`ps` 的 RSS 看的是驻留页总数。
**报内存别报 RSS**，对 mmap 型程序它没有意义。

### 一个真实的内存问题：`git diff` 没有上限

一个 30MB 的新增文件，`git diff` 原样吐 30MB。这份文本要走
JSON 序列化 → IPC → `JSON.parse` → `parseDiff` 解析成行对象。实测：

| | 过 IPC | 解析+双栏 | 堆增 | 行数 |
|---|---|---|---|---|
| 修之前 | 30 MB | 57 ms | **+114 MB** | 400,001 |
| 修之后 | 1 MB | 2 ms | +5 MB | 14,534 |

而差异面板**最多只渲染 3000 行**。也就是说，为了三千行付了一百多兆，
而且这还没算 IPC 那一程（30MB 的 JSON 字符串在 WebView 里 parse 成
UTF-16 是另外 60MB 的瞬时占用）。

`gitsvc::MAX_DIFF_BYTES = 1MB`：piped stdout 只读 `cap+1` 字节（多读一个
用来区分「正好读满」和「后面还有」），超了 `child.kill()`，再切回最后一个
完整换行 —— 切在半行上，前端会把那条残行当成一条真改动画出来。
截断后仍有 14,534 行，是渲染上限的四倍多，正常文件根本撞不到这道闸。

配套两条：被自己掐掉的进程**退出码没有意义，不能当失败**；`truncated`
一路传到界面，因为**一份看着完整、其实少了后半截的差异比一句「显示不下」危险得多**。

### 一个真实的泄漏：`await` 之后才装的定时器没人清

`LogPane` 的过滤 effect：

```js
const timer = setTimeout(async () => {
  const active = await logFilter(...);   // ← cleanup 可能正好在这中间跑
  tick = setInterval(pollStat, 80);      // ← 装出一个再也没人清的轮询
}, 180);
return () => { clearTimeout(timer); if (tick) clearInterval(tick); };
```

cleanup 只能清掉它**当时看得见**的东西 —— 它跑的时候 `tick` 还是 null。
在 1GB 文件上连打十个字，就是十个 80ms 的轮询一起烧 IPC。
（它们最终会因为 `fs.complete` 自己停下，所以表现不是「卡死」而是
「打字时莫名其妙地卡一阵」，这类症状最难往泄漏上想。）

加一个 `dead` 标志，cleanup 里置位，每个 await 之后先判。

### 安全：CSP 一直是 `null`

`tauri.conf.json` 里 `"csp": null` —— 完全没有 Content-Security-Policy。

现状没有活的注入点（全仓库零 `{@html}`、零 `innerHTML` 赋值，`main.ts`
那处是 `= ""` 清空），所以这不是「正在被利用」，是**没有纵深**：
Tauri 里的 XSS 不止是弹窗，它直接等于拿到全部 IPC —— 任意读写文件、起子进程。
而 xterm 处理的是子进程的原始输出，CM6 渲染的是任意文件内容，
这两个都是「喂不可信数据」的组件。

收紧成：

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data:; font-src 'self'; connect-src 'self' ipc: http://ipc.localhost;
object-src 'none'; base-uri 'none'; frame-src 'none'
```

`style-src` 必须留 `'unsafe-inline'`：CM6 和 xterm 都在运行时往 head 里插
`<style>`。这是有代价的妥协，但 `script-src 'self'` 才是挡 XSS 的那一条。

两件配套的事：

1. **`vite.config.ts` 的 `server.headers` 也加同一条**。理由和 mock-ipc 一样 ——
   只有打包后的壳带 CSP 的话，这类问题得等 45 秒的 Tauri 构建才撞得上。
2. **`main.ts` 挂 `securitypolicyviolation` 回传 diag**。CSP 挡下东西
   *不触发* `window.error`，被挡的资源就那么静静地没加载，界面上只表现为
   「某处不好使了」，没有这条通道下次得从零开始猜。

验证方式：`pnpm dev` 下开一个文件（CM6 起来了，Markdown 实时预览、缩略图都在）
+ 开终端（xterm 起来了），控制台零违规。**只看首屏是不够的 —— 那两个组件是懒加载的。**

### 架构漂移：`ts-rs` 那套从来没落地过

ARCHITECTURE §4 白纸黑字写着「Rust 侧结构体用 `ts-rs` 导出到
`src/lib/ipc/types.ts`，**杜绝手写两遍类型定义然后慢慢漂移**」。

**`src/lib/ipc/` 下只有 `commands.ts` 一个文件，仓库里 `ts-rs` 零命中。**
两侧一直是手写两遍，而文档一直宣称这件事有人管。逐字段核对下来
15 个 DTO 目前**碰巧还是一致的** —— 但「碰巧一致」不是能维持的状态：
漏改一侧不报错，只在运行时变成一个 `undefined`，而 `undefined` 在界面上
通常表现为一片空白，没人会往类型上想。

没上 ts-rs（要加依赖、加生成步骤、把生成物提交进仓库，而全部 DTO 只有 15 个
且都在一个文件里），改成 `src-tauri/tests/dto_sync.rs`：**只读源码的一条测试**，
解析两边的定义逐字段比，顺带卡住 `#[serde(rename_all = "camelCase")]`
（少了它 `line_count` 会原样序列化，而 TS 侧写的是 `lineCount`）。
新 DTO 必须在 `PAIRS` 表里登记一行，忘了就红。

按 AGENTS.md 的规矩验过会失败：把 TS 侧 `lineCount` 改成 `lineCountt`，
测试报 `StatDto ↔ LogStat 字段对不上：只在 Rust ["lineCount"] / 只在 TS ["lineCountt"]`。

### 一条说过头的注释

logengine 里 mmap 那处写的是「外部进程截断文件可能导致 SIGBUS，
**由 logrotate 检测（inode / size 变化）负责规避**」。

规避不了。那个检测是 500ms 一次的轮询，只能事后发现「文件被换掉了」，
拦不住扫描线程正踩着的那一页。真要堵死得装 SIGBUS handler + siglongjmp，
对个人工具不值当。改成如实写风险 + 写清楚为什么接受它
（less / lnav / glogg 全是这个模型；logrotate 是改名+新建，老 inode 还在，
真正危险的是原地截断 `> app.log`，那本来就少见）。

**错的注释比没有注释更害人** —— 这条在 AGENTS.md 里写着，这次是自己撞上。

### 顺手：7 条被无视的警告

`FileTree.svelte` 每渲染一行就警告一次
`bind:this={els[i]} is binding to a non-reactive property`，一次展开刷七条。
它本身没造成 bug（`els` 只在事件处理里读），但**七条噪声足够把真警告埋掉**。
而且 `{#each}` 是按 `row.path` keyed 的，下标和数组位置对不上。

改成从容器里 `querySelectorAll('[role="treeitem"]')[i]` 取 —— 按方向键是
人手速度，不值得为它维护一个和 keyed each 对不齐的数组。
键盘导航实测仍然对：↓ src→logs→docs，↑ 回 logs，→ 展开（7 行→8 行）。

### 一条被推翻的旧结论：ptysvc 那个挂起

AGENTS.md 里写着「根因不在本仓库」，依据是**用纯 Python 的 `pty.fork()`
写同样的复现，一样会挂**。今天重跑了这个复现：

```
/usr        读不到 pwd：0/10
/tmp        读不到 pwd：0/10
临时目录     读不到 pwd：0/10
$HOME       读不到 pwd：0/10
```

**40/40 全过。** 顺带量的登录 shell 启动：`zsh -l -c pwd` 0.07s、
`zsh -l -i -c pwd` 0.17s —— 一点都不慢。

而 Rust 那边 `cargo test -p ptysvc` 连跑三次挂了一次（三次重试全超时，
白烧 75s）。旧文档还写着「加上重试之后连跑 8 次全绿」，也不成立了。

**没有提交任何猜出来的修复**（记在 [issue #2](https://github.com/Spc-jgs/lite-ide-mac/issues/2)）。
这正是 AGENTS.md 里那条教训说的情况 ——
上一次就是基于错误诊断改了一版，改完看着好了，但把旧写法放回去也一样不挂。
改成把两个数字如实记下来、把那条已作废的结论划掉。

**收尾清理临时文件时又翻出一件事**：那个「在三处各打时间戳」的插桩
**其实早就做过了**（我在 issue 里写「至今没人做过」，错了）。正常运行
`spawn` 4.6ms、起 shell 到吐提示符 186ms、`Drop` 54.7ms，整条链 0.19s ——
所以挂住时不是慢，是彻底不动。

**但它从来没抓到挂住的那次**：`with_deadline` 超时后把那个线程丢掉了
（注释里写明「故意不 join」），它攒着的 `eprintln!` 输出跟着一起没了。
每次挂住，恰恰是唯一有诊断价值的那次，什么都留不下。
下一步是把探针改成**边跑边往文件里追加并 flush**。

CI 那边不用改：`cargo test --workspace` 那一步已经单独设了 25 分钟超时，
挂的时候是**红**而不是把整个 job 的额度吃光。代价是 CI 会有大约三分之一
的概率红在这条上。

### 行缓存原来只按块数限，不按字节限

`LineCache` 的上限是「最多 96 块」，注释写着「512 × 96 ≈ 5 万行，几 MB 量级」。
那个估算暗含一个前提：**每行一百来字节**。

而日志模式的触发条件之一恰恰是 `maxLineLen > 10k`（ARCHITECTURE §1）——
长行文件是这个模式的**目标用户**，不是意外情况。一份每行 10KB 的访问日志
（带完整请求体的那种，Java 后端很常见），滚过 49,152 行 =
缓存里躺着 **480MB**。而 §7 写的是「1GB 日志常驻内存 < 200MB，
**与文件大小无关**」—— 按块数限，这条保证只对短行文件成立。

改成两条同时生效（`src/lib/logview/cache-budget.ts`）：块数超了一定驱逐；
字节超了也驱逐，但至少留 4 块。为什么要保底：光按字节限会走到另一个极端，
10KB/行时 8M 字符只够 1.5 块，装不下一屏上下文，滚动会来回抖。

长行文件的最坏占用因此变成 `4 × 512 × 行长`，10KB/行时约 40MB，有上限。
而普通日志塞满 96 块也才 590 万字符，**撞不到字节线，行为一个字都没变**——
测试里专门钉了这一条，改坏了会红。

单独拆成 `cache-budget.ts` 是为了能被 `tests/` 直接跑：`line-cache.ts` 引了 IPC，
裸 node 加载不了它。这个文件里只有纯计算，零 import。

### 没改的那条：⌘P 模糊匹配

5 万文件时 14–21ms/击键，超过 16ms 帧预算。拆开量了一遍才发现**猜错了热点**：
`toLowerCase()` 只占 1.3ms，真正的开销在 `isBoundary` 对**每个候选字符**
做单字符 `toLowerCase()`（候选数是 `文本长度 × query 长度` 量级，
所以 query 越长越慢：`handler` 20.8ms > `ha` 14.0ms）。

没顺手改：`fuzzy.ts` 是个**打分函数**，而它一条测试都没有 ——
改动很容易在不报错的情况下把排序质量弄差。连「只优化排序」都不是零风险
（V8 的 `sort` 稳定，同分保持插入顺序，朴素 top-K 堆会打乱它）。
先补刻画测试再动，那是独立一件事。记在
[issue #1](https://github.com/Spc-jgs/lite-ide-mac/issues/1)。

## 2026-08-28 · M19 第二轮扫：UI、交互与「装了不生效」

M18 那轮偏内存/安全/架构，这轮换角度：实际把界面驱动起来看。
三个问题都属于**不报错、不崩溃、只是不对**的那一类。

### 一、⌘J 收起面板会杀掉正在跑的 shell

`{#if panel}` 包住整块底部面板，收起时 Terminal 组件跟着卸载，
effect 清理里的 `ptyKill` 就把 shell 带走了。跑着 gradle build 时
按一下 ⌘J 腾地方，构建当场没，且没有任何提示。

**同一份代码在下一层已经想到过这件事**：切「终端 ↔ Git 日志」用的是
`class:hidden`，注释写着「组件一销毁 Session 就 drop，shell 直接被 kill」。
Terminal.svelte 里那句 `catch { /* 面板收起时容器为 0，忽略 */ }` 更说明
作者本来就以为收起只是把容器变成 0。**只是漏了上面那一级。**

浏览器里挂 IPC 桩录调用序列，对照很干净：

```
修前：开 → pty_spawn    收 → pty_kill{id:1}    开 → pty_spawn（新的）
修后：开 → pty_spawn    收 → （无）            开 → （无，复用）
```

留下的判据写进 AGENTS.md：**这个组件的销毁有没有副作用？**
有的话它每一层可见性条件都得是 `class:hidden`，不能是 `{#if}`。

### 二、多光标一直是装了不生效的

`rectangularSelection()` 和 `crosshairCursor()` 都在扩展列表里，
但 `EditorState.allowMultipleSelections` 没设。CM6 的实现里：

```js
let selection = tr.startState.facet(allowMultipleSelections)
  ? tr.newSelection : tr.newSelection.asSingle();
```

**没开这个 facet，每次事务的选区都被压成一个。** ⌥ 拖矩形选择、
⌥ 点加光标、搜索里的「选中所有匹配」三样全废，而扩展照样进包。

在页面里直接 dispatch 一个三段选区验的：去掉那行 → 实际 1 段；
加上 → 实际 3 段。

（顺带一提，验证过程本身有个坑：改完靠 HMR 是测不出来的 ——
`build()` 只在挂载时跑一次，热更新不会重建已有的 EditorView。必须整页重载。）

### 三、窄窗口下双栏差异挤到读不了

760px 窗口下差异区只剩 482px，双栏每列四十来个字符，一行 Java 代码
都放不下，两栏都在横向滚（scrollWidth 790 / clientWidth 482）。
而按钮的 title 写着「统一视图（窄窗口更合适）」—— **一直只是句提示，
从来没人替用户按下去过。**

同时「双栏」「统一」缺 `white-space: nowrap`，断成两行把 28px 的
工具条撑到 34px。

改法上有个取舍值得记：**不直接改 `side`**，而是分成
`side`（用户意图）和 `sideOn = side && !narrow`（实际形态）。
直接改 `side` 的话窗口拉宽后回不去，等于把用户的选择偷偷改掉了。
窄的时候按钮置灰并说明原因 —— 不做一个按了没反应的按钮。

实测 760px：按钮回到 19px，自动切统一，scrollWidth 790 → 513；
拉回 1400px：自动切回双栏，1122 == 1122 零溢出。

### 顺带修的一条控制台噪声

`onDragDropEvent` 的**注销**没兜住。注册那半边早有 catch 和注释
（「浏览器里跑时这个 promise 会 reject」），但拿到的 unlisten 函数
自己也会抛 —— 桩里缺 `__TAURI_EVENT_PLUGIN_INTERNALS__`，
而真实现的 unlisten 走的正是这个对象，不是 `__TAURI_INTERNALS__`。
两边都补：桩补齐对象，清理函数补 `.catch()`。

**桩与真实现分叉就失去了全部价值** —— 这条 AGENTS.md 里写着，又撞了一次。

## 2026-08-28 · M20 会话恢复

重开应用记得上次的现场：项目根、开着哪些文件、光标停在第几行、
几块面板的开合与尺寸。之前 `localStorage` 里只有一个缩略图开关。

### 为什么是这件事

上一轮扫出六个功能缺口，这个排第一：**实现成本最低，但每天都在被它硌一下**。
日志书签和全局替换更「有用」，但它们是偶尔用一次；重开应用要把项目和文件
重新点一遍，是每天开工第一件事。

### 存在哪

`localStorage`。WKWebView 落在 `~/Library/WebKit/com.liteide.app/`，
正是 `scripts/uninstall.sh` 已经在删的三个目录之一 ——
**不给「卸载零残留」增加任何新义务**，也就没必要为它另建一套配置文件。

### 明确不存的三样

- **文件内容**。存了就等于在应用外面再放一份真相，下次打开时它和盘上的
  文件谁对？这个问题没有好答案，干脆不进这个坑：恢复出来的永远是盘上当前的样子。
- **日志过滤条件**。状态重（级别位 / 关键字 / 大小写 / 折叠），而且下次打开
  那个日志多半是为了看新的东西，把上次的过滤扣上来反而要先想一下
  「为什么只有这几行」。
- **终端**。pty 是活的子进程，跨进程恢复不了，假装能恢复只会更糟。

### 踩到的三个坑

**一、位置记晚了，整个不生效。** 原本在 `openPath()` 之后才把行号写进
`pendingPos`。但 `openPath` 一把标签加进去 `activeId` 就变了，兑现位置的
effect 当场就跑 —— 那时 Map 还是空的。等写进去时 `activeId` 不会再变，
effect 也不会再跑。改成**先记位置，再开文件**。

**二、光标移动不触发保存。** `posByPath` 故意做成普通 Map（每换一行写一次，
做成 `$state` 等于每换行惊动一次渲染，而界面上没有任何地方要显示它）。
但这样一来改它不产生信号，保存的 effect 收不到 —— 于是
「开文件 → 滚到第 5000 行 → 退出」这条最典型的路径什么都没存下，
而快照看着还挺正常。改成 `markPos` 自己调 `scheduleSave()`。

**三、恢复还没开始，就先把空状态写回去了。** 保存的 effect 在挂载时就跑一次，
而 `restoreSession()` 要等 `initialPath()` 这个 IPC 回来。400ms 的防抖一到，
一个「什么都没打开」的空快照就盖掉了上次的现场。本次运行看不出问题
（`saved` 早在初始化时同步读进内存了），但恢复途中退出就真丢了。
加 `restoring` 守卫。

### 命令行路径的规则改了一次

一开始定的是「命令行给了路径就不恢复」。做完想了想不对 ——
`code a.js` 的行为是**在现有窗口里打开它**，不是把工作区清空。改成：

- 指的是**文件**：先恢复现场，再把它开在上面
- 指的是**另一个目录**：那是在切项目，旧项目的标签铺过来只会碍事
- 同一个目录 / 没给：照常恢复

### 顺手修的桩

桩的 `probe_path` 对**任意**路径都返回一个假文件。于是「打开一个不存在的
文件」这条路在浏览器里根本走不到，而真实现是直接 Err ——
会话恢复恰恰高度依赖这条路（上次开着的文件这次可能已经删了、或切分支没了）。
改成不认识的路径就报错。

**又是「桩与真实现分叉」**。这条 AGENTS.md 里写着，M19 撞过一次，这次是第二次。
