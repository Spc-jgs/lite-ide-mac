# 界面写法定死了，新界面照这套来

**新加任何界面先读这一节**，不要另起一套 —— 下面每一条都是从已经统一过的那几处里
挑出来的、真的出过问题的地方。

**通用控件先看画廊再动手**：`pnpm dev` 下开 `http://localhost:1420/?gallery`
（`src/lib/dev/Gallery.svelte`），文字按钮 `.btn`、图标按钮 `.ibtn`、全部 `Icon`、四个交互态
的底全在一屏上。三条硬规矩：**有现成的就用现成的；加了新变体 / 新图标必须出现在画廊里；
组件里只写语义和尺寸档，不写宽高圆角颜色**。不在画廊里的控件，就是下一个「各写各的」——
M9 之前文字按钮九处各写各的、2026-09-18 之前图标按钮九处各写各的，都是这么长出来的。

**界面上「冒出来的东西」的十条通则**（2026-10-13 盘点全应用弹出物之后定的，用户要求以后都照这个；具体做法在第十二、十四、十五条）：

1. **结果说在眼睛在的地方。** 发起它的按钮还在 → 按钮原地说；不在了 → 编辑区底部的胶囊；要读多行或要你决定 → 卡片。不放视野边缘的状态栏。
2. **颜色说结果。** 做成了 / 没做成 / 什么都没发生（只说为什么）三档三种样子；「什么都没发生」是中性灰，不画成成功色。
3. **坏消息不被好消息顶掉。** 失败那条没读完时随后的成功不顶掉它；停多久按字数；鼠标停上去不走；能点掉。
4. **同类弹层位置固定。** 居中的上沿钉在一条线上、往下长；宽度只分三档；由控件点开的挂在控件底下。
5. **叠放有上限、按严重程度排。** 出错 > 要你决定 > 做完了；一个宽度、左右对齐；超过两张折成「还有 N 条」。
6. **进场帮人看清从哪来，退场只给「消失会让底下跳」的**（压暗层、叠着的卡片、胶囊）；菜单、浮层瞬没。**正在退场的不再算「在」**：不拦输入、不接鼠标。
7. **模态就要真模态。** 对话框开着时键盘、鼠标、菜单都拦，被拦的那一下给反馈（顶一下、焦点回默认按钮）。
8. **等待 150ms 之内不出现。** 环和那句「正在…」一起延迟；按钮在忙 / 刚做完时宽度不变、颜色不灰掉。
9. **空态 = 为什么空 + 下一步**，下一步照实说。
10. **一处定义。** 位置、宽度、动效、空态、提示都是 app.css / 共用组件里的原语，组件里不各写各的。

## 一、「当前项」只有一种长相：内缩的圆角块

文件树、大纲、随处搜索、分支面板、标签栏、Git 日志的提交行与文件行，全部是
内缩 + `--r-sm` + `--selected`。**不许用通栏色条，也不许用下划线。**
（2026-09-16 M8 起圆角从 `--r-md` 统一成 `--r-sm`：标签本来就是 r-sm，行用 r-md
两边挨着一眼看得出不是一套；`--r-md` 留给浮层和卡片。Git 日志的行原来是通栏色条，
一起改了。）

## 一之二、控件一个尺度

M8（2026-09-16）用户指着四处说「不协调」：侧边栏头的三个小图标、标签栏、面板头的
标签页、Git 日志的详情栏。病根一样 —— 每块面板的头各有各的按钮尺寸、圆角、图标大小。
现在只有一套：

| 元素 | 高 | 圆角 | 图标 |
|---|---|---|---|
| 各区的头（侧边栏头、标签栏、面板头、Git 面板的头） | **38** | — | — |
| 岛内的工具栏（Git 日志过滤条、详情栏的头、Diff 头、合并视图头） | **34** | — | — |
| 头里的工具按钮（定位 / 折叠 / 跟随 / ＋ / ⌄ / ⋮ / —） | **24×24** | r-sm | 16 |
| **文字按钮** `.btn`（app.css）/ `.btn.sm` | **28 / 24** | r-sm | 字 13 / 12 |
| 浮层、菜单、卡片 / 对话框 | — | r-md 12 / r-lg 14 | — |
| 菜单行、浮层里的列表行 | 28 | r-sm | 16 |
| 导轨按钮 | 26×26 | r-sm | 16 |
| 编辑器标签 / 面板标签页 | 28 / 24 | r-sm | 16 |
| 列表行（文件树、Git 日志这类常驻的密集列表） | 22–24 | r-sm | 16 |

**图标一律 16，组件里不传尺寸**（2026-09-24）：JetBrains 的图标按 16 的网格画，原来各处传的 10–17
七种尺寸一起去掉了。文字按钮同一天从 24 / 20 放大到 28 / 24：字号收成四档后 24 高塞 13 号字太挤，
IDEA 的文字按钮就是 28。文件树每层缩进 19 = 箭头 16 + 间距 3，子项的箭头落在父项图标底下。
小块（键帽、面包屑、项目方块）的圆角用 `--r-xs` 4。

两栏并排时**第一行必须在同一条水平线上**：侧边栏头 = 标签栏 = 面板头 = 38，
Git 日志的过滤条 = 详情栏的头 = 34。岛里不再抬第二层浅色板（Git 日志详情栏原来压着
`--hover`，看着像另一个面板），分区只靠一条 5% 的线。

**文字按钮只有 `.btn` 一套**（M9，2026-09-16）。之前九处各写各的：Git 页「提交」11.5px
实心、空态 11.5px 灰底、分组头 10.5px 透明、确认卡片 11.5 描边、合并视图头 11 描边、
冲突块 10.5 描边、Diff 头 11 分段、文件树空态 12 描边 —— 一屏四种高度四种字号三种底色。
`.btn` 分两层：尺寸（28 / `sm` 24）和语义（默认 = 普通，**实心浅灰底、无描边**；`primary` = 这一排里那一个
主动作，accent 实心；`quiet` = 无底，给分组头 / 行内不该抢眼的；`danger` = 你要做的就是这件不可逆的事，红实心；
`destructive` = 浅灰底红字，**会丢东西、但不是你点的那个动作本身**，比如关脏标签时的「不保存」）。
**组件里只写语义，不再写尺寸** —— 尺寸写进组件就是又一套。分裂按钮用 `.btn-split`。

**默认按钮从描边改成实心浅灰**（2026-10-12 设计稿④）：描边按钮在深色底上读成「一个框」，实心的才读成「一个能按的东西」——
macOS 的系统按钮、Claude / Codex 的次要按钮都是实心的。`danger` 和 `destructive` 的分法照 Apple HIG · Alerts：
破坏性样式给**没想到会有**的后果；人本来就想删的，按钮写「删除」就够了，用实心红是因为它不可逆（第七条）。
工具条上自己画的开关按钮（日志的「折叠堆栈」「跟随尾部」）同一个样子：关着实心浅灰，开着淡强调色底，不描边。

**图标按钮只有 `.ibtn` 一套**（2026-09-18）。和 `.btn` 同一个分层：尺寸 24（各处头里的工具按钮）/
`sm` 20（行内动作）/ `xs` 16（标签块里的 ✕、图钉）/ `lg` 26（**只有导轨**）；语义默认无边灰字，
`on` 是开关态（中性白 `--selected`，accent 留给「有改动」那类状态）。之前九处各写各的：三份
`.hb`、`.phbtn`、`.sbtn`、`.rowact`、`.pt-x` / `.close`（圆角 5px 而不是 r-sm）、两对跳转按钮 ——
五份 24px 的复制品、三种小尺寸各不相同。图标按钮里的图形一律 `<Icon>`，**不用字体里的符号**
（✕ ⋯ ⇄ ↺ ⌃ 都换掉了）：字体符号的粗细、基线和 svg 图标并排时对不上。

标签栏原来是 IDEA 那套（平角 + 底下 2px accent 线），换掉有两个理由：
一是那条线在半透明的外壳上飘着，二是标签栏和文件树紧挨着，
「当前项」在两边长得不一样，人会以为它们是两种东西。

## 一之三、圆角跟着「它是什么」走，不是每样都给 7px（2026-10-13）

用户说「该圆的圆、该直角的直角」。查下来问题不在大面上（岛、浮层、按钮都对），在**贴着字的东西**被当成控件给了 7px：
差异视图里改动的那几个字、日志里的搜索命中，一串高亮像一颗颗胶囊；差异那处还带 1px 左右内边距，把后面的等宽字推歪了一列。

| 它是什么 | 圆角 | 例子 |
|---|---|---|
| **贴在一行字里的**：标出几个字 | **直角或 2px，不加内边距** | 差异的行内改动（直角，同 IDEA / VS Code）、日志搜索命中、文件树的匹配字（2px） |
| 行里的一小块 | `--r-xs` 4 | 折起来的「…」、键帽、ref 标签、面包屑 |
| 控件和列表行（24–28 高） | `--r-sm` 7 | 按钮、输入框、分段控件、内缩的选中块（第一条） |
| 浮起来的面 | `--r-md` 12 / `--r-lg` 14 | 菜单、浮层、卡片 / 对话框 |
| 胶囊 | **99px，写成 99px** | 计数角标、提示胶囊、「还有 N 条」、滚动条滑块 —— 不靠「高 14 时 7px 刚好像胶囊」 |
| **一整行铺满、上下连着的** | **直角** | 差异的增删行底色、块头那条带、编辑器当前行、状态栏、标题栏 —— 一圆角，上下两行之间就多出一个缺口 |
| 岛 | `--island-radius` **12**，`overflow: hidden` 裁住里面 | 编辑岛、侧边栏、底部工具窗：里面铺满的东西（当前行、差异行）是直角，靠岛裁出圆角 |

**岛为什么是 12（同心）**：外层半径 ≈ 里面贴边那一圈的半径 + 间距。岛里贴边的是标签块（圆角 7，离岛边 5～6），7 + 5 ≈ 12。
原来是 8：标签块和岛几乎一样圆，放大看像两块没对齐的板叠着。岛的角不和窗口共角（上有标题栏、下有状态栏、左有导轨），所以不按「窗口圆角 − 缝」算。
以后改了标签块的尺寸或内边距，这个数跟着算一遍。

**内层不比外层圆**：卡片 12 里的按钮 7、输入框 7；里外一样圆、或者里面更圆，看着像两块没对齐的东西叠在一起。

**空态不浮起来**：没打开文件时编辑区中间那块原来是浮层那副样子（亮底、投影、外描边），和对话框一模一样，像在等你回答。
现在直接印在岛上（IDEA、VS Code 的空编辑区都是这样）。**亮底 + 投影只给真的浮在内容上的东西**：浮层、菜单、卡片、对话框、胶囊。

## 二、不要用分隔线表达「这是一格」

八个标签就是八道 1px 竖线 —— 那是**表格**的语言。当前项已经由一块底色
说清楚了，再画线就是同一件事说两遍，而线是常驻的、底色只有一块。

线只用来分**区**（标题栏／内容／状态栏之间），不用来分**项**。

**2026-09-16（M8）起连分区也不靠线了**：外壳（导轨、标签栏、标题栏、状态栏）
之间**一条线都不画**。内容层收成内缩 `--island-gap`（6px）的
圆角岛（`--island-radius` 8px、`--island-border` 5% 描边），岛与岛之间那条缝就是
分隔，也正好是拖拽热区（平时不画线，悬停 / 拖动才亮 accent）。

**岛按「是什么」分，不按「在哪条边」分**（2026-09-18）。M8 第一版把侧边栏归到外壳
（平的、不画边），把底部工具窗归到岛 —— 用户一眼看出来「侧边栏和底栏、主区不是一套 UI」。
它们是同一种东西：IDEA 里 Project 和 Terminal 是同一个 tool window 挂在不同的边，
VS Code 里 sidebar 和 panel 都是 view container。所以**编辑器和所有工具窗（侧边栏、底部）
都是岛**，同一套描边、圆角、底色、间距；外壳只剩导轨、标题栏、标签栏、状态栏。

为什么：原来三条竖线四条横线两种亮度混用，侧边栏头 30px 和标签栏 38px 的横线在竖线
两侧差 8px 接不上；内容层本来就比外壳深一档，边上再压一条亮线等于同一条边说两遍。
玻璃材质上用线分玻璃，本身就在和材质打架 —— 边界该由「面」的形状表达。

配套的三条：侧边栏各视图的头一律 **38px**（和标签栏齐平，两块第一行在同一条水平线上）；
岛**里面**的分区线（Git 日志的详情栏、日志过滤条）一律 `--border-soft`，不用 9% 的；
底部工具窗的头在岛里，画 `--content-bg`（头和内容是同一件东西的两层，不隔缝）。

## 二之二、浮层的外框：亮一档的面 + `--pop-ring`；要你回答的是对话框，告诉你的是卡片

**浮层的面**（2026-10-12 设计稿④）：`--elevated` 比内容区亮一档（#2a2a2e，内容区 #1e1f22），外框是 `--shadow-pop` +
`--pop-ring`（0.5px 的外描边 + 顶边一道内高光，「光从上面来」）。原来是和内容区只差一档的底 + 5% 描边，浮不浮起来全靠阴影。
右键菜单、分支浮层、随处搜索、补全弹层、终端查找条、文件树的小面板都是这一个面，**组件里不再自己写 border 和阴影**。
菜单里的分隔线两侧各内缩 10px（macOS 原生菜单就是这么画的），标题下面不画线。

**输入框一个样子**：`--field-bg`（6% 白的底）、静止时边是透明的（`--field-border`）、r-sm，聚焦时边变强调色、外面一圈 `--focus-glow`（macOS 文本框）。2026-10-19 起静止时不描边：输入框都在岛或浮层里，外面已经有一层边（第十七条）。九个组件原来各抄一份这三个值，现在都引令牌。
不是把边描成实蓝 —— 浮层一打开焦点就在输入框里，那圈蓝永远亮着等于没有信息。浮层顶上的搜索是例外：
一整条、底下一道线，不画框（随处搜索、分支浮层、任务列表都这样）。

**两种问人的方式**（2026-10-12 设计稿①，`Confirms.svelte`）：

| | 长相 | 给谁 |
|---|---|---|
| **对话框** `.dialog` | 编辑岛压暗、正中偏上、标题是问句、一句后果、按钮行；焦点给 `data-default` 那个按钮，关掉后还给原处 | **你刚做的那个动作引起的选择题**：关脏标签、切大文件到编辑模式、丢弃改动、撤销一块、删分支、移除工作树、切分支被挡住、信任仓库、分岔要选合并方式、推送确认 |
| **卡片** `.confirm` | 浮在编辑岛顶上、不压暗 | **告诉你一件事**和**启动时冒出来的**：替换做完了（带撤销）、报错、外部改过、上次的任务没停干净、上次替换被中断 |

分法照 Apple HIG · Alerts：别为了告诉人一件事弹对话框；别在应用启动时弹。原来全是卡片 —— 一条横在代码第一行上的长条，
文件名和三个按钮挤在一行里，像工具栏，看不出「要你先回答」，还盖住正文。
对话框的标题写**问句或后果**（「要保存对 README.md 的改动吗？」），按钮写**动词**（「保存 / 不保存」，不写「确定」）。
有丢东西后果的对话框，`data-default` 给「取消」—— 回车不该顺手确认；分岔这种两边后果不一样的，也给「取消」，不替人选。
点暗处不关：选择要按按钮做，Esc = `data-dismiss` 的那个。

**对话框开着时，整个窗口只认它**（2026-10-13 code review，`shell/modal.ts`）。压暗只是告诉人「先回答这个」，原来键盘和菜单照样生效：
⇧⇧ / ⌘P 的浮层叠到压暗层上，⌃Tab 切到 B 而对话框问的还是 A。现在照 macOS 的表单（sheet）挡整个窗口：键盘只放回车 / 空格 / Esc / ⌘C ⌘A，
Tab 在对话框的按钮之间转圈；点对话框外面（侧边栏、状态栏、标题栏上的挂件）不算数，只放过拖窗口；菜单动作（除了退出）和「在草稿本新建」都不做。
**被挡的那一下要有反馈**：对话框顶一下（放大 1.5% 再回来，160ms），焦点回到默认按钮 —— 没有反馈，被挡和「快捷键坏了」长得一模一样。
压暗的范围还是只盖编辑岛（问的是这一块里的事），挡的范围是整个窗口：看的是「问什么」，挡的是「先答完」。
同一个对话框换了问的对象（「关闭全部」逐个问）要把焦点放回默认按钮：`use:takeFocus={id}`，块不重建、不传 id 的话焦点停在上一下按过的按钮上。

卡片不再是撑开内容区的通栏横条（M8）—— 横条会把编辑器整体往下推一行，人正盯着的那行跳走了。
带色的两种（`warn` 要你决定 / `bad` 出错）把色罩叠在 `--elevated` 上，卡片仍然不透明。

## 三、常驻的只留「不看会出错」的那些

判据就这一句。落到那四处：

| 常驻 | hover 才出 |
|---|---|
| 未保存改动的圆点（关掉要问你） | 标签的 ✕ |
| git 状态字母 M/A/?/! | 改动行的 ＋ − ↺ |
| 分支名、改动条数 | 「⋯」里那些 |

**圆点和 ✕ 占同一个格子**，hover 时原地互换 —— 点击目标不许跳位置。

**预览标签名字斜体**（VS Code 的约定，issue #33 ⑯）：单击树 / 搜索命中 / ⌘B 开的
是预览，同时最多一个，再开一个预览就顶掉它；双击、编辑、⌘P 按名打开都保留（不再是预览）。钉住是另一件事：图钉占 ✕ 的位置，排最左，⌘W 和批量关闭都跳过（issue #33 ⑰）。
除了斜体，它和普通标签长得一样 —— 「临时」这件事只需要一个信号。

**这条管的是「每一项上重复出现」的东西。** 上表四行全是这个形状：
每个标签一个 ✕、每一行改动一组 ＋ − ↺ —— 常驻它们等于满屏噪音。
**整条栏上只有一个的入口不在此列**，标签条末尾那个「新建草稿」的加号就是
（2026-09-09 加的）。它常驻，因为它不是某一项的附属物，
藏起来等于这个功能只剩快捷键。

## 四、分组头要吸顶，而且每行还得能自证类别

分组头 `position: sticky; top: 0`，底色跟着所在层走
（外壳层用 `--panel-bg`，浮层用 `--elevated`；填死色会在滚动时拖出一条实心带）。

**但吸顶不够。** 分支面板最长几十行，滚起来只看得见一个分组头 ——
所以每行还要有自己的图标（本地分支／工作树／远程／操作四个形状）。
原来四种条目共用一个 9px 空心圆，只靠边框颜色区分，12px 的行里那点色差读不出来。

## 五、浮层的骨架是固定的

搜索和分支面板现在是同一副骨架，以后的浮层照抄：

```
输入（16px 图标 + 15px 字，排第一）
范围／过滤（分段控件，紧贴输入）
分组结果（吸顶头 + 内缩圆角行 + 每行图标）
脚栏（键位提示，--chrome-scrim 打底）
```

分支浮层（M9 之二）照 IDEA 的 popup 在这副骨架上多了两样：**输入框下面先是动作**
（更新项目 / 提交 / 推送 ─ 新建分支 / 检出标签或提交 / 新建工作树，带键位、和分支一起搜），
**分支按 `/` 前缀折成文件夹**（`feature/` 底下三条），分组头和文件夹都能折。
「最近」一组是最近切到过的（`branches-ops.noteRecent`，按仓库存 localStorage，5 条）。

**输入排第一**：面板打开之后的下一个动作永远是打字，
而范围十次里有九次不用改。键位提示是「忘了才看」的东西，放脚栏 ——
它顺带给了面板一个下边界，不然结果列表是直接切在圆角上的。

脚栏的 `↵` 说明**按当前项变**（分支说"切换"、远程分支说"检出"、工作树说"打开"）。

## 六、同一个信息只印一遍

Git 栏原来「工作区干净」印了两遍（折叠的提交按钮里一遍、列表空态里一遍）。
随处搜索原来每行都印一个「文件」「操作」胶囊 —— 七行结果七个胶囊，
而分组头本来就说清了。

**空态要给下一步，不是给句号。** 干净时唯一还能做的事是看历史，就把它放出来。

## 七、不可撤销的动作不许和可逆的并排同色

「全部丢弃」原来和「全部暂存」并排、同样大小、同样颜色，中间隔 2px。
现在它进了「⋯」菜单并带 `danger`。**误点的代价不该只隔着 2px。**

## 八、图标只有一处定义，而且是 IDEA 的那一套

- `Icon.svelte` —— 界面图标（侧边栏、刷新、勾、加号、箭头…）
- `FileGlyph.svelte` —— 文件 / 目录图标（按类型上色；目录按角色：源码根、测试根、资源根、包、排除）

**2026-09-24 起两套都是 JetBrains 新 UI 的官方图标**（intellij-community `platform/icons/src/expui/`，
Apache 2.0），文件在 `public/icons/`，许可和逐个来源在 `public/icons/SOURCES.md`。之前是自绘的 32 个：
规矩是齐的（16 网格、1.25 描边），但形状是我们画的，和 IDEA 并排一眼就看出不是一家。

四条：

- **加图标先去上游找**，找不到才自绘，自绘的在 `SOURCES.md` 里标「自绘」（现在只有 `tag` 一个，暂代）。
  上游一个图标 = `public/icons/<名字>.svg` 放一个文件 + `ICON_NAMES` 加一行 + `SOURCES.md` 记一行。
  **看清图标的本意再对名字**：`nodes/tag` 是 XML 标签 `<>` 不是 git 标签，`fileTypes/scratch` 是叠加用的角标 ——
  两个都是第一版对错了、在画廊里才看出来的。
- **单色的走 CSS mask，彩色的画背景图**：mask 只取形状，颜色是 `currentColor`，所以跟着 hover / 选中变；
  背景图画文件里写死的颜色。深灰填充 + 浅灰描边的双色图标（文件夹）也得画背景图，mask 会把它糊成实心。
  **彩色名单写在 `Icon.svelte` 的 CSS 里**（`[data-n=…]` 属性选择器），不在 JS 里：这个组件在入口包，名单写在 JS 里每加一个名字入口就涨十几字节（2026-10-20 挪的，原来是 `<img>` + 一个 Set）。
- **不内联进 JS**：`Icon.svelte` 在入口包里，六十多个 SVG 内联就是 60 KB。也别 `import x from "./x.svg"` ——
  小于 4 KB 的 Vite 会内联成 data URL 塞回 JS。
- **图标颜色说类型，文件名颜色说 git 状态**。原来文件图标是单色的，理由是「颜色通道被 git 占了」——
  那是把两个元素当成了一个通道。

`FileGlyph` 是 2026-09-04 从 `FileTree.svelte` 里收出来的，因为标签栏和
随处搜索也要用：**同一个文件在三个地方出现，不能长三个样。**

编辑器查找条那种裸 DOM 拼的面板，用 Svelte 5 的 `mount(Icon, { target })` 把组件挂进按钮，
不另抄一份；`destroy` 里 `unmount`。

## 八之二、字号四档，字体两种（2026-09-24）

字号只有 `--fs-xs` 11 / `--fs-sm` 12 / `--fs-md` 13 / `--fs-lg` 15（app.css）。**组件里只写档位不写数字** ——
收之前是 12 种，其中五种半像素，最常用的 11 和 11.5 让整个界面偏小发虚。代码区不在这里（编辑器跟
`--editor-font-size`，终端单独设）。唯一的例外是 `main.ts` 的启动失败页：那时 CSS 可能没加载，只能内联写死。

字体：界面 `--ui-font`（系统的 SF Pro），代码 `--code-font`（内置的 JetBrains Mono，连字关着 —— IDEA 默认也关）。
**等宽只给代码类内容**：代码与片段、原样的命令输出和报错、提交哈希、可能输正则的搜索框。文件名、路径、分支名、
计数、键位、状态栏都是界面字体 —— 数字要对齐就加 `font-variant-numeric: tabular-nums`，不是换等宽。
原来整条状态栏都是等宽的，这是界面「程序员味」的一大来源。

**字的层次**（2026-10-12 设计稿④）：浮层、对话框、卡片里不要整块都是 13 号常规白字 —— 那样层次全靠位置，人得逐字读。

| 用途 | 字号 · 字重 | 颜色 |
|---|---|---|
| 标题（对话框、空态卡片、小面板） | `--fs-lg` 15 · 600 / 小面板 13 · 600 | `--text` |
| 条目（菜单项、列表行） | 13 · 常规 | `--text` / `--text-dim` |
| 说明（对话框正文、卡片正文、空态说明） | 13 / 12 · 常规 | `--text-muted` #a9a9ae |
| 快捷键、附注、「当前」 | 12 · 常规 | `--text-faint` |
| 分组名（浮层里吸顶的那行） | 11 · 常规 · 字距 0.04em | `--text-faint` |

分组名原来是 13 号加粗，比它底下的分支名还重 —— 它是路标，不是内容。

## 九、`direction: rtl` 只给路径，别的一概不给

长路径要从**左边**省略（有用的是尾巴），靠的是 `direction: rtl`。
但这个类曾经被快捷键共用，而 `⌘`(U+2318) 在 bidi 里是**中性字符** ——
RTL 段落里它跟着段落方向走，于是源码里的 `⌘1` 在界面上显示成 `1⌘`、
``⌃⇧` `` 显示成 `` `⇧⌃ ``。

**这类 bug 不报错、不崩溃**，而且看源码看不出来（源码一个字没错）。
快捷键、徽章、计数一律不带 `direction`。

## 十、工具窗的头只讲「你在看哪一个」，切换在导轨上

**工具窗有内容才出现**（2026-09-18）。编辑区是主角，工具窗是配角：常驻的只有导轨上
那个入口，本体只在「有东西可看」时出现。一个空的工具窗（没项目时的文件树、没有会话的
终端）不该在屏幕上占一块 —— 用户开 `.app` 看到「底栏什么也没有、侧边栏只有一个打开
文件夹按钮」，问「那不应该不展示么」。两条判据：

- 没项目 → 侧边栏不出现（草稿视图除外，它不属于项目）。「打开文件夹」已经有标题栏
  挂件、⌘O、拖进来三个入口，不在一个本不该出现的容器里放第四个。
- 底部工具窗：终端会话跟着进程死，重启没有终端可恢复，所以**终端视图的「开着」不进
  会话恢复**；Git 视图有仓库才恢复。⌘J / 导轨点开时没 shell 就起一个（没项目就在 `~`），
  于是「开着」和「有内容」永远同时成立。

底部面板（终端 / Git）的头照 IDEA 的工具窗排：

```
[工具窗的名字]  [标签 ✕][标签 ✕]  ＋  ⌄        …        ⋮  —
```

**切工具窗不在这一行里。** 它在左边那条常驻导轨上，和文件树 / Git 改动
同一套 —— 原来「终端」「Git 日志」两个按钮摆在面板头上，于是「换一个工具窗」
这件事在同一个应用里有两种长相：侧边栏在导轨上换，底部在头上换。
导轨上点当前那个就收起，和最上面 sidebar 那个开关是同一个手势。

**工具窗和标签页是两层，抄 IDEA 要连层级一起抄**（issue #31）。v1.0.0 把
「Git 控制台」做成了导轨上和终端平级的第三个工具窗，用户一眼看出来：
「我要的是 IDEA 那种，你现在独立出来了」。IDEA 只有一个 Git 工具窗，
Log 和 Console 是它里面的两个标签 —— 它们是「看 git 在干什么」这同一件事
的两面。判据：**新东西和邻居是不是同一件事的两面**，是就做标签，不是才做窗。
Git 窗那两个标签关不掉，所以没有 ✕（`.pt-label.fixed` 把右边的内缩补回来）。

四条配套：

1. **标签和上面的编辑器标签栏是同一套**（22px 圆角块 + `--selected`，
   ✕ 占固定 16px 的格子、hover / 当前项才显形）。两条标签栏在同一个窗口里，
   长相不一致的话人会以为它们是两种东西。
2. **名字和标签之间不画竖线**，靠留白和亮一档的字色分开 —— 线只分区不分项。
3. **⋮ 里没有真动作就不要这个按钮。** 提交历史那边一条都没有，
   于是它那行右边只有 `—`。摆一个点开是空的菜单，比没有这个按钮糟。
4. **收起用 `—` 不用 `✕`。** 东西还在（终端里的 shell 一直活着），
   只是不占地方了；`✕` 说的是「关掉」，那是另一件事。

顺带一条**只有真点一下才发现**的：`ContextMenu` 原来按 `label` 做 each 的 key，
而三个终端开在同一个目录里标题就都是 `proj` —— Svelte 抛
`each_key_duplicate`，**整个菜单一条都不渲染**。表现是「点了没反应」，
控制台里才有线索。key 换成下标（菜单是一次性建好的静态列表，下标是稳的），
标题也照 IDEA 带上序号：`proj` / `proj (2)` / `proj (3)`。

## 十一、三处外壳各管一件事，谁都不许兼职

2026-09-06 照 IDEA 的分工重排。**加任何常驻控件之前先问：它属于哪一处。**

| 哪儿 | 管什么 | 判据 |
|---|---|---|
| 左边导轨 | 打开哪个工具窗 | 文件树 / Git 改动 / 搜索 / 草稿 / 终端 / Git，**只有这一处**。草稿不在 `{#if root}` 里 —— 它不属于任何项目 |
| 标题栏 | 哪个项目、哪个分支 | 两个挂件（分支挂件带 ↑↓ 计数），右边整片留给窗口拖动。**动作不在挂件旁边** —— 拉取 / 提交 / 推送在分支浮层顶上。**没项目的窗口就是草稿本**：项目挂件是便签图标 +「草稿本」，和「首字母方块 + 项目名」同一个形状，窗口标题也叫「草稿本」（docs/SCRATCH.md 第七节）—— 五个入口把人带进来，进来要认得出这是哪儿 |
| 状态栏左 | 我在哪个文件 | 路径面包屑，**只干这一件**。做完的消息原来顶掉它 2.6 秒，2026-10-13 起去了编辑区底部的胶囊（第十五条） |
| 状态栏中（右半最左一格） | **后台在跑什么** | 照 IDEA 右下角：文字 · 3px 条 · 百分比 · 取消。拉取推送 / 日志索引扫描过滤 / 提交跑钩子全在这一格（`state/progress.svelte.ts`），**别处不许再画进度**；只画最新的一个，多于一个加 +N |
| 状态栏右 | 这个文件什么状态 | 每一格**点了都能改**：行:列（点了跳行）/ 模式 / 语言 / 缩进·换行符（点了弹菜单选一种，issue #37）/ 编码 / 脏（草稿这格说的是「存了没存」：自动保存… / 已自动保存 / 失败 · ⌘S 重试）/ git |

改之前状态栏右半边挂着「搜索 ⇧⇧」「终端 ⌘J」「改动 N」「历史」——
四个全是**打开某个工具窗**，而那四件事导轨上一个不落地都有。
同一件事在一屏里说两遍，而这正是上一条（工具窗切换只能有一处）本身。

**Git 页的头不再印分支**（M9，2026-09-16）。它原来是 `⑂ m13/git ⌄ [↑2 推送] ↻`，和标题栏
的挂件是同一个数据、同一个点击 —— 一屏印两遍，而且两个入口各自长歪（那行长出了同步胶囊
和进度条，挂件长出了 ↑↓ 计数）。现在 Git 页的头是和文件树同一形状的面板头
（`改动 · N` + 刷新 + ⋮），进度当时归了 `RemoteBars` 的卡片 —— 2026-09-22 起搬到状态栏的
进度格（上表），卡片只剩问问题的三张（分岔 / 推送确认 / 失败）。

**同步胶囊在标题栏只活了半天**（M9 之二，同日）。它搬到挂件旁边之后用户一眼「好丑」，
拿 IDEA 的截图说「这也啥样就好了」：IDEA 的挂件就是一个名字，拉取 / 提交 / 推送是
**分支浮层顶上的三条动作**（更新项目… / 提交… / 推送…），搜索框右边一个 fetch。
动作跟着浮层走，挂件只报状态（名字 + ↑↓ 计数）。判据：**挂件是「我在哪」，不是工具栏。**

三条会咬人的：

1. **删格子时竖线要跟着走。** `drop-2` 藏掉一格，而它前面那条竖线不带 drop 类的话，
   640px 宽时状态栏上会出现两条挨着的竖线，末尾还吊着一条后面什么都没有的。
   分隔线分的是「区」，区没了线也该没。
2. **`.statusbar > * { flex: none }` 会让面包屑不收缩**，一条长路径能把右边的挂件
   整个顶出屏幕。要在 `.crumbs` 上单独覆回 `flex: 0 1 auto; min-width: 0`。
3. **构建时间的 tooltip 不能丢。** 它原来挂在标题栏那个 `lite-ide` 字样上，
   而那个字样只在没打开项目时才出现了 —— 现在挂在项目挂件的 `title` 第二行。
   「报上来的 bug 复现不了时先确认对方跑的是哪个构建」这条是有过教训的。

## 十二、浮层从**触发它的那个控件**底下掉下来，不弹在屏幕中间

分支与工作树原来是「压暗背景 + 居中对话框」。两处不对：

- 居中弹窗长得像「要你先处理完才能干别的」，而切分支只是随手看一眼；
- 它离触发它的挂件十万八千里，眼睛要从左上角跳到屏幕中央再跳回来。

现在传一个 `anchor`（挂件的 `left` / `bottom`），scrim **保留但不压暗**
（它只干一件事：点外面关掉），挂件在浮层开着时保持 `--selected` 点亮 ——
否则那块浮层看着像凭空冒出来的。

四条：

- **位置要钳进视口**，抄 `ContextMenu` 那一套：改 DOM 而不是写回 props
  （写回状态会让 effect 依赖自己写的值）。
- **钳位的依赖里要带上列表长度**：过滤一改高度就变，钳完的 top 会过时，
  长列表筛成两行之后浮层底边吊在半空。
- **锚点由一个函数统一算**。分支浮层有两个入口（挂件、菜单；Git 栏的分支行 M9 删了），
  各写各的话，从菜单开出来的那次就会掉在别的地方。
- 随处搜索（⇧⇧）仍然居中 —— 它没有触发它的控件，而且它是全屏范围的检索。

**居中的那些：上沿一条线，宽度三档**（2026-10-13 盘点 A1，`app.css` 的 `.palette`）。原来七个居中浮层各写各的位置：
四种上沿（10 / 12 / 14 / 16vh）、七种宽度，⌘P、⌘E、⇧⌘O 换着开框在屏幕上跳。现在上沿钉在 `--pal-top`（12vh），**往下长** ——
结果列表随输入变长变短，上沿不动输入框才不跟着跳（Spotlight、Raycast、VS Code 的命令面板都这样）。宽度只有 `s` 440（一个输入框 + 短结果：
跳行、编码）/ `m` 640（列表：随处搜索、文件结构、任务、分支、速查表）/ `l` 820（带预览：替换）。**新浮层挂 `palette s|m|l`，组件里不再写
top / left / width / z-index**；挂在控件底下时在组件里把 top / left / transform 关掉（`anchored`）。

## 十三、一次点击能直接做完的，只有「反向操作就在同一屏上」的动作

2026-09-07 立的。起因是分支浮层：点一下分支就 `git switch`，而 git 拒绝时
把一段英文 stderr 原样弹给用户 —— 全应用只有这一处是这样。

**按后果分四档：**

| 后果 | 做法 | 例子 |
|---|---|---|
| 可逆，反向操作在眼前 | 直接做 | 暂存（取消暂存就在同屏）、切到本地分支 |
| 可逆，但反向操作要另找 | 直接做，**做完把结果说出来** | 打开工作树（换了项目根，标签没动） |
| 会被外部条件挡住 | **把挡路的东西摆出来，给现成的出路**（对话框） | 切分支被本地改动挡住 → 列出文件 + 「去提交 / 丢弃这些改动并切换 / 取消」 |
| 不可逆 | 对话框 + `danger`，动作进菜单 | 移除工作树、丢弃改动、移到废纸篓 |

**第三档是最容易漏的那一档。** 它不是「出错了」，是「你得先决定怎么办」——
而底层工具的原话通常是给命令行用户看的（"Please commit your changes or stash
them before you switch branches"），把它转发给界面用户等于让他自己去开终端。
分类要做在**最贴近那个工具的地方**（`gitsvc::Error::LocalChanges`），
别让上层去 `contains("would be overwritten")`。

**说结果，不说请求。** 提示语要读刷新后的真实状态，不要复述「我请求做了什么」——
请求切 `origin/foo` 时底层可能建了本地 `foo`，也可能切到了一个早就存在的同名分支。
前端去复现那套 DWIM 规则就是把同一份判断写两处；读一遍状态，说的话永远是真的。

**防手滑只防鼠标，不防键盘**（M9，2026-09-16）。分支浮层单击开菜单是因为 hover 就移动
选中项、划过去顺手一点就切了；↵ 没有「划过」这回事 —— ↵ 之前人已经打了几个字把目标筛出来。
2026-09-10 让 ↵ 也开菜单，是给最常见的路径（打字 → ↵）加了一道没有保护对象的门，改回直接切。
菜单照 IDEA 排三段：去哪儿（切换 / 检出）/ 拿它做什么（拉取 / 推送 / 新建 / 合并 / 重命名）/
杂项，不可逆的（删除）在最末带 danger。删除走两道卡片：先问一次，`-d` 被「还有没合并的提交」
拦下来再问「仍然删除」（`-D`）—— 第二道是第三档（把挡路的摆出来给出路），不是把 git 原话贴出来。

**配套：任何一个列表行，除了主动作都要有第二个入口**（右键 / hover 的 `⋯` /
`⇧F10`）。只有一个入口的行，等于逼着人用主动作去试探 —— 想在 Finder 里看一眼
某个工作树，得先切过去。

**浮层里叠菜单时，菜单要 `stopPropagation`。** 只 `preventDefault` 不够：
浮层的键盘处理挂在 `<svelte:window>` 上，一次 Esc 会同时关掉菜单和整个浮层。
在浮层那边加「菜单开着就不管」也挡不住 —— `onclose` 是同步的，事件冒到 window
时那个标记已经被清掉了。两边都要写：菜单 `stopPropagation`，浮层再兜一层
「菜单开着时 Esc 只关菜单」（焦点万一不在菜单上，不然 Esc 会变成死键）。

## 十四、等待、卡片、浮层、动效各只有一处定义（2026-09-21）

全在 app.css 末尾那一段，画廊里都有样品。四条：

- **「还在等」只有一个 12px 缺口圆环。** `.spinner`（`sm` 10px 占图标格子）、按钮上
  `class:busy={x}` **和 `disabled={x}` 一起写**（disabled 管不响应，busy 管长得像在干活）。
  **150ms 之内不出现** —— 延迟做在样式里（`animation-delay`），状态层只管真假。**环旁边那句「正在载入…」也一样**：
  包在 `.wait` 里整句一起延迟（2026-10-13 盘点 D2：原来只有环等、字立刻出，第一次打开编辑器 / 差异 / 日志时那句字闪一帧）。
  busy 的按钮宽高不变。不要再写「载入中…」的裸文字，也不要把图标染色当忙碌态。
- **「这里没东西」是 `.empty-msg`**（2026-10-13 盘点 D1；原来 `.empty` / `.none` / `.hint` 三套写法、十来处各写一份边距和颜色）：
  一句**为什么空** + 一个**下一步**（第六条）。`.sub` 第二行补充，`.bad` 拿不到（出错，红、左对齐、等宽），`.wait` 还在等。
  下一步要照实说：Git 栏写「`git init`，这里会自己出现」，因为它真会 —— `.git` 一出现文件监听就报、`git.onGitDirChanged` 重新找仓库
  （2026-10-13 先写的是「之后重新打开这个项目」：那时仓库只在换根时找一次。做不到的就别写「自动」，做到了再改字）。
- **浮层的面是 `.popup`，遮罩是 `.scrim`。** 组件里只写位置、尺寸、z-index。居中的全屏检索
  用 `.scrim.dim`（压暗），挂在控件底下的用裸 `.scrim`（只干点外面关掉）。
- **对话框是 `.dialog`**（`.title` / `.body` / `.actions`，宽的加 `wide`），**卡片是 `.confirm`**，分工见第二之二条。
  卡片色只有两档：`warn` 琥珀 = 要你决定，`bad` 红 = 出错 / 没做成，普通的不上色。带多行的加 `tall`。
  **卡片一个宽度**（640，同 `.palette.m`；正文那格撑满、按钮靠右）、**按种类排不按到达先后**（红 → 琥珀 → 中性：新来的不把正在读的挤走）、
  **最多摆两张**，其余折成一颗「还有 N 条」的小胶囊（2026-10-13 盘点 A2：原来宽窄不一、没有上限，四张能挡住编辑区上半截）。
- **按钮次序照 macOS：主动作最右，取消紧挨其左，其余往左，越不可逆越靠左。**
  卡片和弹窗都是这一条 —— 之前卡片主动作在左、弹窗在右，一屏两种次序。
- 动效都在 app.css 那一段（表和理由在那段注释里）。**进场**：hover 70ms / 浮层 90ms 淡入 / 卡片、对话框 120ms 淡入下落 /
  胶囊 140ms 淡入上浮 / 对话框被挡时顶一下 160ms。**退场**只给「压在内容上、一消失底下就跳」的三种：对话框的压暗层 120ms 淡出、
  卡片 140ms 收起高度 + 淡出（下面的平滑补上）、胶囊 140ms 淡出；**菜单和浮层瞬没** —— 一关人就要接着操作，等动画就是卡
  （2026-10-13 盘点 C1，`shell/motion.ts`）。浮层**只动透明度** —— 要钳位的浮层动了 transform 量到的是动画中途那一帧。
  **退场中的东西不再是「在」**：对话框淡出那 120ms 里压暗层打 `leaving`、不接鼠标，模态守卫按状态（`asking`）判不按 DOM 判 ——
  不然答完之后马上点别处会被一个已经答完的框拦下来。淡出到一半又要问时 Svelte 会把那层倒回来复用，`leaving` 要摘掉，不然新框点不动（复现过）。
  **`leaving` 跟着状态打（`asking` 为假就打），不靠退场过渡函数**：Svelte 缓存过渡配置、只在进场结束时清，复用过的那一层第二次退场不再调 `layerOut`（2026-10-20，smoke ㉗ 间歇红了一周多的原因）。
- **分段控件是 `.segs`**：照 macOS，一条 6% 白的轨道，`on` 那段是亮一档的实心块（2026-10-12；原来是几个描边按钮拼起来、
  选中那段描强调色 —— 按钮改实心之后拼不起来了）。差异视图的「双栏 / 统一」和日志的「只看命中 / 全文」都是它；别再各写一份。
- **菜单的选中项是强调色底、白字**（`ContextMenu`、编辑器补全弹层同一个样子，2026-10-12 设计稿② 方案 B）。原来是中性白 11%，
  理由是「强调色会比内容还抢眼」；推翻它是因为 macOS 每个应用的菜单都是这样，人一天看几百次。危险项被选中是红底白字。
  **菜单项右边印快捷键**（`MenuItem.keys`）：只印此刻按得出来的 —— 标签的右键菜单不印 ⌘W，你右键的那个标签不一定是当前标签。
- **进度条是 `.pbar`**（3px 细条，`indet` 来回跑），只出现在状态栏的进度格里。有百分比就登记
  百分比（`progress.start(label, { percent })` + `set`），没有就 `null`（不确定条），
  **不能画成 0%**。`end` 放 finally / effect cleanup，漏掉就是一条永远转着的任务。

## 十五、结果说在眼睛在的地方：胶囊、原地、卡片（2026-10-13）

做完一件事、或者没做成，那一句话放哪，按「人这时候在看哪儿」定（盘点 B1，用户选的方案 B + C）：

| 情形 | 放哪 | 例子 |
|---|---|---|
| 做成了 / 没做成，一句话说得清 | **编辑区底部居中的胶囊**（`notify.ok` / `fail` / `hint`，`shell/Toast.svelte`） | 已复制路径、已推送、推送失败 |
| 发起它的按钮是常驻的、人眼睛还在按钮上 | **按钮原地**换成「✓ 已提交」1.4 秒（`class:done`，主色不灰掉、宽度不变），胶囊照样说细节 | 提交按钮 |
| 没做成，说明是多行的 / 要你决定 | **卡片**（`notify.block` 等，第二之二条） | 切分支被挡住、列出文件 |

原来是状态栏最左那一格，照 IDEA。用户一眼「没看见」：眼睛这时候在编辑区或者刚点的那块，左下角是视野最边上，2.6 秒就走了；
它还把面包屑顶掉。胶囊照 macOS 的 HUD（Safari「已复制」、Xcode「构建成功」）：浮在内容上、不抢焦点、一行、一次只有一条。

- **颜色说结果**：`ok` 主色 ✓ = 做成了，`fail` 红 ✕ = 没做成，`hint` 灰、没图标 = **什么都没发生，说一句为什么**
  （剪贴板里没有文字、光标不在名字上、钉住了所以 ⌘W 没关它）。原来 `hint` 那几条走 `ok`，画成了做成了的颜色 —— 一扫过去以为做成了。
  新加提示先问：这一下**做成了没有**？没做也没坏 → `hint`。
- **没做成的不被做成的顶掉**：失败那条没读完时来的 `ok` / `hint` 不显示；新的失败照样顶掉旧的。
- **停多久按字数**（`readMs`：1.6 秒起，每字 60ms，封顶 6 秒；失败至少 4 秒），鼠标停上去不走、点一下关掉。
- **原地反馈只给常驻按钮**：右键菜单一点就关了，没有「原地」；推送从浮层 / 确认框发起，它的原地是标题栏挂件上的 ↑N 消失。

## 十六、双栏差异照 IDEA / VS Code：两栏平分、一起滚、留空看得出、折叠说清几行（2026-10-13）

- **两栏永远各占一半**（`minmax(0, 1fr)`）。原来代码列 `minmax(max-content, 1fr)`、整个 grid 横向滚，左边一行长就把右栏挤出屏幕。
  长行在格子里裁掉，靠两栏共用的横向偏移 `--sx` 平移（触控板左右划 / ⇧ 滚轮 / 底下两条细条），IDEA 那样两边同一列对着同一列。
  仍然是一个 grid：纵向天然同步、软换行时左右行高自动对齐（「两个并排的滚动容器」要自己同步、差一帧会抖）。
- **对面没有的行画细斜纹**（1px 线、7px 间距、5.5% 白），连着好几行的改成淡纯色 —— 原来 2.8% 的粗斜纹看不见，一片黑像渲染坏了。
- **块头写「N 行未改动 · 展开」**（`DiffLine.hidden`，照 VS Code 的折叠条），后面跟 git 猜的函数名。**点了只展开那一段**（照 IDEA）：
  没改动的行两边一样，从新侧的全文取（`git-ops.diffNewText`：提交的差异取那次提交、暂存区的取暂存区、工作区的读盘），旧行号按这一段的固定差算。
  不用「`git diff -U999999` 重拉一份」—— 那样所有块合成一大块，「暂存这一块」就成了暂存整个文件。全文和差异对不上（拉差异之后又改了）就不展开、说一句，
  不按行号硬插。补进来的行只进画面和着色（`view`），**不进按行暂存的下标（`bodyIdx` 照旧数原来的行）**。
- 行号栏宽度跟最大行号的位数走；两栏的分界线用 `--border`（实一档），栏内行号和正文之间用 `--border-soft`。
- 行内改动直角贴字（第一之三条）。

## 键位只有一处出处，`owner` 那一列是判据不是注释

`src/lib/state/keymap.ts` 是全应用键位的唯一出处。加菜单栏之前它散在四处
（keydown 分支、随处搜索的 `hint`、空态卡片、菜单栏），而手抄四份的结果是
可预见的：改一个键位漏掉三处。**显示错的快捷键比不显示更糟** ——
v0.5.0 里把 `⌘1` 显示成 `1⌘` 那个就是先例（源码对、渲染错、不报错）。

现在菜单、速查表、空态卡片、空草稿里那行灰字提示、随处搜索的动作表**全部从它生成**，
那张 69 行的手写 `actions` 表已经删了。

`owner` 决定两件事，缺一不可：

| owner | 菜单项 | keydown 分支 |
|---|---|---|
| `menu` | 带 accelerator | **不许有** |
| `key` | 只有标签，不带 accelerator | 有 |
| `cm6` | **一个字都不许进菜单** | 没有（CM6 自己的 keymap） |

原因：**菜单项带上 accelerator 之后 AppKit 会先把键吃掉，webview 收不到。**
两边都接是双触发（⌘W 一下关两个标签），两边都不接是按了没反应，
而**两种都不报错**。

四条最容易错的：

- **⌘F 归 CM6。** 进菜单等于把编辑器的查找静默抢没了（项目内搜索是
  ⇧⌘F，不冲突）。
- **⌘P 归编辑器（参数提示），找文件是 ⇧⌘O 归菜单**（2026-10-20 照 IDEA 换的；原来 ⌘P 是找文件、故意留在 keydown）。⌘P 不进菜单的理由没变：挂进菜单的话，焦点在终端里按 ⌘P 会被菜单抢走，
  而那时更可能是想给 shell 的。
- **别名：主键位进菜单、别名留 keydown**（⌘[ 是 ⌥⌘← 的别名）。macOS 菜单一项只能挂一个
  accelerator，速查表是唯一能把两个都说清的地方。
- **编辑器键位照 IDEA，而且 CM6 自带的键也要登记成 `cm6`**（2026-09-23）。CM6 的
  `defaultKeymap` / `searchKeymap` 不在这张表里，测试看不见它们 —— 菜单上的 ⌘/（速查）
  和 ⇧⌘G（改动列表）就这么把编辑器的注释、查找上一处抢了几周没人发现。登记进来之后，
  「同一个键位不许挂两条」会当场卡住。加菜单键位前先查 IDEA 里这个组合在编辑器里干什么。

修饰键次序按 Apple 的 **⌃⌥⇧⌘**。老的 `actions` 表里写的是 `⌘⇧G`，
`tests/keymap.test.ts` 现在卡着这条 —— 这类错误肉眼扫不出来。

## 菜单栏是 keymap.ts 的一份拷贝，靠测试卡住

菜单必须在窗口出现之前建好（`setup` 里），那时前端还没起来 ——
所以 `src-tauri/src/menu.rs` 里是一份拷贝。等前端 ready 再下发的话，
中间那几百毫秒菜单栏是 Tauri 的默认英文菜单，看着像另一个应用。

两份拷贝由 `src-tauri/tests/menu_sync.rs` 卡住，判据和 `dto_sync.rs` 一样：
**只读源码，比两边的集合。** 它验过红，四种漂移都会红：

| 漂移 | 后果（都不报错） |
|---|---|
| 文案不一致 | 菜单写「保存」、速查表写「保存当前文件」 |
| 键位不一致 | 菜单上写着 ⌘S，按下去没反应 |
| 给 `key` 的项挂了 accelerator | keydown 分支永远轮不到 |
| `cm6` 的混进菜单 | CM6 的查找被静默抢走 |

**菜单项的 id 写字面量，不写常量**：`menu_sync.rs` 读源码比对 id，`item(app, crate::winctl::SCRATCHBOOK, …)` 它读不出来，
报「keymap.ts 里归菜单，菜单里却没有它」（2026-10-13 草稿本撞的）。Rust 侧要用同一个 id 的地方（`winctl::SCRATCHBOOK`）照旧用常量。

菜单里新增一项，**必须先在 `keymap.ts` 登记** —— 反向检查也在跑
（`help-repo` 就是被这条逼出来的）。

四处配套：

- **编辑菜单必须走 predefined。** 剪切/复制/粘贴/撤销在 WKWebView 里靠
  NSResponder 链（`undo:` `copy:` 这些选择器）；自己发事件到前端操作 DOM，
  在 CM6 和 xterm 里都会走样。
- **菜单事件一律转给前端**（`on_menu_event` → `emit_to(前台窗口, "menu", id)`）。
  动作要读的状态（当前标签、仓库、终端列表）都在前端，搬过来就是存两处。
  **只发给前台窗口**（多窗口，2026-10-08）：广播的话在 A 里按 ⌘S，B 也保存。
  三个例外在 Rust 侧接：「打开文件夹…」（`NSOpenPanel` 只能在 Rust 侧开）；
  「退出」（要先让每个窗口存好现场再退，`winctl::quit`）；一个窗口都没有时（#41，应用还在 Dock 上）
  的「打开文件夹 / 最近打开 / 新建草稿」（`winctl::menu_without_window`）。
- **灰态按窗口存**：原生菜单只有一份，`sync_menu_state` 先存进调用它的那个窗口，它在前台才真的改菜单；
  窗口到前台时 Rust 用它存着的那份刷一遍。
- **灰态是白捡的。** 今天所有键位都是 window 级监听，不管当下有没有意义
  都会触发 —— 没有标签时按 ⌘S 就是走一遍然后什么也没发生。
  菜单项有 `enabled`，`sync_menu_state` 把状态推过去就能变灰，
  **而灰掉的菜单项本身就是一句解释**：不是坏了，是现在用不上。

  但**不要按焦点灰**。`⌘S` 那条注释写得很清楚：它就是要在编辑器没有焦点时
  也管用（焦点在文件树/Git/终端上时按 ⌘S 什么都不发生，是被当 bug 修过的）。
  判据是「有没有活动标签」，不是「焦点在哪」。

## 浏览器里没有菜单栏，所以动作必须在随处搜索里也有一份

`pnpm dev` 跑在浏览器，**那儿一个菜单项都没有** —— 归菜单的键位
（⌘S ⌘O ⌘W ⌘K …）在那里全都够不着，改 UI 的主循环就废了一半。

解法不是「浏览器里再挂一套 keydown」（那就成了两个引擎各听各的，
和 `::-webkit-scrollbar` 那条同一个病）。解法是
**随处搜索的动作表覆盖全部动作**，它本来就是从 `keymap.ts` 生成的：
Tauri 里走菜单，浏览器里走 ⇧⇧ → 操作。

## 透明窗口没有退路，所以有一个 `data-shell` 开关

`transparent: true` 之后窗口自己不画底。材质层没挂上（或者根本不在 Tauri 里跑），
外壳层留空透出来的就是**空**。而改 UI 的主循环恰恰是浏览器里的 `pnpm dev`，
那里一块 NSVisualEffectView 都没有。

`main.ts` 在 mount **之前同步**打一个 `data-shell`：

```js
document.documentElement.dataset.shell =
  "__TAURI_INTERNALS__" in window ? "tauri" : "web";
```

用这个判据而不是「深色还是浅色」，是因为要问的其实是「这个壳有没有材质层」。
用 `__TAURI_INTERNALS__` 而不是 `invoke` 一次，是因为它**同步、零成本**——
这行在 mount 之前跑，晚一帧就是一帧的白闪。
macOS 上 `apply_vibrancy` 万一失败，`lib.rs` 会 `eval` 把它打回 `web`。

回落那组值不是随便填的：**浏览器里调好的层级，装进 .app 里不能反过来。**
踩过一次 —— `--chrome-scrim` 在 web 下留成 `transparent`，标题栏就露出 body 的底，
而 body 是内容色，于是浏览器里标题栏比侧边栏**浅**，
装进 .app 里（材质 + 黑 20% scrim）又比侧边栏**深**，层级整个倒过来。

## 十七、一条视线只穿过一层闭合边框；按下有触感；焦点看得见（2026-10-19）

用户给了一份 Claude 桌面端的设计语言拆解（open-claude-ui，**是反编译出来的，代码和样式表不搬进来**，只学原则、用我们自己的令牌重写），
让照着优化。逐条对过：大半我们已经有（0.5px 细边 + 顶边高光、实心按钮不描边、70 / 120ms 动效、输入法守卫）；**颜色不跟**（陶土橙是它的品牌色，
编辑器用了像仿制品；保留 10-12 定的系统蓝和冷灰，用户确认）；**尺寸不跟**（它的控件默认 32 高是给聊天阅读的，IDE 要密度，28 照 IDEA）。学了四条：

1. **一条视线只穿过一层闭合边框。** 岛、浮层、对话框、卡片自己有边，里面的东西（输入框、按钮、工具条）一律不再画闭合的框 ——
   输入框只用底色、按钮是实心或无底、分区用单向的一道线。框里套框读起来是「表格 / 格子」。**自成一体的小块不算**：提交历史里的分支标签、冲突标记、提交号块，它们本身就是一个对象。
2. **按下去缩一点**：`.btn` 0.98、`.ibtn` 0.92（图标按钮小，0.98 只缩半个像素看不出来）。按下不过渡、松手 70ms 弹回；减少动态效果时不缩。
   只变底色的话按下和悬停差一档灰，触控板上感觉不到「按到了」。
3. **键盘焦点**：独立的按钮是 1.5px 的环往外让 1px + 外面一圈 `--focus-glow`（macOS 系统控件的样子）；**列表行还是内缩 1px**（treeitem / option / menuitem / tab：
   一行挨一行，往外的光晕会压到上下行）。原来 1px 的线在 24px 的图标按钮上几乎看不出来。
4. **浮层两层影子**（`--shadow-pop`）：贴近的一层小而实（勾出边缘），远处一层大而淡（说抬多高）。原来只有远处那层，边缘是糊的。

没学的，连同理由：浮层列表的滚动边缘渐隐（我们的浮层列表有吸顶分组头，边缘一淡，分组头底下那行就看不清了）；
卡片悬停往上抬（工具窗里的东西不是卡片墙，悬停抬起会让密集列表晃）；聊天专属的那一大半（输入框、气泡、模型切换、语音）留到 AI 面板（#46）再看。
