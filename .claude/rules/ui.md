# 界面写法定死了，新界面照这套来

**新加任何界面先读这一节**，不要另起一套 —— 下面每一条都是从已经统一过的那几处里
挑出来的、真的出过问题的地方。

## 一、「当前项」只有一种长相：内缩的圆角块

文件树、大纲、随处搜索、分支面板、标签栏，全部是
`margin: 0 6px` + `--r-md` + `--selected`。**不许用通栏色条，也不许用下划线。**

标签栏原来是 IDEA 那套（平角 + 底下 2px accent 线），换掉有两个理由：
一是那条线在半透明的外壳上飘着，二是标签栏和文件树紧挨着，
「当前项」在两边长得不一样，人会以为它们是两种东西。

## 二、不要用分隔线表达「这是一格」

八个标签就是八道 1px 竖线 —— 那是**表格**的语言。当前项已经由一块底色
说清楚了，再画线就是同一件事说两遍，而线是常驻的、底色只有一块。

线只用来分**区**（标题栏／内容／状态栏之间），不用来分**项**。

## 三、常驻的只留「不看会出错」的那些

判据就这一句。落到那四处：

| 常驻 | hover 才出 |
|---|---|
| 未保存改动的圆点（关掉要问你） | 标签的 ✕ |
| git 状态字母 M/A/?/! | 改动行的 ＋ − ↺ |
| 分支名、改动条数 | 「⋯」里那些 |

**圆点和 ✕ 占同一个格子**，hover 时原地互换 —— 点击目标不许跳位置。

**这条管的是「每一项上重复出现」的东西。** 上表四行全是这个形状：
每个标签一个 ✕、每一行改动一组 ＋ − ↺ —— 常驻它们等于满屏噪音。
**整条栏上只有一个的入口不在此列**，标签条末尾那个「新建草稿」的加号就是
（2026-09-09 加的）。它常驻，因为它不是某一项的附属物，
藏起来等于这个功能只剩快捷键。

## 四、分组头要吸顶，而且每行还得能自证类别

分组头 `position: sticky; top: 0`，底色跟着所在层走
（外壳层用 `--panel-bg`，浮层用 `--elevated`；填死色会在滚动时拖出一条实心带）。

**但吸顶不够。** 分支面板最长几十行，滚起来只看得见一个分组头 ——
所以每行还要有自己的图标（本地分支／工作树／远程／操作四个形状）。
原来四种条目共用一个 9px 空心圆，只靠边框颜色区分，12px 的行里那点色差读不出来。

## 五、浮层的骨架是固定的

搜索和分支面板现在是同一副骨架，以后的浮层照抄：

```
输入（16px 图标 + 15px 字，排第一）
范围／过滤（分段控件，紧贴输入）
分组结果（吸顶头 + 内缩圆角行 + 每行图标）
脚栏（键位提示，--chrome-scrim 打底）
```

**输入排第一**：面板打开之后的下一个动作永远是打字，
而范围十次里有九次不用改。键位提示是「忘了才看」的东西，放脚栏 ——
它顺带给了面板一个下边界，不然结果列表是直接切在圆角上的。

脚栏的 `↵` 说明**按当前项变**（分支说"切换"、远程分支说"检出"、工作树说"打开"）。

## 六、同一个信息只印一遍

Git 栏原来「工作区干净」印了两遍（折叠的提交按钮里一遍、列表空态里一遍）。
随处搜索原来每行都印一个「文件」「操作」胶囊 —— 七行结果七个胶囊，
而分组头本来就说清了。

**空态要给下一步，不是给句号。** 干净时唯一还能做的事是看历史，就把它放出来。

## 七、不可撤销的动作不许和可逆的并排同色

「全部丢弃」原来和「全部暂存」并排、同样大小、同样颜色，中间隔 2px。
现在它进了「⋯」菜单并带 `danger`。**误点的代价不该只隔着 2px。**

## 八、图标只有一处定义

- `Icon.svelte` —— 界面图标（侧边栏、刷新、勾、加号、箭头…）
- `FileGlyph.svelte` —— 文件类型字形（目录／代码／文档／配置／纯文本）

`FileGlyph` 是 2026-09-04 从 `FileTree.svelte` 里收出来的，因为标签栏和
随处搜索也要用：**同一个文件在三个地方出现，不能长三个样。**
文件夹那一个形状走 `Icon` 的 `files`，因为导轨上画的是同一样东西。

## 九、`direction: rtl` 只给路径，别的一概不给

长路径要从**左边**省略（有用的是尾巴），靠的是 `direction: rtl`。
但这个类曾经被快捷键共用，而 `⌘`(U+2318) 在 bidi 里是**中性字符** ——
RTL 段落里它跟着段落方向走，于是源码里的 `⌘1` 在界面上显示成 `1⌘`、
``⌃⇧` `` 显示成 `` `⇧⌃ ``。

**这类 bug 不报错、不崩溃**，而且看源码看不出来（源码一个字没错）。
快捷键、徽章、计数一律不带 `direction`。

## 十、工具窗的头只讲「你在看哪一个」，切换在导轨上

底部面板（终端 / 提交历史）的头照 IDEA 的工具窗排：

```
[工具窗的名字]  [标签 ✕][标签 ✕]  ＋  ⌄        …        ⋮  —
```

**切工具窗不在这一行里。** 它在左边那条常驻导轨上，和文件树 / Git 改动
同一套 —— 原来「终端」「Git 日志」两个按钮摆在面板头上，于是「换一个工具窗」
这件事在同一个应用里有两种长相：侧边栏在导轨上换，底部在头上换。
导轨上点当前那个就收起，和最上面 sidebar 那个开关是同一个手势。

四条配套：

1. **标签和上面的编辑器标签栏是同一套**（22px 圆角块 + `--selected`，
   ✕ 占固定 16px 的格子、hover / 当前项才显形）。两条标签栏在同一个窗口里，
   长相不一致的话人会以为它们是两种东西。
2. **名字和标签之间不画竖线**，靠留白和亮一档的字色分开 —— 线只分区不分项。
3. **⋮ 里没有真动作就不要这个按钮。** 提交历史那边一条都没有，
   于是它那行右边只有 `—`。摆一个点开是空的菜单，比没有这个按钮糟。
4. **收起用 `—` 不用 `✕`。** 东西还在（终端里的 shell 一直活着），
   只是不占地方了；`✕` 说的是「关掉」，那是另一件事。

顺带一条**只有真点一下才发现**的：`ContextMenu` 原来按 `label` 做 each 的 key，
而三个终端开在同一个目录里标题就都是 `proj` —— Svelte 抛
`each_key_duplicate`，**整个菜单一条都不渲染**。表现是「点了没反应」，
控制台里才有线索。key 换成下标（菜单是一次性建好的静态列表，下标是稳的），
标题也照 IDEA 带上序号：`proj` / `proj (2)` / `proj (3)`。

## 十一、三处外壳各管一件事，谁都不许兼职

2026-09-06 照 IDEA 的分工重排。**加任何常驻控件之前先问：它属于哪一处。**

| 哪儿 | 管什么 | 判据 |
|---|---|---|
| 左边导轨 | 打开哪个工具窗 | 文件树 / Git 改动 / 搜索 / 终端 / 提交历史，**只有这一处** |
| 标题栏 | 哪个项目、哪个分支 | 两个挂件，右边整片留给窗口拖动 |
| 状态栏左 | 我在哪个文件 | 路径面包屑；有提示消息时消息顶掉它 |
| 状态栏右 | 这个文件什么状态 | 每一格**点了都能改**：模式 / 语言 / 编码 / 脏 / git |

改之前状态栏右半边挂着「搜索 ⇧⇧」「终端 ⌘J」「改动 N」「历史」——
四个全是**打开某个工具窗**，而那四件事导轨上一个不落地都有。
同一件事在一屏里说两遍，而这正是上一条（工具窗切换只能有一处）本身。

三条会咬人的：

1. **删格子时竖线要跟着走。** `drop-2` 藏掉一格，而它前面那条竖线不带 drop 类的话，
   640px 宽时状态栏上会出现两条挨着的竖线，末尾还吊着一条后面什么都没有的。
   分隔线分的是「区」，区没了线也该没。
2. **`.statusbar > * { flex: none }` 会让面包屑不收缩**，一条长路径能把右边的挂件
   整个顶出屏幕。要在 `.crumbs` 上单独覆回 `flex: 0 1 auto; min-width: 0`。
3. **构建时间的 tooltip 不能丢。** 它原来挂在标题栏那个 `lite-ide` 字样上，
   而那个字样只在没打开项目时才出现了 —— 现在挂在项目挂件的 `title` 第二行。
   「报上来的 bug 复现不了时先确认对方跑的是哪个构建」这条是有过教训的。

## 十二、浮层从**触发它的那个控件**底下掉下来，不弹在屏幕中间

分支与工作树原来是「压暗背景 + 居中对话框」。两处不对：

- 居中弹窗长得像「要你先处理完才能干别的」，而切分支只是随手看一眼；
- 它离触发它的挂件十万八千里，眼睛要从左上角跳到屏幕中央再跳回来。

现在传一个 `anchor`（挂件的 `left` / `bottom`），scrim **保留但不压暗**
（它只干一件事：点外面关掉），挂件在浮层开着时保持 `--selected` 点亮 ——
否则那块浮层看着像凭空冒出来的。

四条：

- **位置要钳进视口**，抄 `ContextMenu` 那一套：改 DOM 而不是写回 props
  （写回状态会让 effect 依赖自己写的值）。
- **钳位的依赖里要带上列表长度**：过滤一改高度就变，钳完的 top 会过时，
  长列表筛成两行之后浮层底边吊在半空。
- **锚点由一个函数统一算**。分支浮层有三个入口（挂件、Git 栏的分支行、菜单），
  三处各写各的话，从菜单开出来的那次就会掉在别的地方。
- 随处搜索（⇧⇧）仍然居中 —— 它没有触发它的控件，而且它是全屏范围的检索。

## 十三、一次点击能直接做完的，只有「反向操作就在同一屏上」的动作

2026-09-07 立的。起因是分支浮层：点一下分支就 `git switch`，而 git 拒绝时
把一段英文 stderr 原样弹给用户 —— 全应用只有这一处是这样。

**按后果分四档：**

| 后果 | 做法 | 例子 |
|---|---|---|
| 可逆，反向操作在眼前 | 直接做 | 暂存（取消暂存就在同屏）、切到本地分支 |
| 可逆，但反向操作要另找 | 直接做，**做完把结果说出来** | 打开工作树（换了项目根，标签没动） |
| 会被外部条件挡住 | **把挡路的东西摆出来，给现成的出路** | 切分支被本地改动挡住 → 列出文件 + 「去提交 / 丢弃这些改动并切换 / 取消」 |
| 不可逆 | 确认条 + `danger`，动作进菜单 | 移除工作树、丢弃改动、移到废纸篓 |

**第三档是最容易漏的那一档。** 它不是「出错了」，是「你得先决定怎么办」——
而底层工具的原话通常是给命令行用户看的（"Please commit your changes or stash
them before you switch branches"），把它转发给界面用户等于让他自己去开终端。
分类要做在**最贴近那个工具的地方**（`gitsvc::Error::LocalChanges`），
别让上层去 `contains("would be overwritten")`。

**说结果，不说请求。** 提示语要读刷新后的真实状态，不要复述「我请求做了什么」——
请求切 `origin/foo` 时底层可能建了本地 `foo`，也可能切到了一个早就存在的同名分支。
前端去复现那套 DWIM 规则就是把同一份判断写两处；读一遍状态，说的话永远是真的。

**配套：任何一个列表行，除了主动作都要有第二个入口**（右键 / hover 的 `⋯` /
`⇧F10`）。只有一个入口的行，等于逼着人用主动作去试探 —— 想在 Finder 里看一眼
某个工作树，得先切过去。

**浮层里叠菜单时，菜单要 `stopPropagation`。** 只 `preventDefault` 不够：
浮层的键盘处理挂在 `<svelte:window>` 上，一次 Esc 会同时关掉菜单和整个浮层。
在浮层那边加「菜单开着就不管」也挡不住 —— `onclose` 是同步的，事件冒到 window
时那个标记已经被清掉了。两边都要写：菜单 `stopPropagation`，浮层再兜一层
「菜单开着时 Esc 只关菜单」（焦点万一不在菜单上，不然 Esc 会变成死键）。

## 键位只有一处出处，`owner` 那一列是判据不是注释

`src/lib/state/keymap.ts` 是全应用键位的唯一出处。加菜单栏之前它散在四处
（keydown 分支、随处搜索的 `hint`、空态卡片、菜单栏），而手抄四份的结果是
可预见的：改一个键位漏掉三处。**显示错的快捷键比不显示更糟** ——
v0.5.0 里把 `⌘1` 显示成 `1⌘` 那个就是先例（源码对、渲染错、不报错）。

现在菜单、速查表、空态卡片、随处搜索的动作表**全部从它生成**，
那张 69 行的手写 `actions` 表已经删了。

`owner` 决定两件事，缺一不可：

| owner | 菜单项 | keydown 分支 |
|---|---|---|
| `menu` | 带 accelerator | **不许有** |
| `key` | 只有标签，不带 accelerator | 有 |
| `cm6` | **一个字都不许进菜单** | 没有（CM6 自己的 keymap） |

原因：**菜单项带上 accelerator 之后 AppKit 会先把键吃掉，webview 收不到。**
两边都接是双触发（⌘W 一下关两个标签），两边都不接是按了没反应，
而**两种都不报错**。

三条最容易错的：

- **⌘F 归 CM6。** 进菜单等于把编辑器的查找静默抢没了（项目内搜索是
  ⇧⌘F，不冲突）。
- **⌘P 故意留在 keydown。** 挂进菜单的话，焦点在终端里按 ⌘P 会被菜单抢走，
  而那时更可能是想给 shell 的。
- **⌘B 是 ⌘1 的别名。** macOS 菜单一项只能挂一个 accelerator，
  主键位进菜单、别名留 keydown，速查表是唯一能把两个都说清的地方。

修饰键次序按 Apple 的 **⌃⌥⇧⌘**。老的 `actions` 表里写的是 `⌘⇧G`，
`tests/keymap.test.ts` 现在卡着这条 —— 这类错误肉眼扫不出来。

## 菜单栏是 keymap.ts 的一份拷贝，靠测试卡住

菜单必须在窗口出现之前建好（`setup` 里），那时前端还没起来 ——
所以 `src-tauri/src/menu.rs` 里是一份拷贝。等前端 ready 再下发的话，
中间那几百毫秒菜单栏是 Tauri 的默认英文菜单，看着像另一个应用。

两份拷贝由 `src-tauri/tests/menu_sync.rs` 卡住，判据和 `dto_sync.rs` 一样：
**只读源码，比两边的集合。** 它验过红，四种漂移都会红：

| 漂移 | 后果（都不报错） |
|---|---|
| 文案不一致 | 菜单写「保存」、速查表写「保存当前文件」 |
| 键位不一致 | 菜单上写着 ⌘S，按下去没反应 |
| 给 `key` 的项挂了 accelerator | keydown 分支永远轮不到 |
| `cm6` 的混进菜单 | CM6 的查找被静默抢走 |

菜单里新增一项，**必须先在 `keymap.ts` 登记** —— 反向检查也在跑
（`help-repo` 就是被这条逼出来的）。

三处配套：

- **编辑菜单必须走 predefined。** 剪切/复制/粘贴/撤销在 WKWebView 里靠
  NSResponder 链（`undo:` `copy:` 这些选择器）；自己发事件到前端操作 DOM，
  在 CM6 和 xterm 里都会走样。
- **菜单事件一律转给前端**（`on_menu_event` → `emit("menu", id)`）。
  唯一例外是「打开文件夹…」：`NSOpenPanel` 只能在 Rust 侧开。
  动作要读的状态（当前标签、仓库、终端列表）都在前端，搬过来就是存两处。
- **灰态是白捡的。** 今天所有键位都是 window 级监听，不管当下有没有意义
  都会触发 —— 没有标签时按 ⌘S 就是走一遍然后什么也没发生。
  菜单项有 `enabled`，`sync_menu_state` 把状态推过去就能变灰，
  **而灰掉的菜单项本身就是一句解释**：不是坏了，是现在用不上。

  但**不要按焦点灰**。`⌘S` 那条注释写得很清楚：它就是要在编辑器没有焦点时
  也管用（焦点在文件树/Git/终端上时按 ⌘S 什么都不发生，是被当 bug 修过的）。
  判据是「有没有活动标签」，不是「焦点在哪」。

## 浏览器里没有菜单栏，所以动作必须在随处搜索里也有一份

`pnpm dev` 跑在浏览器，**那儿一个菜单项都没有** —— 归菜单的键位
（⌘S ⌘O ⌘W ⇧⌘G ⌘/ …）在那里全都够不着，改 UI 的主循环就废了一半。

解法不是「浏览器里再挂一套 keydown」（那就成了两个引擎各听各的，
和 `::-webkit-scrollbar` 那条同一个病）。解法是
**随处搜索的动作表覆盖全部动作**，它本来就是从 `keymap.ts` 生成的：
Tauri 里走菜单，浏览器里走 ⇧⇧ → 操作。

## 透明窗口没有退路，所以有一个 `data-shell` 开关

`transparent: true` 之后窗口自己不画底。材质层没挂上（或者根本不在 Tauri 里跑），
外壳层留空透出来的就是**空**。而改 UI 的主循环恰恰是浏览器里的 `pnpm dev`，
那里一块 NSVisualEffectView 都没有。

`main.ts` 在 mount **之前同步**打一个 `data-shell`：

```js
document.documentElement.dataset.shell =
  "__TAURI_INTERNALS__" in window ? "tauri" : "web";
```

用这个判据而不是「深色还是浅色」，是因为要问的其实是「这个壳有没有材质层」。
用 `__TAURI_INTERNALS__` 而不是 `invoke` 一次，是因为它**同步、零成本**——
这行在 mount 之前跑，晚一帧就是一帧的白闪。
macOS 上 `apply_vibrancy` 万一失败，`lib.rs` 会 `eval` 把它打回 `web`。

回落那组值不是随便填的：**浏览器里调好的层级，装进 .app 里不能反过来。**
踩过一次 —— `--chrome-scrim` 在 web 下留成 `transparent`，标题栏就露出 body 的底，
而 body 是内容色，于是浏览器里标题栏比侧边栏**浅**，
装进 .app 里（材质 + 黑 20% scrim）又比侧边栏**深**，层级整个倒过来。
