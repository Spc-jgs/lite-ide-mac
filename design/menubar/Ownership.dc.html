键位归属
这是这次唯一会静默做错的地方。 菜单项一旦带上 accelerator，AppKit 会先把键吃掉，webview 收不到。 所以同一个键位不能两边都接 —— 两边都接是双触发（⌘W 关掉两个标签），两边都不接是按了没反应， 而两种都不报错。
键位谁接为什么
⌘O菜单 新增的动作，本来就没人接
⌘S菜单 从 keydown 挪过去。顺带解决一件事：现在焦点在终端里时 ⌘S 也会被 window 监听吃掉，而那时"保存"没有意义 —— 菜单项能按「有没有活动标签」禁用
⌘W菜单 同上，无标签时禁用
⌘1菜单 主键位进菜单
⌘Bkeydown ⌘1 的别名（VSCode 手感）。macOS 菜单一项只能挂一个 accelerator，别名留给 keydown —— 菜单上只写主键位，写两个反而让人不知道该记哪个
⌘J菜单 主键位进菜单
⇧⌘F菜单 项目内搜索
⇧⌘O菜单 文件结构
⇧⌘G菜单 Git 改动列表
⌃⇧`菜单 新建终端。这条尤其该进菜单 —— 焦点在 xterm 里时它今天能不能触发，取决于 xterm 有没有吞掉这个组合
⌘Pkeydown 故意留在 keydown。 进菜单的话，焦点在终端里按 ⌘P 会被菜单抢走 —— 而终端里 ⌘P 更可能是想给 shell 的。菜单里只写标签、不挂 accelerator
连按两下 ⇧keydown 它是「两次抬起」的手势，不是 accelerator 能表达的。 菜单项照常放（那是它唯一的说明书），只是把键位写进标签文字里
⌘FCM6 一个字都不许进菜单。 那是 CM6 查找面板的键位，进了菜单等于把编辑器的查找抢没了，而且是静默的
改完必须实测这三条
「两边都接」和「两边都不接」都不报错，只能按出来验：

1. ⌘W 只关一个标签（双触发的话关两个）
2. 焦点在终端里按 ⌘S —— 菜单项应当是灰的，按了没反应
3. 编辑器里按 ⌘F —— CM6 的查找面板照常弹出来
禁用态是这次的附赠品
今天所有键位都是 window 级监听，不管当下有没有意义都会触发： 没有标签时按 ⌘S、不是 Git 仓库时按 ⇧⌘G，都是走一遍然后什么也没发生。

菜单项有 enabled，前端把状态同步过去就能让它变灰 —— 灰掉的菜单项本身就是一句解释： 不是坏了，是现在用不上。
