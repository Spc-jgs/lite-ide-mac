git 早就留好了这个口子， GIT_ASKPASS 就是为图形程序设计的。 IDEA 生成一个临时 .sh、VS Code 带一个 askpass.sh，两家形状一模一样。
三个开关不是互斥的，是有次序的
① credential.helper
git 先问它。这台机器上是 osxkeychain —— 存过一次就一直有。
实测：精简环境下 fetch 退出码 0， 说明这一步走通了，后面两个根本没用上。
② GIT_ASKPASS
① 拿不到时才走这儿。这是我们要加的那一块 —— 它服务的是「第一次连这个远程」。
用户填完之后，由 ① 存进钥匙串， 下次就轮不到 ② 了。
③ GIT_TERMINAL_PROMPT
②也没有时，回退到终端里问 —— 而我们没有终端， 那就是静默挂死。
所以 =0 继续留着。
上一版把 ② 和 ③ 看成一回事了，其实 ② 在前、③ 是兜底。 「两难」本来就不存在。
四条实测（这台机器，2026-09-05）
✓ 精简环境 + GIT_TERMINAL_PROMPT=0 的 fetch 退出码 0 —— 钥匙串那条路不需要终端
✓ SSH_AUTH_SOCK 在 launchd 里， 和终端里是同一个 socket（访达启动也有）
✓ git 在两种 PATH 下都解析到 /usr/bin/git 2.50.1
✗ 两个失败签名可按子串判（见右）

边界重画
上一版写的是「应用不碰凭据，这是功能边界」—— 那条边界画错了地方， 它把「第一次连一个新远程」整个变成了死路。

正确的边界是「不存储」，不是「不询问」。 两家主流都收密码，但都不自己存 —— 填完转发给 git，由 credential.helper 写进钥匙串。

我们照做，并且明确三个不做：
不落盘（内存里转一手，用完即弃）· 不写日志（`diag!` 一个字都不能带）· 不做「记住我」勾选框（记不记由钥匙串说了算， 我们提供不了那个保证）
askpass 是个会被 git 执行的脚本，几条不能省
1
脚本放私有目录，权限 0700。 放 /tmp 根下的话，同机别的用户能读到里面的 socket 路径和 token。用 $TMPDIR （macOS 上它本来就是每用户私有的）。
2
socket 上要有一次性 token。 否则同机任何进程连上来都能让我们弹框、并拿走用户输入的密码。 token 写在脚本里（0700 保护），每次操作换一个。
3
跑完就删。 进程退出、被取消、应用崩溃都要清 —— 崩溃那条靠启动时清扫自己的临时目录兜底。
4
提示串是 git 给的，当数据不当格式串。 它带远程 URL，而 URL 是仓库配置里的、可能来自别人的仓库。 往界面上放要转义，别拼进 HTML。
5
并发要串行化。 VS Code 有个已知 bug 正是并行 git 调用的 askpass 请求交错，username 和 password 串了台。 我们同一时刻只允许一个远程操作，天然避开 —— 但要写下来， 以后加并行时会撞。
6
用户点取消 = 空 stdout。 git 会当成「没拿到」然后失败，这正是我们要的 —— 不要在脚本里想办法「优雅退出」。

填一次就够 —— 之后由 macOS 钥匙串保管，lite-ide 不存它
继续 取消
一次弹一格，不是一次弹两格。 git 对 username 和 password 分两次调 askpass， 提示串不一样。合成一个框要自己缓存第一次的答案 —— 而那正是 VS Code 那个交错 bug 的来源。
画成一个框是观感：两次请求填同一个框的两格， 第二次来的时候第一格已经填好且不可编辑。
那句「lite-ide 不存它」要写出来。 用户在一个第三方程序里输 GitHub 密码， 他有权知道这东西去哪儿了。
「密码或访问令牌」——不写「密码」。 GitHub 早就不收密码了，这里填的其实是 PAT。 写「密码」会让人反复试自己的登录密码然后以为坏了。
